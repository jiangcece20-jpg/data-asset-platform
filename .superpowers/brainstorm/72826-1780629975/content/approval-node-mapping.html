飞书流程节点和平台配置怎么对应

核心：飞书负责“节点顺序和任务流转”，平台负责“每个节点的审批人怎么解析、表单值怎么填”。

飞书后台：审批定义 / 流程设计
提交
→
节点 A
custom_node_id: applicant_manager
→
节点 B
custom_node_id: resource_owner
→
节点 C
custom_node_id: fixed_leader
→
节点 D
custom_node_id: governance_owner
→
结束

飞书里每个审批节点建议配置为“发起人自选审批人”，并设置稳定的 custom_node_id。这样平台创建实例时可以把每个节点的审批人传进去。

平台后台：审批路由 + 节点审批人方案
审批路由
工单类型 = 权限申请，安全等级 = S5 → approval_code = APPROVAL_PERMISSION
applicant_manager → 申请人上级
resource_owner → 资源技术/业务负责人
fixed_leader → 固定领导：张总 open_id
governance_owner → 治理负责人角色

平台发起实例前解析每个节点的 open_id，并把“节点 ID → 审批人列表”传给飞书。

A

推荐：路由选择流程，节点方案配置每个节点审批人

飞书后台维护节点顺序；平台维护每个 custom_node_id 对应哪类审批人规则。适合多节点、可扩展、不会重新自建审批引擎。

B

简化：一个路由只选一个审批人规则

适合单节点或审批人很简单的流程；但遇到“上级→负责人→领导→治理负责人”会表达不清。
