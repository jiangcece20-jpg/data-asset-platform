# 审批拆单与二次合并规则设计

## 1. 目标与范围

本设计用于消除“按安全等级、目录、来源等维度拆分子单”的歧义，统一权限申请中的多维路由匹配、审批人解析、二次合并与跨流程拆分规则。

确认后同步至：

- `docs/product/00-总册PRD.md`
- `docs/product/2026-06-09-飞书审批集成-模块PRD.md`
- `docs/product/V2.1.1-需求合集/01-飞书审批集成-PRD-V2.1.1.md`

本次只完善产品规则、用户可见结果和验收案例，不调整代码、原型或技术实现。

## 2. 核心结论

权限申请采用两阶段处理：

1. 逐资产匹配多维路由并解析完整审批链。
2. 按“同飞书流程、同节点顺序、同节点实际审批人”进行二次合并。

安全等级、目录、来源等条件是路由判断依据，不直接作为最终拆单键。两个资产的原始业务属性可以不同；只要最终流程、节点顺序和各节点实际审批人完全相同，就可以合并到同一子单。

以下任一项不同，必须拆分：

- 命中的飞书流程不同；
- 审批节点数量或顺序不同；
- 任一对应节点的实际审批人不同；
- 一个资产免审批，另一个资产需进入审批。

相同审批人不能覆盖流程差异。即使两个流程最终解析出的人员名单完全相同，只要飞书流程不同，也必须生成不同子单。

## 3. 路由组合与优先级

对申请中的每个资产独立计算：

1. 仅检查当前工单类型下已启用且校验通过的流程及路由。
2. 同一条路由中的不同条件采用 AND；任一条件不满足即不命中该路由。
3. 同一条件中的多个可选值采用 OR；命中其中任一值即满足该条件。
4. 未配置的条件表示该维度不限制。
5. 目录选择父节点时，匹配该父目录及当前、未来新增的全部子目录。
6. 普通条件路由按优先级从高到低判断，命中第一条后停止。
7. 兜底路由仅在所有普通条件路由均未命中时参与匹配。
8. 同一优先级不得存在可能同时命中的启用路由；发现冲突时不允许相关配置启用。
9. 所有启用路由均未命中时，沿用 V2.1.1 口径，资产免审批通过，并保留免审批原因。
10. 路由命中后解析每个动态节点的实际审批人；任一必需节点无法解析审批人时，阻止整批提交并定位异常资产与节点。

## 4. 二次合并算法

每个资产完成路由匹配和审批人解析后，形成用于比较的审批链结果：

- 处理类型：飞书审批或免审批；
- 命中的飞书流程；
- 从第一节点到最后节点的节点顺序；
- 每个节点解析出的实际审批人。

合并规则：

| 比较项 | 是否必须相同 | 不同时的结果 |
| --- | --- | --- |
| 处理类型 | 是 | 免审批与需审批资产分别成单 |
| 飞书流程 | 是 | 跨流程必须拆分 |
| 节点数量和顺序 | 是 | 节点结构不同必须拆分 |
| 各节点实际审批人 | 是 | 任一节点人员不同必须拆分 |
| 安全等级、目录、来源 | 否 | 仅用于路由；最终审批链相同即可合并 |

免审批资产统一归入免审批子单，不创建飞书审批实例；该子单独立展示免审批原因和生效结果。

每个资产在一个申请批次中只能进入一个子单，不得重复或遗漏。只有一个资产时仍生成一个主工单和一个子单。主工单继续按既有规则聚合子单审批状态和生效状态。

## 5. 用户可见行为

提交前拆单预览至少展示：

- 本次资产总数和预计子单数；
- 每个子单包含的资产及数量；
- 命中的审批流程或“免审批”；
- 审批节点顺序和节点审批人；
- 导致独立拆单的关键差异。

确认提示：`本次共申请 X 个资产，将生成 Y 个审批子单。各子单独立审批和生效，请确认后提交。`

用户修改资产清单、权限类型、申请期限或其他会影响路由的申请内容后，原预览立即失效，必须重新计算并确认。

## 6. 详细案例

申请人一次申请 A–F 共 6 个资产的只读权限。

| 资产 | 安全等级 | 目录 | 来源系统 | 命中流程 | 实际审批链 |
| --- | --- | --- | --- | --- | --- |
| A 订单明细表 | S3 | 物流/订单 | MaxCompute | 普通权限审批 | 直属上级张三 → 资源负责人李四 → 目录负责人王五 |
| B 运单明细表 | S3 | 物流/运输 | Hive | 普通权限审批 | 直属上级张三 → 资源负责人李四 → 目录负责人王五 |
| C 签收明细表 | S3 | 物流/订单 | MaxCompute | 普通权限审批 | 直属上级张三 → 资源负责人赵六 → 目录负责人王五 |
| D 客户证件表 | S5 | 金融/客户 | MaxCompute | 高敏权限审批 | 直属上级张三 → 安全管理员钱七 → 资源负责人李四 → 数据管理员孙八 |
| E 外部订单 API | S3 | 物流/订单 | API 网关 | API 权限审批 | 直属上级张三 → 资源负责人李四 → 目录负责人王五 |
| F 临时报表表 | S2 | 临时分析 | SelectDB | 未命中流程 | 免审批通过 |

最终生成 1 个主工单和 5 个子单：

| 子单 | 包含资产 | 结果与原因 |
| --- | --- | --- |
| 子单 1 | A、B | 流程、节点顺序、各节点实际审批人全部相同；虽然目录和来源不同，仍可合并 |
| 子单 2 | C | 与 A、B 流程相同，但资源负责人不同，必须拆分 |
| 子单 3 | D | 命中高敏权限审批，流程和节点结构不同，必须拆分 |
| 子单 4 | E | 审批人名单与 A、B 相同，但飞书流程不同，跨流程必须拆分 |
| 子单 5 | F | 未命中流程，生成免审批子单，不创建飞书实例 |

## 7. 验收规则

- 多个条件组合时，不同维度使用 AND，同一维度多值使用 OR。
- 一项资产命中多条规则时，只采用最高优先级的第一条；配置存在同级冲突时不可启用。
- 父目录条件能够命中已有和未来新增的全部子目录。
- 不同业务属性的资产若最终审批链完全相同，可以合并。
- 同一流程下任一节点审批人不同，必须拆分。
- 审批人完全相同但飞书流程不同，必须拆分。
- 节点数量或顺序不同，必须拆分。
- 免审批资产不得与需审批资产合并，且不创建飞书审批实例。
- 任一必需审批人无法解析时，整批申请不得提交，并能够定位具体资产和节点。
- 拆单预览中的资产总数等于所有子单资产数之和，不得重复或遗漏。
