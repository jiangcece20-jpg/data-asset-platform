# 对外 APP 问数找数买数交互原型设计规格

## 1. 设计目标

为设计与研发提供一套可交互、可追踪状态的原型，解释综合 APP 中“找数”入口如何完成问答案、找数据、评估、APP 购买、可信空间购买以及购买后使用。

原型需要同时回答：

- 用户如何从业务问题获得答案或候选数据产品。
- 不同产品分别用什么信息、预览和试用方式帮助用户判断价值。
- APP 内容商品与可信空间商品如何使用不同交易链路。
- 个人权益和企业采购/席位共享如何共存。
- 配置后台如何驱动移动端商品、试用、价格、权益和线索状态。

## 2. 范围与非目标

### 2.1 范围

- 综合 APP 首页“找数”入口示意。
- 移动端问数、找数、商品评估、交易衔接、“我的”和企业中心。
- APP 运营后台的商品、内容、商业化、企业权益、线索、运营和审批配置。
- 与资产平台、可信空间之间的系统边界和模拟状态。

### 2.2 非目标

- 不重构综合 APP 的其他功能或全局导航。
- 不生成 iOS/Android 安装包；在浏览器内按移动端尺寸模拟原生 APP。
- 不接真实支付、AI、可信空间、资产平台或审批系统。
- 不实现生产级持久化、合同签署、发票、财务对账和真实数据查询。
- 不在 APP 运营后台重复实现资产选料和元数据治理。

## 3. 已确认的产品决策

1. 综合 APP 首页只保留一个“找数”入口，问答案和找数据在模块内融合。
2. 输入区提供智能识别、问答案、找数据三个模式；买数是评估后的动作。
3. 商品目录统一搜索并分频道，覆盖 APP 自营与可信空间商品。
4. 行业报告与交互报表是独立商品类型。
5. 每个商品仅允许 APP 支付、可信空间购买、询价定制中的一种获取路径。
6. 用户使用个人账号，可加入并认证企业；企业认证是企业试用和空间购买前置。
7. APP 使用单一会员加单品购买；个人和企业都可获得权益，原型重点展示企业采购和席位共享。
8. 空间购买目标体验为 APP 内嵌、单点登录、商品深链和订单回传。
9. AI 仅引用公开、个人已购或当前企业已授权内容；未购内容渐进披露。
10. 试用按风险分层，并可逐商品配置不支持、自助或申请试用。
11. 空间商品主数据只读，APP 维护增强信息；APP 报告/报表由 APP 管理。
12. 所有对外发布走统一入口、分类检查清单。
13. 无结果自动承接为需求线索。
14. 资产平台与 APP 运营后台双后台协同。

## 5. 核心交互设计

### 5.1 统一问数找数

输入框文案为“说说你想了解的问题，或描述你需要的数据”。默认智能识别，用户可主动切换“问答案”或“找数据”。

- 问答案优先返回结论、图表、引用来源和追问建议。
- 找数据优先返回商品、匹配原因、覆盖信息和评估入口。
- 智能识别可返回混合结果，并允许用户一键切换模式。
- 无可靠来源时不得拼凑答案，转为商品推荐或需求提交。

### 5.2 AI 权限与付费墙

- 免费或已获权益：完整回答、图表和来源。
- 未购内容：只使用公开摘要，锁定精确数值、完整图表、细分维度和深度追问。
- 无公开依据：解释无法回答并推荐商品。
- 购买后恢复原会话，显示“已解锁”，重新生成完整答案。

### 5.3 商品卡与动作路由

商品卡统一显示类型、场景、提供方、更新频率、试用标签、交易归属和价格摘要。

主动作根据状态唯一呈现：登录后预览、认证企业、申请试用、开通会员、单品购买、企业采购、前往可信空间或提交需求。

### 5.4 类型化详情与试用

| 类型 | 详情核心 | 原型关键动作 |
| --- | --- | --- |
| 行业报告 | 摘要、目录、样例、方法、版本、授权 | 阅读预览、开会员、单篇购买 |
| 交互报表 | 指标、维度、时间、更新、导出规则 | 受限体验、会员解锁、导出 |
| 数据集 | 粒度、覆盖、字典、样本、质量 | 看样本、申请试用、空间购买 |
| API | 入参出参、示例、错误码、SLA、计费 | 看文档、申请额度、空间购买 |
| PQ/PIR | 核验字段、返回、命中率、隐私 | 模拟核验、空间购买 |
| 联合分析 | 模板、参与字段、输出、披露限制 | 查看方案、预约试算 |
| 解决方案 | 场景、产品组合、范围、案例 | 预约演示、询价 |

### 5.5 APP 交易

- 会员页展示单一会员权益、周期和企业版入口。
- 单品确认页明确访问期限、下载/导出和授权范围。
- 小额企业标准套餐可在线支付。
- 大额企业采购提交企业订单，由后台推进报价、合同、付款确认和权益开通。

### 5.6 可信空间购买

企业未认证时先进入认证引导；认证完成后恢复商品上下文。空间购买通过内嵌页打开并复用身份。成功后回到 APP 商品页或空间订单详情；回调延迟时显示“空间已受理，状态同步中”。

### 5.7 企业权益

企业管理员可查看采购状态、套餐、已用/剩余席位，邀请成员并分配或收回席位。成员获得席位后可从“我的—企业权益”访问共享内容。

### 5.8 无结果需求

系统将问题、筛选条件和浏览商品预填到需求单。用户补充对象、地域、时间、更新、场景和期望交付。后台处理为推荐现有、需要定制或暂不支持，并通过 APP 消息反馈。

## 6. 系统与数据设计

### 6.1 原型架构

使用独立 React/Vite 原型，移动端和 PC 后台共享 TypeScript 领域模型及 mock store。移动端使用路由呈现屏幕，后台修改状态后可立即在移动端查看对应变化。

### 6.2 核心模型

- `Product`：商品公共信息、来源、类型、交易归属、试用、价格和发布状态。
- `ProductEnhancement`：空间商品的 APP 展示标题、说明书、标签、预览和运营位。
- `UserContext`：个人登录、当前企业、认证状态和角色。
- `Entitlement`：个人/企业来源、会员/单品/席位类型、有效期和能力范围。
- `Order`：APP/空间来源、个人/企业归属、支付/合同/交付状态。
- `TrialApplication`：试用方式、企业、审批和额度/有效期。
- `DemandLead`：问题上下文、需求信息、运营状态和推荐商品。
- `ApprovalRecord`：商品类型、检查清单、结论、理由和时间线。

### 6.3 状态一致性

- 空间商品不可编辑主字段，增强层与空间编号绑定。
- 一个商品只能有一种交易归属，运行时不允许同时展示两种支付入口。
- 权益判断顺序为个人已购/会员、当前企业席位、无权限，并优先选择无需追加支付且能力更高的权益。
- 商品下架不删除历史订单和权益记录；是否继续使用由商品授权范围决定。

## 7. 代表数据

- 全国货运价格指数：APP 交互报表，会员解锁。
- 中国公路物流行业月报：APP 行业报告，会员或单品购买。
- 道路运输从业人员资格核验：可信空间 API/PQ。
- 企业物流活跃度数据集：可信空间数据集。
- 承运商经营稳定性联合分析：询价/空间联合分析。

## 8. 完整演示链路

1. 问货运价格趋势 → 受限回答 → 开通会员 → 解锁完整回答。
2. 找资格核验 API → 详情评估 → 企业认证 → 空间购买 → 订单回传。
3. 企业采购报告权益 → 后台确认合同付款 → 分配席位 → 成员共享。
4. 搜不到数据 → 提交需求 → 后台处理 → 推荐商品或定制。

## 9. 异常与恢复

- 搜索/AI：加载、网络失败、意图不清、无来源、无权限、空结果。
- 商品：同步延迟、价格待确认、暂停销售、下架。
- 试用：未认证、待审批、驳回、额度用尽、过期。
- APP 订单：取消、失败、退款、权益到账延迟。
- 空间：单点登录失效、企业不匹配、不可用、回调延迟。
- 企业权益：席位已满、收回、企业套餐到期。

每个异常页提供明确原因和唯一恢复动作；不能恢复时保留记录并提供联系或需求入口。

## 10. 配置后台设计

| 业务域 | 核心能力 |
| --- | --- |
| 商品中心 | 双来源列表、空间同步、APP 商品、增强信息、上下架 |
| 内容中心 | 报告正文/版本、报表绑定、预览、下载/导出 |
| 商业化中心 | 会员、单品价格、个人订单、企业报价合同付款 |
| 企业权益 | 套餐、席位、成员、分配记录、到期续费 |
| 试用与线索 | 测试额度、试用审批、询价、无结果需求 |
| 运营配置 | 首页入口、频道、场景、推荐位、热门词、AI 引导问题 |
| 审批与集成 | 分类清单、审批记录、空间同步、订单回调、异常告警 |

重点制作商品编辑、发布审批、企业采购/权益开通和需求线索处理；其他模块提供列表和关键配置状态。

## 11. Prototype Decision

| Need prototype? | Reason |
| --- | --- |
| Yes | 新交互模型同时涉及移动端问数找数融合、双交易、企业权益和 PC 配置后台，需要用可交互状态验证设计与研发理解是否一致 |

选择独立 React/Vite 原型。它与现有内部数据资产平台隔离，移动端和后台共享 mock 状态；不采用单文件 HTML，也不并入现有内部平台页面。

## 12. 验收标准

- 总首页仅示意并突出“找数”入口。
- 智能识别、问答案和找数据可以切换且结果结构正确。
- 四条演示链路完整可走通，结果可在“我的”或后台追踪。
- 商品类型、交易归属、试用、预览和权益配置前后一致。
- AI 未越权披露；购买后能恢复原问题解锁。
- 企业认证、企业采购、席位分配和成员共享状态可演示。
- 空间异常、支付失败、审批驳回、权益过期和空结果均有明确反馈。
- 原型通过构建、类型检查、关键状态单元测试和浏览器移动端/PC 端冒烟检查。

## 13. 风险与约束

- 单点登录、空间商品深链和订单回传需要可信空间团队确认接口能力；原型只模拟目标体验。
- 企业采购涉及合同、财务和发票系统；原型只覆盖用户可见状态及运营开通动作。
- AI 答案质量取决于内容索引、权限过滤和引用能力；原型固定演示数据，不代表生产准确率。
- 飞书 PRD 尚无目标文档和凭证，本次只维护仓库内文档，不宣称已同步飞书。
