# 产品规划“三张全景图连续讲解”调整设计

## 1. 调整目标

评审先建立完整产品认知，再进入规则和建设分期。规划正文按照“需求全景—业务流转—产品承接”的顺序连续展示三张图，避免流程图只出现在附件、应用架构图只有源文件链接，以及正文在三张图之间穿插其他章节。

## 2. 目标叙事顺序

简明版规划调整为：

1. 一页结论：说明做什么、解决什么。
2. 六层体系架构：说明服务谁、创造什么价值、覆盖哪些场景和能力，以及运营与资源约束。
3. 全景业务流程：说明用户、企业、平台及外部系统如何完成找数、评估、购买、交付、使用、查询和治理闭环。
4. 产品应用架构：说明上述流程由哪些应用端、业务域、治理能力和公共能力承接。
5. 为什么做与关键规则：补充背景、购买主体、报价、付款、交付和范围边界。
6. 怎么建设：按三个阶段说明建设目标、内容和完成条件，不承诺时间周期。
7. 指标、启动条件、演示路线和版本说明。

三张图必须连续出现，中间不插入“为什么做”“报价方式”“付款方式”等规则章节。

## 3. 图表呈现

### 3.1 六层体系架构图

- 继续使用现有六层 PNG。
- 图后保留六层摘要和 F1～F13 简化分组，帮助读者从图进入文字说明。

### 3.2 全景业务流程图

- 在六层体系后新增独立章节并嵌入现有一级、二级流程 PNG。
- 图前用一句话说明用途；图后用简短文字解释一级主链路和二级分支，不重复逐项抄图。
- 同时提供 Draw.io 源文件链接，便于后续维护。

### 3.3 产品应用架构图

- 从现有 Draw.io 源文件导出 PNG，并在正文中直接嵌入。
- 图后继续保留“五层产品架构”和“六个核心业务域”的文字摘要。
- 同时提供 Draw.io 源文件链接。

## 4. 文档调整范围

- 简明版规划：重排章节、嵌入流程图和产品应用架构图、更新章节编号和相关材料。
- 完整版规划：在六层需求蓝图后增加全景流程图，并在产品应用架构章节嵌入架构 PNG；不改变详细规则和三阶段范围。
- 飞书产品规划主文档：以调整后的简明版为准同步；三张 PNG 作为飞书图片上传并插入对应章节，不依赖本地相对路径；回读确认章节顺序和对应说明完整。
- 功能说明 PRD、完整模块 PRD 和原型功能本次不调整。

## 6. 验收标准

- 简明版正文依次出现“六层体系架构—全景业务流程—产品应用架构”。
- 三张图均可在本地 Markdown 中直接预览，不需要打开 Draw.io 才能理解。
- 流程图和应用架构图均有源文件入口及简短读图说明。
- 完整版保持同样的三图顺序，不删除原有详细内容。
- “怎么建设”仍放在产品全景和业务规则之后，三阶段内容及无时间周期原则不变。
- 飞书规划中三张图均可直接查看；回读后能检索到三个章节标题、流程说明和应用架构说明。
- 本次调整不改变购买、支付、权益、交付及分期范围等产品规则。
