# 找数买数用数演示路线流程图设计

## 1. 目标

依据《对外 APP 找数、买数与用数 · 评审演示路线》，生成一份适合嵌入 PRD 阅读的多页 Draw.io 源文件。图表用于帮助读者快速理解不同业务流程、角色协作、关键判断和状态结果，并可通过步骤编号回查原文。

## 2. 交付范围

- 交付一个多页 `.drawio` 源文件，不导出 PNG、SVG 或 PDF。
- 共 10 个页面，每页对应一个可独立阅读的流程主题。
- 只呈现当前有效流程，省略演示路线中使用删除线标记的 A6、A7、A11～A13、C5、C6。
- 不修改演示路线或功能说明 PRD 的正文。

## 4. 信息结构

### 4.1 总览页

采用横向阶段流，主线为“找数 → 评估 → 购买/跳转 → 交付与用数 → 需求回流或卖数”。流程 A～E 作为五条业务路线挂接到对应阶段，突出两类成交边界：APP 内成交与可信空间成交。

### 4.2 详细页

采用横向泳道流程图。根据页面实际参与方，从下列泳道中选择必要角色，不创建空泳道：

- 用户或买家
- APP / 平台
- 企业管理员或运营人员
- 可信空间或外部系统
- 卖家

主路径从左向右推进；决策分支尽量上下展开，并在路径汇合后回到主线。每个节点保留原步骤编号，例如 `A4`、`B8`、`D2-8`。

## 5. 节点表达

- 操作节点采用“步骤编号 + 动作名称 + 一句关键结果”。
- 系统节点只保留对路径或状态有影响的结果，不复制 PRD 的完整检查点。
- 决策节点只用于会改变路径的判断，如企业资格是否满足、交付是否成功、空间数据集是否允许下载。
- 规则旁注用于承载固定口径，不与主流程争抢视觉层级。
- 连线标签控制在短语级，如“通过”“失败”“可下载”“仅沙箱”。

## 6. 关键口径

图中必须准确表达以下规则：

1. APP 商品只有商品级固定可售卖周期，用户不能选择周期或数据截止日期；订单创建时锁定购买周期。
2. APP 数据集订单的付款、权益、交付状态分轴展示；交付失败不能回退已支付事实。
3. 可信空间价格、订单、交付和售后以空间权威信息为准；APP 回跳不等于成交成功。
4. 企业已开通找数买数且空间数据集支持下载时，可进入用数或下载；仅沙箱可用时返回空间。
5. 报告默认在线阅读，看板默认看板预览；周期结束后停止新增版本或刷新，但保留最近合法内容。
6. 用户需求处理结果只允许“推荐现有商品、需要定制、暂不支持”三选一。
7. 只有人工确认的高风险变化可以暂停新购，且不自动终止存量权益。
8. 入驻商家 MVP 采用卖家自收款；卖家确认到账后，平台幂等开通买家权益。

## 7. 视觉规范

- 画布采用适合 PRD 插图的横向布局，并在各页保持统一边距、字体和节点尺寸。
- 用户动作使用蓝色，平台处理使用紫色，管理员或运营动作使用橙色，可信空间或外部系统使用绿色。
- 异常、阻断和失败分支使用红色；规则旁注使用浅灰或浅黄色。
- 主路径使用实线箭头，异步回传或镜像使用虚线箭头。
- 避免渐变、装饰性图标和大段文字，保证缩放后仍可阅读。
