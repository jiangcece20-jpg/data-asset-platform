# 标准驱动建表工具 · 设计文档

> 日期：2026-08-08  
> 状态：已评审（对话确认）；**原型已实现**（分支 `feature/standard-driven-table-builder`，2026-08-08；非生产就绪）  
> 交付形态：**仅原型**（不接真实数据源、不执行真实建表）  
> 落地仓库：本仓库 `data-asset-platform`  
> 关联：数据标准能力与 `data-standards` 仓库规划对齐；本原型在资产平台产品切换中作为并列产品入口

## 1. 背景与目标

企业内部建表时，表名与字段命名、类型、码表、分类分级常靠个人经验，难以统一引用已发布数据标准，也容易在源头继续产生不规范字段。

本能力在资产平台中提供独立产品线 **「建表工具」**：用户选择目标库后，填写表名/描述与字段名/注释，系统推荐标准表名、字段标准及相关属性，确认后在目标库完成建表（原型为演示成功态）。并列产品线 **「数据标准」** 提供轻量壳，承接缺标时的新建标准草稿。

### 1.1 本期目标（MVP 原型）

- 在产品切换中可进入「建表工具」「数据标准」。
- 建表工具以 4 步向导完成：选库 → 录入 → 推荐确认 → 建表结果（演示）。
- 推荐覆盖表名、字段名、类型/长度/精度、约束、码表、分类分级、命中标准与依据/置信度、缺标提示。
- 缺标可一键发起「新建标准草稿」并跳转数据标准壳；不阻断建表。
- 全程纯前端演示，无真实连库与后端。

### 1.2 非目标（MVP）

- 真实数据源连接与物理 DDL 执行。
- CREATE TABLE SQL 解析导入。
- 数据标准完整治理（发布、审核、落标、评估）。
- 真实权限、审批。
- 建表成功后回写资产目录/元数据（可文案提示后续能力）。

### 1.3 完整规划（不进本次原型）

- 真实连库建表、多引擎方言与库权限。
- SQL 解析导入。
- 建表成功同步资产/元数据。
- 与标准发布、落标映射打通。
- 推荐引擎规则/识别特征配置化。
- 单页工作台效率增强（在向导主路径稳定后可选）。

## 2. 用户与价值

| 角色 | 主目标 | 在本工具中的用法 |
| --- | --- | --- |
| 数据开发 / 数仓建模 | 按标准在选定库建好表 | 走完向导；缺标可稍后处理或发起草稿后继续 |
| 标准管理员 / 治理 | 发现缺标并补齐标准 | 从缺标列表进入数据标准壳建草稿；也可直接进标准壳维护 |

## 3. 产品结构

### 3.1 资产平台产品切换

在现有「数据资产 / 数据之源 / 智能问数」之外新增：

| 产品线 Key（建议） | 名称 | 状态标签 | MVP 深度 |
| --- | --- | --- | --- |
| `data-standard` | 数据标准 | 建设中 | 轻量壳：标准集/标准列表占位 + 新建标准草稿页 |
| `table-builder` | 建表工具 | 建设中 | 完整 4 步向导 |

关系：

```text
资产平台产品切换
├── 数据资产
├── 数据之源
├── 智能问数
├── 数据标准     ← 标准库壳，承接建标草稿
└── 建表工具     ← 选库建表 + 标准推荐（本功能主体）
```

### 3.2 交互范式

采用 **分步向导（方案 1）**，不采用单页工作台或标准抽屉嵌套作为 MVP 主形态。

```text
① 选数据源类型与目标库
  → ② 填写表名/表描述 + 字段（手填或粘贴）
  → ③ 一键推荐并默认采纳（可逐条改选/忽略/发起建标草稿）
  → ④ 确认后「在目标库建表」→ 成功态（表位置、字段清单、DDL 预览）
```

## 4. 向导分步设计

### 4.1 Step ① 选目标库

| 项 | 说明 |
| --- | --- |
| 数据源类型 | 下拉演示：Hive / MaxCompute / MySQL（可再加 1～2 个演示项） |
| 目标库 / Schema | 随类型切换演示选项，如 `ods` / `dwd` / `dim` |
| 说明 | 「原型演示：不连接真实数据源，建表结果为模拟成功」 |

未选择数据源与目标库时，不能进入 Step ②。

### 4.2 Step ② 表与字段录入

**表级**

- 表中文名、表英文名（可空，交给推荐）
- 表描述（可空）

**字段级**

- 列：字段中文名、字段英文名（可空）、注释、操作
- 手填：增行 / 删行
- 粘贴批量：弹窗粘贴「中文名 / 英文名 / 注释」多行，解析后写入表格
- 进入 Step ③ 前必须同时满足：至少 1 个字段；表中文名与表英文名至少填一项

完整规划后续可增加 SQL 解析导入，本期不做。

### 4.3 Step ③ 推荐确认

进入时自动执行一轮推荐，并 **默认写入** 推荐结果。页面分三块：

**A. 表级推荐条**

- 推荐标准表名（中/英）、推荐依据简述
- 操作：采纳 / 保留原文 / 手工改

**B. 字段推荐表**

| 列 | 内容 |
| --- | --- |
| 输入 | 用户填的中文名/注释 |
| 推荐标准 | 标准中文名、英文名、编码、所属标准集 |
| 技术属性 | 类型 / 长度 / 精度、非空、主键建议 |
| 码表 | 关联码表名（无则 —） |
| 分类分级 | 分类路径 + 分级 |
| 置信度 | 高/中/低或百分比 |
| 状态 | 已采纳 / 已改选 / 已忽略 / 缺标 / 草稿已发起 |
| 操作 | 改选标准、忽略、发起新建标准草稿 |

**C. 缺标汇总**

- 列出无匹配字段
- 支持单条或批量「新建标准草稿」→ 跳转数据标准壳并带入上下文
- 缺标字段仍用建议命名占位，**不阻断建表**

**推荐内容（MVP 全覆盖）**

1. 标准表名（中/英）  
2. 标准字段名（中/英）  
3. 数据类型 / 长度 / 精度  
4. 是否非空、主键等约束建议  
5. 关联码表 / 值域  
6. 分类分级  
7. 命中的已发布标准（编码、标准集）及推荐依据 / 置信度  
8. 无匹配时的缺标提示与建议命名  

**采纳规则**：默认一键采纳；支持逐条改选标准、忽略或发起建标草稿。

### 4.4 Step ④ 建表结果

- **成功态（主路径）**：目标库、最终表名、字段数、创建时间（演示）
- 字段定稿清单（含标准引用、码表、分类分级）
- DDL 预览（按所选数据源类型切换方言文案，不执行）
- 动作：复制 DDL、再建一张表、去数据标准查看相关草稿（若有）
- **失败态（预留演示）**：如「目标库无权限」，可重试；默认主路径走成功

## 5. 数据标准壳（轻量）

导航示意：

- 标准集列表（占位数据）
- 数据标准列表（占位数据）
- **新建标准草稿页**：接收建表带来的字段名、注释、建议英文名、类型、来源=`建表工具`；可保存草稿并提示「可返回建表工具继续」

不做：发布、审核、落标、评估。

## 6. 状态、校验与跨产品跳转

### 6.1 字段推荐状态

| 状态 | 含义 | 可否进入建表 |
| --- | --- | --- |
| 已采纳 | 使用推荐标准写入定稿 | 可以 |
| 已改选 | 用户换了另一条已发布标准 | 可以 |
| 已忽略 | 不用标准，保留用户原文/手工值 | 可以（标「未落标」） |
| 缺标 | 无匹配；可用建议命名 + 可发起草稿 | 可以（不阻断） |
| 草稿已发起 | 已跳转并创建标准草稿，建表侧保留建议命名 | 可以 |

原则：**缺标不阻断建表**；阻断仅来自表结构校验问题。

### 6.2 向导过程状态

| 状态 | 用户可见 |
| --- | --- |
| 草稿中 | Step ①～③ 可来回 |
| 推荐中 | Step ③ 短暂 loading，随后默认采纳 |
| 待建表确认 | Step ③ 点「确认建表」前校验通过 |
| 建表成功 | Step ④ 成功页 |
| 建表失败（演示） | 预留失败态，可重试 |

原型可用内存/session 演示态保存向导进度；刷新重置可接受，或做轻量 session 恢复。

### 6.3 校验与异常

| 场景 | 系统行为 |
| --- | --- |
| 未选数据源/库 | 不能进 Step ② |
| 无字段，或表中文名与表英文名都空 | 不能进 Step ③，提示补全 |
| 粘贴格式无法解析 | 提示示例格式，不覆盖已有行 |
| 字段英文名互相重复 | 标红，确认建表前必须改掉 |
| 推荐无高置信命中 | 仍给建议命名 + 缺标，不报错 |
| 改选标准时列表为空 | 提示「当前标准集无已发布标准」 |
| 发起建标草稿后用户未保存 | 回建表工具时该字段仍为「缺标」 |

### 6.4 跨产品跳转

```text
建表工具 Step ③「新建标准草稿」
  → 数据标准 / 新建草稿（带入：字段中文名、注释、建议英文名、类型、来源=建表工具）
  → 保存草稿成功 → 可「返回建表工具」回到 Step ③ 同一草稿上下文
  → 取消/未保存 → 回 Step ③，状态仍为缺标
```

- 产品切换可随时离开建表工具；未提交内容按演示约定保留或提示「离开将丢失未提交内容」。
- MVP：从数据标准壳 **不** 反向改写已成功建表的字段。

### 6.5 权限（原型示意）

- 不建真实权限；顶栏可选切换「数据开发 / 标准管理员」演示身份。
- 两种身份均可走完建表向导；标准壳「保存草稿」均可操作。

## 7. 演示数据剧本

| 场景 | 输入 | 期望演示结果 |
| --- | --- | --- |
| 高置信命中 | 字段「客户编号」 | 命中 `客户编号 / customer_code`，带类型与分类分级 |
| 码表命中 | 字段「客户性别」 | 命中枚举标准 + 性别码表 |
| 缺标 | 字段「优惠券编码」或类似 | 缺标 + 建议命名 + 可发起草稿 |
| 粘贴批量 | 3～5 行混合上述类型 | 一次推荐出采纳/缺标混排 |
| 建表成功 | 走完向导确认 | Step ④ 成功 + DDL |
| 建标往返 | 缺标字段点新建草稿并保存 | 回 Step ③ 状态为「草稿已发起」 |

## 8. 技术落地约定（原型）

- 沿用现有 React + hash 路由 + `AppShell` / `ProductSwitcher` / `productLines`。
- 扩展 `ProductLineKey` 与路由：建表向导页、数据标准壳页、新建草稿页。
- 推荐逻辑：前端 mock 规则（关键词/注释匹配固定剧本），不接大模型服务。
- DDL：按数据源类型切换模板字符串，仅预览与复制。

| 决策点 | 结论 |

| 产品形态 | 独立建表工具产品线；完整规划 + MVP 原型 |
