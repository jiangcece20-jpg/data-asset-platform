# 对外 APP 找数买数商品类型与详情页重构设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 日期 | 2026-07-16 |
| 目标工程 | `external-app-vue3` |
| 设计状态 | 已确认，待实施 |
| 关联规格 | `docs/superpowers/specs/2026-07-11-external-app-data-discovery-commerce-design.md` |
| 适用范围 | 移动端商品目录、商品详情、求上架、购买入口与权益展示 |

本规格收口对外 APP 的标准商品类型，重新定义不同类型的评估、预览、购买与交付规则，并将现有纵向堆叠的商品详情改造成可扩展的 Tab 详情框架。与 2026-07-11 规格冲突时，以本规格为准；工程实现以现有 Vue 3/Vite 原型为基础。

## 2. 目标与非目标

### 2.1 目标

- 将前台商品类型从七类收口为数据集、API、行业报告、自有看板四类。
- 让用户在购买前按商品类型查看足以判断价值的信息。
- 明确数据集与 API 统一在可信空间购买，行业报告与自有看板在 APP 内获取。
- 支持用户发现尚未上架可信空间的候选资产，并提交轻量“求上架”需求。
- 统一免费、会员、限期单品购买、可信空间购买四种获取方式的展示与操作规则。
- 用通用详情框架承载四类商品，避免继续在单个页面中堆叠类型判断。

### 2.2 非目标

- 不接入真实支付、可信空间订单、API 网关、邮件或文件下载服务。
- 不实现真实数据出域、真实 API 调用或生产级权限控制。
- 不修改仓库内 React 数据资产平台与旧 HTML 原型。
- 不在本期继续提供 PQ/PIR、联合分析、解决方案三个独立前台类型。
- 不重做找数首页、问答案和 PC 运营后台的信息架构；仅补齐本设计所需的状态与入口。

## 3. 已确认的产品决策

1. 前台只保留数据集、API、行业报告、自有看板四个标准商品类型。
2. PQ/PIR 等接口型能力归入 API；联合分析和解决方案暂不作为标准商品类型。
3. 数据集和 API 必须上架可信空间后才能购买，APP 不承担正式数据或正式 API 的交付。
4. 数据集不提供试用，只提供经过脱敏和审核的样例数据。
5. API 在 APP 内提供固定脱敏样例的沙箱调试；无需企业认证，不触发真实 API，也不消耗正式调用额度。
6. 行业报告和自有看板在 APP 内提供免费、会员权益或单品购买。
7. 自有看板单品购买按有效期授权，原型默认有效期为 12 个月，不做永久买断。
8. 行业报告使用内容区块级预览策略，支持免费、打码和锁定，并兼容网页报告与 PDF。
9. 行业报告单品购买永久解锁购买时的报告版本；后续独立发布的新版本不自动包含，原版本的勘误更新继续可见。
10. 尚未上架可信空间的候选数据集/API 可在 APP 被发现，但只能提交“求上架”，不能购买、下载或试用。
11. “求上架”采用轻量需求表单，并在“我的”中展示处理进度。
12. 数据集不通过 APP 下载或邮件附件交付；正式交付统一由可信空间负责。

## 4. 商品分类、获取与交付矩阵

| 商品类型 | 商品来源 | 上架/交易渠道 | 买前体验 | 正式交付 |
| --- | --- | --- | --- | --- |
| 数据集 | 资产平台内部资产、可信空间商品 | 可信空间购买 | 说明书、字段字典、审核后的脱敏样例、数据探查报告 | 可信空间 |
| API | 资产平台加工能力、可信空间商品 | 可信空间购买 | 接口文档、固定脱敏沙箱调试 | 可信空间 API 网关 |
| 行业报告 | APP 自有内容 | 免费、会员、APP 单品购买 | 摘要、目录、样例章节、内容区块级打码或锁定 | APP 在线阅读；授权范围内查看附件 |
| 自有看板 | APP 自有内容 | 免费、会员、APP 限期单品购买 | 部分指标、图表骨架、打码数据 | APP 在线访问；按授权控制导出 |

商品来源与交易渠道必须分开建模。资产平台内部资产上架可信空间后，来源仍是“资产平台”，交易渠道变为“可信空间”；不能用单一 `source` 字段同时表达来源与销售位置。

## 5. 生命周期与可见性

### 5.1 商品可用状态

前台详情需要识别以下业务状态：

- `candidate`：候选资产，经过基础可见性初筛，但尚未上架可信空间。
- `preparing`：已受理求上架，正在评估、加工或合规审批。
- `published`：已经上架，可按商品规则获取或购买。
- `paused`：暂停售卖，保留说明书和历史权益，不允许新购。
- `delisted`：已经下架，不进入普通搜索；历史订单和权益记录保留。

### 5.2 候选资产展示边界

候选数据集/API 可以展示：

- 名称、业务描述、数据分类、更新频率、最近更新时间、来源平台。
- 经过可见性初筛的字段名称、字段类型和非敏感字段说明。
- “暂未上架可信空间”和“可申请上架”状态说明。

候选资产不得展示：

- 样例数据行、字段值分布、敏感字段含义和真实接口返回。
- 价格、购买、下载、试用或正式调用入口。
- 尚未通过审核的数据探查明细。

## 6. 通用详情页框架

### 6.1 页面结构

商品详情统一由四部分组成：

1. 顶部导航：返回、商品标题、收藏。
2. 商品摘要：类型、来源、状态、更新频率、价格/权益摘要、场景标签。
3. 横向 Tab：根据商品类型加载对应的信息结构；切换 Tab 不改变当前商品上下文。
4. 底部固定操作区：根据类型、生命周期、登录状态、企业认证和权益计算唯一主动作。

Tab 内容区保留加载、空数据、受限、错误四类状态。移动端横向 Tab 可滚动，切换后回到内容区顶部；页面整体仍保持手机壳原型宽度。

### 6.2 组件边界

- `ProductDetailShell`：负责商品加载、摘要、Tab 导航和固定操作区。
- `ProductSummaryCard`：只展示通用摘要，不包含类型特有逻辑。
- `ProductDetailTabs`：接收 Tab 配置、当前 Tab 与切换事件。
- `DatasetDetail`、`ApiDetail`、`ReportDetail`、`DashboardDetail`：分别承载四类内容。
- `ContentGate`：统一处理免费、打码、锁定以及解锁提示。
- `ProductPrimaryAction`：统一计算求上架、空间购买、开会员、单品购买和立即查看。
- `ListingRequestForm`：候选数据集/API 的轻量求上架表单。
- `ListingRequestList`：在“我的”和现有 PC“试用与线索”中复用求上架记录及状态。

页面不继续用一个超大模板串联全部类型的 `v-if/else-if`。类型组件只读取自身详情模型；购买与权益判断仍由通用层处理。

## 7. 四类商品详情设计

### 7.1 数据集

#### Tab 1：基本信息

- 数据集描述与适用场景。
- 更新频率、最近更新时间、数据行数。
- 数据分类、来源平台、覆盖范围、时间范围。
- 数据粒度、质量更新时间与合规说明。

#### Tab 2：字段信息

字段表格展示字段名称、字段类型、业务含义、详细描述、是否主键、是否可为空。已上架商品可展示审核后的敏感等级标签；候选资产不展示可能泄露内部口径的敏感说明。

#### Tab 3：样例数据

仅对已上架商品展示经过审核的脱敏样例，默认最多 10 行。样例必须标注“仅用于结构评估，不代表完整数据”，并显示脱敏、水印和样本生成时间。数据集不提供试用，不出现“申请试用”按钮。

#### Tab 4：探查报告

展示完整率、唯一性、空值率、值分布、异常值、更新时间和总体质量结论。报告是买前质量说明，不提供对完整数据的自由探查。

### 7.2 API

#### Tab 1：基本信息

展示能力描述、适用场景、提供方、更新说明、计费单位和可信空间商品编号。

#### Tab 2：接口文档

展示请求方式、接口路径示例、请求参数、响应字段、鉴权说明和版本。APP 中不展示可用于调用正式环境的真实密钥或地址。

#### Tab 3：在线调试

用户可以修改有限的白名单参数并点击“发送请求”。返回固定脱敏样例和模拟耗时，同时明确标记“沙箱样例，不调用真实服务、不消耗正式额度”。非法参数在本地校验并返回明确提示。

#### Tab 4：错误码与 SLA

展示常见错误码、可用性承诺、响应时间、限流规则和正式计费说明。正式购买按钮始终指向可信空间。

### 7.3 行业报告

#### Tab 1：报告概览

展示摘要、作者/机构、发布日期、更新时间、适用对象、报告标签和价值说明。

#### Tab 2：目录与样例

展示章节目录及可预览章节；锁定章节显示锁标识，不伪装成可点击内容。

#### Tab 3：在线阅读

报告正文按内容区块渲染。每个区块具有以下预览策略之一：

- `visible`：完整展示。
- `masked`：保留版式，关键数字、图表或正文打码，并显示解锁提示。
- `locked`：仅显示标题和内容类型，不渲染正文。

同一策略兼容网页内容和 PDF 页；PDF 原型以页级预览数据模拟，不接真实 PDF 阅读器。

#### Tab 4：版本与授权

展示当前版本、历史版本摘要、会员/单品授权范围、附件查看规则和版权说明。

### 7.4 自有看板

#### Tab 1：看板概览

展示业务问题、核心指标、维度、时间范围、更新频率和适用场景。

#### Tab 2：在线预览

免费内容完整显示；会员或单品内容保留图表结构，对关键指标、精确数值和明细进行打码。预览不允许通过提示文本泄露被锁定数字。

#### Tab 3：指标口径

展示指标名称、业务定义、计算口径、更新周期和可用维度。受限指标可显示名称与摘要，但隐藏完整计算说明。

#### Tab 4：更新与导出

展示数据更新时间、版本说明、导出格式和导出限制。免费、会员、单品权益可以拥有不同导出能力。

## 8. 获取、权益与主动作规则

### 8.1 APP 内容商品

行业报告和自有看板支持以下配置组合：

- 免费：无需购买或登录即可查看完整内容；登录只用于收藏与历史记录。
- 会员包含：会员有效期内查看完整内容。
- 单品购买：报告永久解锁购买时的报告版本；看板默认授权 12 个月。
- 会员加单品：用户可选择开通会员或单独购买，页面需明确权益期限和差异。

### 8.2 主动作优先级

主动作按以下顺序计算，命中后不再展示冲突主按钮：

1. 已拥有有效权益：`立即查看`。
2. 候选数据集/API：`求上架`。
3. 准备中的数据集/API：`查看上架进度`。
4. 已上架数据集/API，企业未认证：`完成企业认证`。
5. 已上架数据集/API，企业已认证：`前往可信空间购买`。
6. 免费报告/看板：`免费查看`。
7. 会员包含且用户非会员：`开通会员`，单品购买作为同级次要动作。
8. 仅支持单品购买：`单品购买`。
9. 暂停或下架：禁用购买，并显示原因和可恢复路径。

## 9. 求上架流程

### 9.1 提交条件与表单

用户必须登录才能提交求上架，但提交阶段不要求企业认证；真正进入可信空间购买时再完成企业认证。

轻量表单预填商品信息，用户补充：

- 使用场景。
- 所需数据/API 范围。
- 期望时间跨度。
- 期望更新频率。
- 希望可购买的时间。
- 补充说明。

### 9.2 用户可见状态

求上架记录进入“我的—求上架记录”，状态为：

`已提交 → 评估中 → 上架准备中 → 已上架 / 暂不支持`

- 已上架：记录提供商品入口和“前往可信空间购买”。
- 暂不支持：必须展示面向用户的原因和可选替代商品，不暴露内部审批细节。
- 同一用户对同一候选资产存在未结束记录时，不重复创建，只进入已有进度。

## 10. 领域模型调整

### 10.1 类型收口

`ProductType` 仅保留：

- `dataset`
- `api`
- `report`
- `dashboard`

原有 PQ/PIR 样例迁移为 `api`；联合分析和解决方案样例从前台目录移除。

### 10.2 新增或调整的模型概念

- `ProductOrigin`：`asset_platform`、`app_content`、`trusted_space`。
- `AvailabilityStatus`：`candidate`、`preparing`、`published`、`paused`、`delisted`。
- `AcquisitionOption`：`free`、`member`、`item_purchase`、`space_purchase`。
- `EntitlementPolicy`：区分报告的“指定版本永久访问”和看板的“按期限访问”，看板原型默认 12 个月。
- `PreviewPolicy`：按商品或内容区块描述 `visible`、`masked`、`locked`。
- `DatasetField`、`DatasetSampleRow`、`DataProfilingReport`：数据集类型附件。
- `ApiEndpoint`、`ApiSandboxCase`、`ApiErrorCode`：API 类型附件。
- `ReportContentBlock`：行业报告内容与付费墙配置。
- `DashboardMetric`、`DashboardPreviewPanel`：看板预览及打码配置。
- `ListingRequest`：求上架表单、处理状态和用户反馈。

现有 `dealChannel` 可以保留为展示派生值，但购买判断应由生命周期与获取方式共同决定，不能只依赖单一渠道字段。

## 11. 状态与数据流

### 11.1 商品详情

1. 路由通过商品 ID 读取目录商品。
2. 通用详情壳根据 `ProductType` 加载对应 Tab 配置与类型附件。
3. 权益服务结合生命周期、获取方式、登录/认证和用户权益计算主动作。
4. 用户切换 Tab 只更新详情页本地状态，不重复创建商品或权益状态。

### 11.2 求上架

1. 用户从候选商品卡或详情页点击“求上架”。
2. 未登录用户先完成原型登录，随后返回原商品表单。
3. 表单提交到求上架 store，候选商品进入对该用户可见的“已提交”状态。
4. 用户在“我的”查看进度；运营人员在现有 PC“试用与线索”页面的“求上架”分类中推进到评估中、上架准备中、已上架或暂不支持，不新增后台一级导航。
5. 已上架后，商品详情切换为可信空间购买入口。

### 11.3 APP 权益

行业报告和自有看板完成原型支付后创建权益：报告权益绑定购买时的报告版本且不设到期日，看板权益带有效期。详情页、报告内容区块和看板预览都读取同一权益判断结果，避免按钮显示已购买但内容仍被锁定。

## 12. 异常与恢复

- 商品不存在：展示空态并返回找数据结果。
- 类型附件缺失：保留商品摘要，对缺失 Tab 展示“资料准备中”，不渲染错误字段。
- 沙箱参数非法：字段级提示，不发送模拟请求。
- 沙箱模拟失败：保留参数，允许重新调试。
- 求上架重复提交：进入已有记录而不是生成重复记录。
- 求上架暂不支持：展示原因、替代商品和重新提交需求入口。
- 可信空间暂不可用：保留商品上下文，提示稍后重试，不伪造购买成功。
- 权益过期：内容重新进入打码/锁定状态，并提供续费或重新购买。
- 商品暂停或下架：禁用新购，历史有效权益按授权规则继续展示。

## 13. 验收标准

### 13.1 商品类型与详情

- 前台目录只出现四种商品类型。
- 四类商品详情均使用 Tab，且 Tab 内容符合本规格。
- 数据集能够展示基本信息、字段、脱敏样例和探查报告。
- API 能够完成固定脱敏样例的本地沙箱调试，并明确不是正式调用。
- 行业报告能够同时演示免费、打码和锁定内容区块。
- 自有看板能够演示免费、会员和限期单品三种权益效果。

### 13.2 交易与求上架

- 已上架数据集/API 只提供可信空间购买，不出现 APP 单品支付和试用。
- 候选数据集/API 只提供求上架，不展示样例值或购买入口。
- 求上架表单、状态记录和“我的”入口可以完整演示。
- 行业报告与自有看板的购买后权益即时生效；报告新版本不自动继承旧版本单品权益，看板权益过期后恢复受限状态。
- 看板单品购买默认显示 12 个月有效期。

### 13.3 工程质量

- 商品详情通用框架与四类内容组件边界清晰。
- 主动作由可测试的决策逻辑产生，页面不出现冲突按钮。
- 类型迁移后不存在指向 PQ/PIR、联合分析、解决方案的失效路由或筛选项。
- Vue 类型检查与生产构建通过。
- 关键商品状态和四条主链路完成浏览器冒烟检查。

## 14. 测试策略

- 单元测试：商品类型迁移、主动作优先级、权益有效期、预览策略和求上架去重。
- 组件测试：四类 Tab、候选资产受限状态、报告 `visible/masked/locked`、看板打码、API 沙箱参数校验。
- 流程测试：候选数据集求上架、已上架 API 沙箱后前往空间、报告开会员解锁、看板单品购买 12 个月解锁。
- 构建验证：运行 Vue 工程类型检查与生产构建。
