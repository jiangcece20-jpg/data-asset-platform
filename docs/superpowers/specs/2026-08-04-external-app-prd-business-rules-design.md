# 对外 APP 找数买数用数 PRD 业务规则补充设计

## 1. 目标与边界

本次补充用于消除功能说明 PRD 中搜索、购买、审批、状态、席位、账单和变化监控等复杂业务规则的歧义，使研发可以实现、测试可以形成唯一预期用例。

PRD 只描述业务口径、判断顺序、用户可见结果和允许操作。技术状态编码、模型阈值、稳定标识、接口映射、幂等、事务、存储和重试算法进入 SDD，不写入产品 PRD。

## 2. APP 意图与需求承接

### 2.1 意图判断

- APP 与 PC 均由用户手动切换“关键词检索”和“AI 问答”，不提供“智能识别”，也不在后台隐藏改判模式。
- 两端默认进入“关键词检索”；该模式只返回数据集、API、报告和看板商品，不返回问答正文。
- “AI 问答”保留连续对话和上下文；该模式返回答案、来源和相关商品，不把回答直接混入关键词商品列表。
- 切换模式时分别保留两个模式中尚未提交的输入和已有结果，用户返回原模式后可以继续原任务。

### 2.2 结果供给不足

- APP 找数据的“需求提交阈值”由运营后台配置，第一期默认值为 3。
- 有效匹配商品总数小于阈值时，在结果列表底部展示“没有完全满足？提交数据需求”。默认配置下，0～2 条结果展示入口，3 条及以上不展示。
- 数量按本次检索的全部有效匹配结果计算，不按 APP 首屏卡片数、分页数或已加载数量计算。
- 进入需求表单时自动带入原问题、当前对话上下文、已识别商品类型和筛选条件，用户可以修改。
- 问答案无法形成可靠回答时，继续按现有规则直接提供需求提交入口，不使用商品数量阈值。

## 3. 商品过滤、去重与综合排序

### 3.1 过滤与去重

- 只允许已包装、已发布且当前可在目录展示的商品进入搜索结果。
- 第一期关键词检索只展示数据集、API、报告和看板商品；企业内部视图、用户自建看板和用数模块内容不进入找数结果，由用数模块后续提供独立入口。
- 资产平台商品与可信空间商品即使主题或数据内容相近，也分别展示，因为来源、购买资格、价格、交付和售后渠道不同。
- 只对完全相同的商品记录去重，不跨来源合并，也不隐藏可信空间同类商品。
- 个人用户仍可浏览可信空间商品；页面提示仅认证企业可购买，不因当前无购买资格而降低排序。

### 3.2 综合排序

综合推荐按以下顺序逐级判断，前一层级不同即确定先后；仅在同级时进入下一层：

1. 用户明确指定的商品类型。
2. 商品名称或主题匹配。
3. 业务场景和标签匹配。
4. 商品内容描述匹配。
5. 运营配置的展示顺序。
6. 最近上架时间。

同一商品不得因命中多个字段重复出现。具体检索召回、相关度计算和同值稳定排序进入 SDD。

## 4. APP 方案、价格与有效期

### 4.1 价格计算

- 一次性方案使用方案总价。
- 持续方案只允许按完整计价周期购买，购买期限必须是计价周期的整数倍。
- 应付金额＝单周期价格 × 购买周期数＋明确增加项－明确优惠项。
- 第一期不按天折算，不自动执行周期阶梯折扣；所有优惠或调整均作为独立金额项展示。
- 可信空间价格只读展示，不由 APP 重新计算。

### 4.2 首次生效

- 持续服务从商品首次达到“可使用”时开始计期。
- “可使用”表示付款成功、权益创建成功且首次必要交付完成；交付中或交付失败不消耗服务期限。
- 生效时间和到期时间统一精确到秒，格式为 `YYYY-MM-DD HH:mm:ss`，系统统一按北京时间处理。
- 权益有效区间采用左闭右开：`生效时间 ≤ 当前时间 < 到期时间`；当前时间到达到期时间时立即失效。
- 列表页可简化展示到日期；订单详情、权益详情和续订确认页必须展示到秒。
- 可信空间商品使用空间返回的生效和到期时间；若空间返回其他时区，APP 转换为北京时间展示，同时保留原始时间和时区供对账。

### 4.3 续订

- 未到期续订从原到期日顺延；已到期续订从重新恢复为可使用时起算。
- 续订使用下单时最新启用方案和价格，主体不可转换。
- 续订延长原权益，不创建重复的“我的数据”入口。

## 5. 企业采购、锁价与付款

### 5.1 审批快照和锁价

- 采购申请提交时记录商品、方案、期限、席位数、许可范围和金额快照。
- 申请提交后的企业采购策略变化不改变该申请的审批流程。
- 管理员审批通过后，在配置的“审批后付款有效期”内锁定原方案和原价格；普通商品调价或方案更新不影响该申请付款。
- 超过审批付款有效期后申请变为已失效，申请人需按当前商品、方案和价格重新提交。
- 商品暂停新购或下架可提前终止未付款申请和订单的付款资格。

### 5.2 订单锁价和付款期限

- 订单创建时锁定商品、方案、期限、席位数、许可和应付金额。
- 在订单付款有效期内继续按锁定内容付款；商品调价不修改已创建订单。
- 未付款订单按付款方式配置付款有效期，超期自动关闭。
- 经过审批的订单实际付款截止时间取“审批付款截止时间”和“订单付款截止时间”中更早的时间。
- 主动关闭、超期关闭、商品暂停或下架后，只能按当前商品和价格重新发起购买。

### 5.3 企业付款方式

- 第一期支持企业余额、合同支付、公对公转账三类可配置方式。
- 商品或企业可开放一种或多种方式；只有一种时直接进入，多种时由经办人选择。
- 企业订单禁止个人支付方式。

## 6. 订单状态聚合与排序

订单卡保留审批、付款、权益、交付和外部同步原始状态；快捷状态仅用于列表归类，不能覆盖原始事实。

| 快捷状态 | 进入条件 | 用户主要看到的结果 |
| --- | --- | --- |
| 待付款 | 已具备付款资格，订单尚未完成付款，且未关闭 | 付款截止时间和继续付款 |
| 处理中 | 待审批、支付中、已付款但权益或必要交付未完成、交付重试或人工处理 | 当前处理轴、更新时间和下一步 |
| 已完成 | 付款完成，权益有效且必要交付达到可使用状态 | 使用入口、订单和权益结果 |
| 已关闭 | 申请驳回/撤回/失效，订单主动或超期关闭，付款取消，退款完成，或外部订单终止 | 关闭原因、历史事实和重新购买入口 |

冲突时按“已关闭 → 已完成 → 待付款 → 处理中”的顺序判断；已退款订单即使历史上完成过交付，也归入已关闭并保留历史时间线。

“我的订单”及各快捷状态分组均按下单时间倒序，不因最近更新、待办或异常改变排序位置。可信空间订单不进入本地订单列表，页面另设“查看可信空间订单”入口。

## 7. 企业席位与自动查询权限

### 7.1 席位口径

- 第一期企业方案必须配置席位数，不采用企业全员自动覆盖许可。
- 席位按每个已购商品权益分别计算，不跨商品、订单或权益共用。
- 企业席位必须由有权限的管理员显式分配；购买发起人和管理员都不自动获得首个席位。
- 成员成功获得某商品席位后，在该企业身份下自动获得查询和使用该商品数据的权限，不需要再次申请数据权限。
- 未获得席位的成员可以看到商品和企业已购提示，但不能查询受限数据。
- 收回席位、成员离职或企业成员身份失效后，成员立即失去该商品的企业查询权限；个人权益不受影响。

### 7.2 选择与批量分配

- 成员选择页展示总席位、已分配席位、剩余席位和当前新增人数。
- 已授权、成员失效或不属于当前企业的成员不可选择，并分别说明原因。
- 当前新增人数达到剩余席位后，系统直接阻止继续勾选其他成员，并提示先取消已选成员；页面不允许形成超额选择状态。
- 提交后因成员状态变化出现个别失败时允许部分成功：成功成员立即占用席位并获得权限，失败成员不占席位，页面逐项说明失败原因并允许重新选择后重试。
- 重复提交已授权成员不重复占位，也不生成第二份授权记录。

## 8. 可信空间商品、订单与 API 账单边界

### 8.1 商品信息同步与购买跳转

- 第一期只同步可信空间可上架资产、商品方案、价格和购买资格等商品信息，不同步交易订单和 API 账单。
- 商品信息不配置固定同步过期阈值，只展示当前同步状态和最近成功同步时间。
- 同步失败进入后台人工处理，不因经过固定时长自动判定过期。
- 用户前往可信空间购买时，若最新价格或资格刷新失败，仍允许按最近一次成功同步信息进入空间；页面必须提示信息时间和“最终以可信空间确认为准”。
- 可信空间在交易前最终确认价格、资格和可购方案，APP 不将历史同步信息作为成交承诺。

### 8.2 订单和 API 账单查看

- 可信空间当前无法区分由 APP 导流产生的订单和空间自有渠道订单，第一期不在 APP 建立可信空间订单镜像，也不展示其审批、付款、交付、退款或售后状态。
- “我的订单”只承载 APP 内创建的订单，并提供独立的“查看可信空间订单”入口，跳转到可信空间订单页面处理和查询。
- 第一期不在 APP 同步、汇总或重新计算可信空间 API 账单；账单入口跳转到可信空间 API 账单页面，以空间数据和规则为准。
- APP 不把可信空间订单或费用拼接到本地订单、企业订单、企业账单和 API 账单统计中，避免混入空间自有渠道交易。

## 9. 资产变化监控

- 每次检查以上次成功检查结果为比较基线；首次检查保存完整快照，并把全部内容作为首次发现的变化生成一条变化事件。
- 比较维度包括资源可用性、结构、规模、数据时效和合规状态；规模与时效阈值按资源配置。
- 同时命中多项变化时使用最高风险优先，不进行分数累加。
- 不可用、合规失效或破坏性结构变化初判为高风险；非破坏性结构变化、规模或时效超过阈值初判为中风险；普通元数据变化或预期范围内波动初判为低风险。
- 检查任务失败只表示“检查失败”，不自动生成数据风险。
- 系统初判后由运营确认正式等级；只有确认后的高风险变化可发起暂停新购，暂停仍需有权限人员确认。
- 首次检查生成的变化事件不自动初判风险，状态为“待确认”；运营必须选择低、中或高风险并填写原因，完成定级前不得发起暂停新购。后续变化事件才按规则自动初判。
- 第一期允许使用 Mock 监控数据验证上述流程。

## 10. 数据需求记录与反馈

- 第一期只形成“用户提交问题—运营查看处理—用户收到反馈”的轻量闭环，不建设优先级、排队、调序、撤回、重开、供给任务或复杂流转。
- 需求只包含“已提交、处理中、已回复”三个状态。提交后默认为已提交；运营开始处理时改为处理中；填写并发送反馈后改为已回复。
- 运营反馈以文本为主，可选关联一个已上架商品；系统不因关联商品自动改变需求内容或替用户下单。
- 用户通过站内通知收到反馈提醒，并可在需求详情查看原问题、提交时间、当前状态和回复内容。

## 11. PRD 落点

- 功能说明 PRD 新增“复杂业务规则”章节，并在相关功能表中增加交叉引用及本次调整日期。
- 完整模块 PRD 同步相同口径，删除与本设计冲突的全员许可、需求优先级、可信空间订单/账单镜像和同步过期判断。
- 更新验收清单，至少覆盖意图路由、低供给入口、搜索排序、价格与期限、审批锁价、状态聚合、席位上限、部分授权失败、可信空间外跳、首次监控定级、变化多规则冲突和需求反馈。
- 外部状态编码及映射、搜索相关度计算、去重稳定标识、金额精度和幂等实现进入 SDD。
- 飞书功能说明 PRD 以本地校准稿同步，并回读检查新增章节和关键规则。

## 12. 仍需外部确认

| 待确认问题 | 当前处理 | 确认方 |
| --- | --- | --- |
| 各方案审批付款有效期、各付款方式订单有效期的具体可选值 | PRD 规定必须配置和取较早截止时间；具体值由运营配置评审确定 | 交易产品、财务、运营 |
| 搜索相关度和同值稳定排序的技术实现 | PRD 规定业务优先级；计算方式进入搜索 SDD | 搜索/研发负责人 |
| 破坏性结构变化的字段级识别方式及规模/时效默认阈值 | PRD 规定风险结果；具体识别和默认值进入监控 SDD/配置评审 | 数据资产平台、数据治理、研发 |

## 13. 代表性验收示例

| 场景 | 输入或前置状态 | 唯一预期结果 |
| --- | --- | --- |
| APP 低供给 | 阈值为 3，有效匹配 2 条 | 展示 2 条商品，列表底部展示需求提交入口 |
| 跨来源同主题 | 资产平台和可信空间各有一个同主题商品 | 展示两张卡，不合并；分别说明渠道和资格 |
| 持续方案计价 | 单周期 100 元，购买 3 个完整周期 | 应付 300 元；不按天折算 |
| 交付延迟 | 已付款，首次必要交付仍处理中 | 付款保持已支付，服务期限尚未开始 |
| 到期边界 | 生效时间为 2026-08-05 10:00:00，到期时间为 2026-09-05 10:00:00 | 2026-09-05 09:59:59 仍有效；10:00:00 起立即失效 |
| 审批后调价 | 原方案审批通过且仍在付款有效期，商品后来调价 | 仍按审批锁定价格付款；页面展示截止时间 |
| 付款截止冲突 | 审批截止早于订单付款截止 | 使用审批截止时间作为最终付款截止 |
| 多轴订单状态 | 已付款，权益有效，交付失败重试中 | 快捷状态为处理中，原始各轴状态分别展示 |
| 订单历史排序 | 较早订单刚更新状态，较晚订单无更新 | 较晚下单的订单仍排在前面 |
| 席位达到上限 | 剩余 1 席，用户已选择 1 人后再点另一成员 | 阻止第二次勾选并提示先取消已选成员 |
| 授权个别失败 | 3 个已选成员中 1 个提交时身份失效 | 2 人授权成功并占用 2 席；失败成员不占位，显示原因并可重试 |
| 可信空间订单查看 | 用户曾跳转空间购买，随后进入 APP“我的订单” | 本地列表不生成空间订单；通过独立入口跳转空间订单页面 |
| 可信空间 API 账单查看 | 企业用户希望查看空间 API 调用费用 | APP 不聚合费用；通过独立入口跳转可信空间 API 账单页 |
| 首次资产检查 | 资源尚无历史成功快照，首次检查成功 | 保存全量快照并生成待确认事件；运营定级前不能暂停新购 |
| 多项资产变化 | 同时命中低、中、高风险条件 | 初步等级为高，待运营确认，不自动暂停 |
| 需求反馈 | 用户提交问题，运营填写文本并关联一个商品 | 状态变为已回复；用户收到站内通知并在详情查看回复和商品链接 |
