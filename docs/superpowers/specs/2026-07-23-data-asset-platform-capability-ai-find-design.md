# 数据资产平台能力全景与 AI 找数需求设计

## 1. 文档信息

- 日期：2026-07-23
- 受众：管理层
- 目标：形成一份可用于管理层汇报的资产平台一级模块与二级功能清单，并设计一张重点说明 AI 找数场景、意图、功能模块、依赖底座和建设节奏的需求图。
- 范围口径：完整目标蓝图，同时标记“已具备 / 建设中 / 待规划”。
- 状态依据：当前仓库中的模块 PRD、前端原型、竞品调研和《数据资产平台 · 2026 下半年规划》。

> 状态反映当前资料和原型覆盖情况，不等同于生产环境可用性。正式对外或立项汇报前，需要产品和研发共同校准“已具备”的生产可用口径。

## 2. 设计原则

1. 一级模块采用管理层容易理解的业务能力语言，不直接映射前端菜单或技术服务。
2. 二级功能覆盖完整目标形态，现状与规划通过状态标记体现，不因当前未建设而从蓝图中删除。
3. AI 不是孤立模块。凡是 AI 直接参与理解、推荐、生成、分析或判断的功能，统一标记 `✦ AI`。
4. 第一部分用表格列完整能力，方便查阅；第二部分只用一张图重点展开 AI 找数，避免两张复杂架构图争夺重点。
5. AI 找数从“找资产”扩展到“找、懂、查、析、用、治”，但 MVP 仍聚焦可验证的高频消费链路。

## 3. 状态与标记

| 标记 | 含义 |
| --- | --- |
| 已具备 | 当前 PRD 或原型已有明确产品能力，并已形成可演示或已上线链路 |
| 建设中 | 已进入 H2 规划、设计、开发或灰度范围 |
| 待规划 | 属于完整目标蓝图，但当前无明确交付计划或仅有方向性设想 |
| `✦ AI` | AI 直接参与该功能的理解、召回、推荐、生成、分析、诊断或评测 |

## 5. AI 找数需求设计

### 5.1 定位

AI 找数是资产平台面向数据消费侧的智能入口。用户只需要表达业务问题，平台负责理解意图、找到合适资产、返回可信答案，并衔接权限、预览、查询、分享和治理动作。

价值链如下：

```text
业务问题
→ 理解用户意图
→ 找到资产或执行查询
→ 返回带口径和来源的结果
→ 进入预览、申请、查询或治理动作
```

### 5.2 六类用户意图

| 意图 | 范围 | 示例 | 建设节奏 |
| --- | --- | --- | --- |
| 找 | 找表、指标、报表、看板、API、技术映射和替代资产 | “用户留存应该看哪张报表？” | MVP |
| 懂 | 查定义、口径、字段、负责人、更新时间、质量和权限状态 | “GMV 的口径是什么？” | MVP |
| 查 | 查指标值、明细、趋势、维度、对比、排名和占比 | “昨天 GMV 按城市分布” | MVP |
| 析 | 异常发现、原因归因、关联分析、预测和自动总结 | “GMV 为什么涨了？” | 逐步增强 |
| 用 | 预览、申请权限、进入查询、下载、API、收藏、分享和订阅 | “帮我申请这张表的权限” | MVP 先打通核心动作 |
| 治 | 纠错、补充说明、修正口径与血缘、报告质量问题 | “这张表的负责人不对” | 后续闭环 |

### 5.3 主要功能模块

#### A. 对话理解

- 自然语言输入与问题改写
- 用户意图识别
- 指标、时间、维度、分析动作和资产类型槽位解析
- 多轮上下文补位
- 歧义识别与候选确认
- 会话历史、新建会话和上下文清除

#### B. 智能检索与路由

- 全文检索、语义检索和知识图谱联合召回
- 找资产、查数、分析、定义咨询、技术映射和用数动作路由
- 结合角色、权限、质量、热度和资产状态进行排序
- 展示命中原因和推荐理由
- 无法直接查数时降级推荐资产
- 未命中、不支持和权限不足时提供诚实说明与下一步引导

#### C. 查数与分析

- 指标识别、指标注册表匹配和口径确认
- 数值、明细、趋势、维度拆解、对比、排名和占比查询
- 归因、异常和预测能力逐步扩展
- 查询执行、图表生成和摘要结论
- 结果中展示口径、数据来源、统计时间和更新时间

#### D. 可信与用数闭环

- 推荐表、指标、报表、看板和 API
- 报表与看板预览
- 表详情、字段说明、样例、分区和血缘追溯
- 权限申请和申请状态查看
- 携带表、字段和条件上下文进入即席查询
- 收藏、分享、订阅和反馈
- 将错误说明、口径、血缘和质量问题回流到治理流程

### 5.4 贯穿式对话控制

以下能力不作为业务意图单独展示，但必须贯穿所有意图：

- 上下文补位
- 意图切换
- 歧义确认
- 权限与安全拦截
- 能力边界说明
- 未命中与诚实降级
- 失败重试与改问引导
- 新建会话与清除上下文

### 5.5 输出结果

| 输出类型 | 内容 |
| --- | --- |
| 资产结果 | 表、指标、报表、看板、API 及推荐理由 |
| 可信答案 | 数字、图表、口径、来源、更新时间和质量状态 |
| 分析结论 | 趋势、对比、排名、占比、归因和异常提示 |
| 下一步动作 | 预览、申请权限、打开详情、进入查询、收藏、分享和反馈 |

### 5.6 可信数据与 AI 底座

| 底座能力 | 对 AI 找数的作用 |
| --- | --- |
| 资产目录与元数据 | 提供资产名称、说明、标签、字段、负责人和状态 |
| 数据标准 | 统一业务术语、数据元和代码含义 |
| 指标与语义层 | 提供指标口径、维度、时间规则和可查询范围 |
| 知识图谱与血缘 | 提供资产关系、业务映射、来源和影响范围 |
| 数据质量与时效 | 帮助判断结果是否可信和是否过期 |
| 权限与安全 | 控制资产可见性、查询范围和脱敏策略 |
| 检索引擎 | 提供全文、向量和混合召回与重排能力 |
| 查询与 BI 引擎 | 执行指标和 SQL 查询并生成可视化结果 |
| 大模型与 Agent | 完成理解、规划、工具调用和结果组织 |
| 评测与运营 | 监控成功率、准确率、成本、延迟和用户反馈 |

### 5.7 建设范围

#### MVP

- 找、懂、查、用四类核心意图
- 资产推荐与技术对象映射
- 指标值、趋势、维度、对比、排名和占比
- 多轮上下文和歧义确认
- 口径、来源和更新时间
- 报表/看板预览、表详情、权限申请和即席查询衔接
- 未命中、不支持和无法直接查数时的诚实降级

#### 后续增强

- 归因和异常解释
- 预测与关联分析
- 更多指标、维度和数据源
- 会话分享、订阅和主动推送
- 个性化推荐和反馈学习
- 纠错、口径、血缘和质量问题治理闭环

### 5.8 管理层成功指标

| 指标 | 含义 |
| --- | --- |
| 找数成功率 | 用户问题最终获得可用资产或可信答案的比例 |
| 首次提问命中率 | 无需反复改问即可得到正确结果的比例 |
| 零结果率 | 无资产、无指标或无法回答的问题比例 |
| 平均找数与拿数时长 | 从首次提问到获得可用结果的时间 |
| 业务自助用数率 | 无需数据人员介入即可完成的用数比例 |
| 可信信息覆盖率 | 查数结果中同时展示口径、来源和时间信息的比例 |
| 用数转化率 | 结果进入预览、权限申请、查询、收藏或分享的比例 |
| 单次找数成本 | 模型、检索和查询资源的综合调用成本 |

## 7. 异常与边界

- 无匹配资产：明确说明未找到，并引导补充业务域、时间、指标或资产类型。
- 指标存在歧义：展示候选指标、口径摘要和是否可直接查数。
- 指标未接入：说明已识别的指标与分析意图，降级推荐相关资产。
- 权限不足：不泄露受限信息，提供权限申请入口。
- 数据质量或时效不足：在结果中标记风险，不将不可信数据包装为确定结论。
- 查询失败：保留用户问题和解析条件，提供重试或进入即席查询的替代路径。
- 能力未覆盖：明确说明不支持，不生成看似合理但不可验证的答案。
