## 2. 建设背景

### 2.1 业务现状

当前数据供给同时存在于多个来源：APP 自营内容、数据资产平台上架资产、可信数据空间商品与 API，以及客户用数成果回流形成的入驻商家供给。用户有找数入口，但商品发现、购买主体、交易渠道、交付位置、后续使用与卖数回流尚未形成稳定闭环。

- APP 已具备用户入口、内容和部分问数能力，但缺少统一商品认知与完整交易后链路。
- 数据资产平台沉淀数据资源和资产事实，但资产需要完成商品包装后才能面向用户销售。
- 可信数据空间具备企业数据交易能力，价格和方案可同步展示。用户主按钮为「提交试用申请」（调整于 2026-08-25；~~提交意向单~~），不跳转空间购买；成交由运营到空间代办，空间买方须为认证企业。自有空间名称「万联易达可信空间」。
- 用数模块是数据集购买后的主要使用场景；本产品只负责把已购数据和权限交付到用数模块，不负责用数内部分析与报表制作。客户在用数做出成果后，可申请入驻并回 APP 上架售卖。
- 订单、权益、API 用量账单、需求反馈、数据变化事件与卖家订单分散，用户与运营都缺少统一视图。

### 2.2 核心问题

| 问题 | 业务表现 | 需要解决的产品命题 |
| --- | --- | --- |
| 供给分散 | 用户不知道数据来自 APP、资产平台、可信空间还是入驻商家 | 统一发现和展示，同时明确来源与交易渠道 |
| 信息不足 | 详情缺少价格、许可、质量、版本、样例、交付与卖家合规说明 | 建立按商品类型组织的评估信息 |
| 主体易错配 | 同一用户兼有个人和企业身份 | 购买主体必须贯穿订单、支付、权益、发票和可见范围 |
| 企业采购复杂 | 只让管理员购买效率低，完全放开又失去治理 | 允许普通成员按企业策略直购或提交审批 |
| 买后不可用 | 数据买到后不知道在哪里用、谁能用 | 将权益发放、用数模块交付、成员授权和首次使用纳入闭环 |
| 查询分散 | APP 订单、空间订单、API 账单与卖家订单不在一个入口 | 在 APP 提供统一查询，但不篡改外部权威事实 |
| 供给不闭环 | 无结果、询价和使用反馈不能稳定驱动供给 | 建立需求受理、供给任务、发布和回告链路 |
| 变化无治理 | 上游版本、质量、许可或状态变化影响新购与存量用户 | 建立变化监控、影响判断、暂停销售与处置恢复 |
| 成果难回售 | 客户在用数做出看板等成果后无法合规上架售卖 | 建设入驻商家准入、上架审核、结算与卖家订单（本期流程模块） |

### 2.3 建设机会

通过统一产品设计连接 APP、资产平台、可信空间与用数模块，形成：

`业务问题 → 找到数据 → 看懂商品 → 选择主体与渠道 → 完成交易 → 获得权益 → 在内容或用数模块中使用 →（可选）入驻上架售卖 → 反馈与供给改进`

价值不止增加订单，而是把数据资产转化为可发现、可购买、可交付、可使用、可卖出、可治理的产品能力。

## 3. 产品目标

### 3.1 产品定位

对外 APP 的「找数、买数与用数」不是独立数据商城，而是从业务需求出发的统一数据消费入口；入驻商家是其中的供给侧回流模块。

- APP 自营报告/看板、资产平台数据集、入驻商家数据集在 APP 内下单与交付（调整于 2026-08-25：买家打钱到平台，支付后待开通；~~入驻商家 MVP 为卖家自收款~~）。
- 空间数据集/API 在 APP 展示商品、方案、价格、空间名称（自有空间为「万联易达可信空间」）；列表成交位置出空间名，~~有样例/有试用接口不进列表~~（下线于 2026-08-25，详情仍可说明）。APP 不展示自有/互联。主按钮为「提交试用申请」（调整于 2026-08-25；~~提交意向单~~），用户不跳转空间购买、不在 APP 在线付。登录用户（含个人）可提交；当前企业只读回填。确认企业、确认方案、线下试用在线下完成。运营确认到账后转为买数订单，买方须为认证企业。数据集接到本平台用数；API 仍在空间使用。
- APP 汇总展示用户有权查看的订单、权益、意向单、API 账单与卖家订单；空间账单异议仍回空间处理。
- 找不到商品时进入需求闭环；上游数据变化时进入治理闭环；用数成果达标后可进入入驻上架闭环。

### 3.2 总体目标

让个人和企业用户从「我需要什么数据」出发，在一个入口实现：**找得到、看得懂、买得对、用得上、查得清、管得住、能闭环、能卖数**。

### 3.3 分目标

| 目标 | 目标结果 | 判断方式 |
| --- | --- | --- |
| 找得到 | 聚合 APP、资产平台、可信空间与入驻商家的可售商品 | 找数成功率、无结果率、结果来源覆盖 |
| 看得懂 | 展示价格/方案、口径、质量、许可、版本、交付与卖家合规摘要 | 详情完成率、详情到购买/询价转化率 |
| 买得对 | 购买主体、交易渠道、支付/结算方式和权益归属一致 | 主体/渠道错配率、支付成功率、审批时长 |
| 用得上 | 报告可阅读，数据集可交付到用数模块，企业权益可分配 | 权益到账时长、用数模块交付成功率、首次使用时长 |
| 查得清 | 在 APP 查看个人/企业订单、我的数据、API 账单与卖家订单 | 订单可追踪率、账单同步及时率 |
| 管得住 | 企业可配置采购策略；平台可审核、监控、处置风险与商家 | 越权事件、风险发现时长、异常恢复时长 |
| 能闭环 | 无结果和变化事件能够转为任务并完成回告或处置 | 需求响应时长、需求转商品率、受影响客户闭环率 |
| 能卖数 | 已准入卖家可上架用数成果，买家可成交，卖家可确认到账发权 | 准入通过率、上架发布时长、确认到账发权成功率 |

### 3.4 北极星指标

**有效用数闭环率**：有效找数需求中，最终形成以下任一可验证结果的需求占比：获得有来源且有权限的有效回答；获得并使用报告/看板；购买数据集并首次进入用数模块使用（含空间数据集接到本平台用数）；空间 API 由运营代办成交后仍在空间使用；没有现成供给时提交需求并获得有效回告；入驻商家商品完成购买并首次使用。

### 3.5 产品原则与边界

1. **先需求、后商品**：先理解用户任务，再匹配回答、内容、数据集或 API。
2. **展示统一、事实分离**：统一体验不等于复制或重算外部订单、账单和交付事实。用户不跳转可信空间购买。
3. **主体贯穿全链路**：个人购买仅本人使用；企业购买形成企业权益并可向员工分配。
4. **企业优先、允许切换**：同时具有个人和企业身份时默认企业购买，用户可切换个人身份。
5. **企业支付主体一致**：企业订单只允许企业余额、合同或公对公转账，不允许个人支付方式代付。
6. **一个商品一个资源**：当前不做商品包和多资源组合；空间单个商品可以包含多个购买方案。
7. **交易完成不等于价值完成**：必须继续追踪权益、交付、授权和首次使用。
8. **状态可解释、失败可恢复**：未知状态不能显示为成功，失败必须有重试、人工接管或明确去向。
9. **未包装资源不暴露**：资产完成商品包装和审核后才能进入前台；入驻商家须准入且上架审核通过后才可售。
10. **交付方式与期限显式定价**：APP 内成交商品支持按个人/企业分别启用一次性与持续方案；持续方案须设周期与最长购买期限。空间商品只同步空间方案和价格；主按钮为「提交试用申请」（调整于 2026-08-25；~~提交意向单~~），成交由运营代办。
11. **入驻商家是流程模块，不是独立产品**：卖家为 U1～U4 附加身份；商品/审核/订单权威在 APP；用数只提供可上架对象与获权打开；与需求回流并行，不互相替代。
12. **售卖须验卖方资质**：未准入不可上架；暂停/清退连动在架商品。

本期明确不做：数据集试用、原始明细下载、商品包、个人方式支付企业订单、APP 内裁决可信空间账单异议、用数模块内部分析和报表制作、未立项的项目制联合分析；入驻商家本期不做报告/派生数据集上架、代收代付自动分账、许可自动引擎、企业卖家多成员经营台。

### 3.6 报价、公开信息与到期规则

- APP 内成交商品可按需要启用个人/企业、一次性/持续方案，不要求每个商品同时开放四套方案。
- 数据集一次性交付是购买时点快照；报告是当前版本；看板是固定数据版本；API 是固定调用量包。
- 持续服务须限制最长可购有效期；到期后按类型停止更新/新版本/刷新/调用，并保留最近合法内容（许可撤权除外）。
- 空间数据集/API 仅认证企业可作为空间买方；APP 只读同步方案与价格。用户主按钮为「提交试用申请」（调整于 2026-08-25；~~提交意向单~~），不跳转空间购买。
- 看板指标定义购买前公开；图表数据仍按权益控制。
- 入驻商家商品前台必显：卖家名称、合规摘要、自有/衍生及源约束提示；调整于 2026-08-25：买家打钱到平台，平台按合同结算。~~MVP 结算为卖家自收款，页面明示平台不代收、不担保资金。~~（下线于 2026-08-25）

### 8.1 第一阶段：最小生产闭环

**阶段目标**：让一组真实商品、个人用户和试点企业能够安全完成「找—评—买—交—用—查—（可选）卖」，同时保证异常可恢复、事实可追溯。

#### 必须跑通的关键链路

1. 个人用户找到资产平台数据集，以个人身份在 APP 下单，完成支付并首次进入用数模块使用，权益仅本人可见。  
2. 企业普通成员以企业身份购买资产平台数据集，按企业策略直购或提交审批，使用企业支付方式并获得可分配的企业权益。  
3. 用户查看空间商品的空间名称（自有空间为「万联易达可信空间」）；列表成交位置出空间名。~~数据集有无样例、API 有无试用接口进列表~~（下线于 2026-08-25）。主按钮「提交试用申请」（调整于 2026-08-25；~~提交意向单~~）；运营到空间代办成交。数据集接到本平台用数；API 仍在空间使用。  
4. 用户在「我的」统一壳中按个人/企业范围查看订单、数据和账单，并可进入卖家中心功能菜单；所有来源、状态和下一步均可解释。  
5. 用户找不到合适商品时提交需求，运营可以受理、分派，并在商品发布或有替代方案时回告。  
6. 商品、资产或集成异常时，平台能够停止错误新购、保留存量事实，并完成重试或人工接管。  
7. **入驻商家**：用户申请准入并通过；上架 **数据集** 并发布；另一买家购买（个人或企业价）；付款后 **待开通**，运营开通后发权。~~上架看板并发布；卖家确认到账后买家获权打开看板~~（下线于 2026-08-25）；运营可强制暂停/下架。  

#### 建设范围

- 接入真实 APP 内容、资产平台商品白名单和可信空间商品/方案目录；目录可含入驻商家已发布商品。  
- 建设类型化详情，明确来源、价格、许可、版本、质量、交付与使用限制；入驻商家含卖家与合规摘要。  
- APP 内成交商品支持按需启用个人/企业一次性与持续方案；空间方案与价格只读同步。主按钮为「提交试用申请」（调整于 2026-08-25；~~提交意向单~~），不跳转空间购买。  
- 建设 APP 个人/企业订单，落地主体校验、企业单级审批和合规支付路径。  
- 建设空间试用申请：登录用户可提交；当前企业只读回填；运营领取、确认认证企业、去空间处理代办成交；数据集接入本平台用数，API 只记录成交结果（调整于 2026-08-25；~~建设空间意向单~~）。  
- 接入用数模块的数据集创建、刷新、到期和失败恢复；企业数据支持员工授权；提供可上架对象清单与开通契约。  
- 在 APP / PC「我的」建设统一壳：我的订单、我的数据、API 使用账单入口，以及卖家中心功能菜单（入驻申请/新建上架/卖家订单/我的上架单）。  
- 建设入驻商家本期竖切：准入 L1+L2、上架审、来源「入驻商家」、平台收款与待开通、运营强制处置（调整于 2026-08-25；~~结算 B~~）。  
- 建立基础需求受理与回告、商品审核、白名单资产变化监控和最小售后处置。  
- 建立权限、幂等、审计、埋点、告警和人工修正的生产底座。  

#### 阶段边界

不做数据集试用、原始下载、商品包、多级审批、高级推荐、自动化供给规划、用数内部分析与报表制作；不做入驻商家报告/派生数据集上架、代收代付 A、强制 L3、许可自动引擎。支付原型可跳转演示，但正式试点不得用个人方式支付企业订单。

#### 完成标准

- 购买主体、订单主体、支付/结算主体和权益主体在所有试点链路中一致。  
- 持续服务订单必须记录所选期限；超最长有效期不得创建订单；到期规则与许可撤权优先级正确。  
- 普通成员不能越权配置策略、审批或查看企业全量订单账单。  
- 支付成功但权益/交付失败时不回退支付事实，可重试或转人工；入驻商家未确认到账不得发权。  
- 空间意向单未落到认证企业时，不能进入空间成交；账单异议可准确回空间。  
- 未准入不可上架；未审核通过的商家商品不出现在前台。  
- 真实订单、权益、审批、退款、商家审核和人工修正记录可追溯，不物理删除。  
- 找数、详情、交易、交付、首次使用、需求回告与入驻卖数漏斗能够完整出数。  

### 8.2 第二阶段：运营治理闭环

**启动条件**：第一阶段真实试点已形成稳定指标基线。

#### 建设重点

- 优化搜索排序、详情信息、购买到首次使用路径和消息触达。  
- 完善金额阈值、预算、条件审批、多级审批、续期与到期提醒。  
- 打通企业余额、合同、公对公、发票与订单主体的正式协同。  
- 完善企业数据成员分配、收回、到期、续期、迁移和使用摘要。  
- 资产变化监控升级为正式任务、告警、影响分析和分级处置。  
- 完善退款、终止、补偿、客户通知、外部对账和账单差异处理。  
- 用搜索无结果、询价、购买和使用数据形成需求热度与供给优先级。  
- 增强入驻商家治理：巡检、材料过期、投诉工单、卖家经营摘要。  
- 建立商品、交易、交付、空间集成、用数使用、商家供给效率运营看板。  

#### 完成标准

- 找数成功率、详情转化、交付成功率和首次使用时长相对第一阶段基线持续改善。  
- 企业采购、支付、发票、授权和到期流程使用统一主体与状态口径。  
- 高风险变化能在 SLA 内完成新购控制、存量影响判断、通知和恢复。  
- 售后、对账、商家争议和集成异常有明确责任人、时限和闭环记录。  
- 高频需求与合格商家供给能稳定转化为商品或明确回告。  

### 8.3 第三阶段：规模化协同

**启动条件**：企业客户、商品供给和实际使用规模证明值得扩展。

#### 建设重点

- 多企业身份切换、复杂组织、分级管理员、预算控制和多级审批。  
- 标准化供给接入；落地入驻商家完整能力（报告/派生数据集、代收代付、L3 等）。  
- 个性化找数、适用性判断、商品推荐和需求预测。  
- 自动续期、到期处置、成员授权调整、异常恢复和客户通知编排。  
- 面向经营的企业价值、商品生命周期、供给效率和成本收益分析。  

#### 完成标准

- 新企业和新供给方能通过标准流程接入，定制性工作显著下降。  
- 规模增长下仍保持主体隔离、权限安全、交付稳定和变化处置质量。  
- 推荐、自动化和供给规划能用真实数据证明效果。  
- 商品包、多资源组合和项目制联合分析仍需单独立项。

## 9. 关键依赖与决策门

### 9.1 第一阶段关键依赖

| 依赖 | 必须具备的能力 | 未就绪时的试点降级 |
| --- | --- | --- |
| 企业身份与认证 | 正式企业认证、成员角色、企业映射 | 首期仅支持单一当前企业 |
| 数据资产平台 | 可商品化目录、版本/质量/许可和变化事实 | 商品白名单 + 定时对账 |
| 可信数据空间 | 商品多方案、价格、SSO、订单/交付/账单查询 | 仅开放已确认商品，未知状态不放行 |
| APP 订单与权益 | 持久化、权限、幂等、审计、售后入口 | 不以人工表格替代核心交易事实 |
| 用数模块数据集服务 | 创建、授权、刷新、到期、失败恢复；可上架对象与开通 | 首期单一交付模板；上架对象可先白名单 Mock |
| 看板平台 | 同步看板基础结构、面板和指标骨架 | APP 维护展示口径，不接管看板内部建设 |
| 支付/财务/发票 | 个人支付与企业余额/合同/公对公路径；平台收款记单（调整于 2026-08-25；~~自收款记单~~） | 企业试点限定一种正式企业支付路径；商家结算按合同人工确认（调整于 2026-08-25；~~商家自收款先人工确认~~） |
| 调度/告警/工单 | 定时任务、监控、重试、人工接管 | 白名单监控 + 日巡检 |
| 合规与商业制度 | 许可、样例、退款、到期、卖方资质与存量处置规则 | 未确认商品/卖家不进入试点 |

### 9.2 决策门

| 决策门 | 必须回答的问题 | 通过标准 |
| --- | --- | --- |
| Gate 0：范围冻结 | 首期服务谁、卖什么、入驻商家是否纳入、明确不做什么 | 试点企业/用户、商品白名单、入驻卖家试点、验收场景和非目标确认 |
| Gate 1：契约就绪 | 资产、空间、用数、支付、可上架对象能否提供权威事实和恢复机制 | 状态、权限、超时、幂等、审计和 SLA 联合评审通过 |
| Gate 2：试点准入 | 是否可以让真实用户安全交易、使用与卖数 | 核心链路、权限、财务、合规检查及运营 SOP 通过 |
| Gate 3：进入治理增强 | 产品是否稳定并产生有效用数与卖数结果 | 硬门槛无事故，异常可恢复，指标稳定出数 |
| Gate 4：进入规模化 | 是否值得增加企业、供给和自动化复杂度 | 第二阶段指标改善明确，业务规模达到立项条件 |

## 10. 指标与阶段验收

| 指标层 | 核心指标 | 说明 |
| --- | --- | --- |
| 北极星 | 有效用数闭环率 | 判断需求是否最终形成有效回答、购买使用、供给回告或入驻成交使用 |
| 发现 | 找数成功率、有效回答率、无结果率 | 判断入口和供给是否解决需求 |
| 评估 | 详情完成率、详情到购买/询价转化率 | 判断商品信息是否足够 |
| 交易 | 主体/渠道错配率、审批时长、支付成功率 | 判断购买是否正确和高效 |
| 交付 | 权益到账时长、用数模块交付成功率、首次使用时长 | 判断交易是否形成可用结果 |
| 查询 | 订单可追踪率、账单同步及时率 | 判断用户能否理解交易和费用 |
| 供给 | 需求响应时长、需求转商品率、回告转化率 | 判断需求是否驱动新供给 |
| 卖数 | 准入通过率、上架发布时长、确认到账发权成功率 | 判断入驻商家模块是否跑通 |
| 治理 | 风险发现/恢复时长、受影响客户闭环率 | 判断平台是否可持续运行 |

第一阶段上线前完成埋点和口径验收；试点运行形成稳定真实基线后，再评价后续阶段目标。严重权限越界、主体或渠道错误放行、重复扣款/重复发放、未确认到账却发权、未知外部状态展示为成功必须保持为 0。
