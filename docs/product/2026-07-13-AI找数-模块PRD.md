## 2. 模块定位与背景

### 2.1 一句话定位

**AI 找数**是面向消费侧的**对话式找数与用数入口**：用户用自然语言描述需求，系统识别意图后推荐资产或直接出数；报表看板**页内预览**，表**带上下文一键跳转即席查询**，不打断找数流程。

### 2.2 要解决的问题

- 用户说业务语言（"用户下单后的退款情况"），资产是技术语言（`dwd_trade_refund_detail`），关键词检索接不住。
- 找到资产只是一半：报表要看、表要查，用户找完还要跨模块折腾才能"用起来"。SQL 查询能力归**即席查询模块**，本模块负责带上下文衔接，不重复建设。
- 指标类问题（"昨天 GMV 是多少"）本质要的是**数**不是**资产列表**，需要直接出数的快捷路径。
- 数出来了不敢用：口径、来源、更新时间不透明，对管理层汇报场景是硬伤。

### 2.3 非目标（本模块不做 / 本期暂缓）

- **不替代资产检索**：AI 找数与资产检索为并列一级入口，各自独立演进。
- **权限闭环暂缓**：本期仅保留权限状态展示与"申请→申请中"的示意，申请理由、审批流、通知回流按权限中心 PRD 另行验收。
- **角色推荐策略暂缓**：不做基于角色的差异化推荐与过滤，后续迭代评估。
- **不做通用问答**：只处理找数 / 查数 / 表名映射三类意图，其余诚实告知无法处理。

## 3. 目标与成功标准

### 3.1 产品目标

- 业务描述可召回资产，指标问题可直接出数，两条路径**边界规则明确、可解释**（见 §6）。
- 找到即可用：报表看板页内预览，表展示结构与说明后携带上下文跳转即席查询。
- 每一个数都有来源与口径；每一次"听不懂 / 没找到 / 没接入"都诚实告知，不硬塞结果。

### 3.2 成功指标（可后续量化）

- 找数会话中完成"用数动作"（预览 / 运行 SQL / 打开来源表）的比例。
- 查数结果中来源与口径面板的查看率。
- 兜底（没找到 + 追问）占比与追问后的成功率。

## 6. 意图与召回策略（四层管道）

所有输入按以下管道处理，**优先级与顺序即产品规则**，实现不得依赖正则书写顺序等隐式约定：

```
用户输入
  → ① 意图分类   查数（指标+疑问/时间词） / 找资产（业务描述/资产词） / 表名映射（英文表名形态） / 不明确
  → ② 槽位解析   指标 · 维度 · 时间 · 分析类型（单值/分布/趋势/对比）；缺失槽位由上下文补位（仅此一处）
  → ③ 召回执行   查数 → 指标服务/白名单表；找资产 → 资产索引（报表 > 看板 > 表）；映射 → 血缘
  → ④ 兜底       歧义追问一次 → 诚实"没找到"
```

### 6.1 意图判定规则

| 规则 | 判定 | 示例 |
| ---- | ---- | ---- |
| 英文表名形态（含下划线 snake_case） | 表名映射 | `order 表在数仓里是哪张` |
| 指标 + 分析/时间词 + **无**资产词 | 查数 | `昨天 GMV 是多少` `近 30 天 GMV 趋势` |
| 指标 + 资产词（报表/看板/相关/表现…）或纯业务描述 | 找资产 | `各渠道 GMV 表现` `GMV 相关报表` |
| 说法不精确，命中多个候选指标 | **指标确认** | `昨天销售额是多少` → "GMV（支付口径）还是营收（确收口径）？"；确认后携带原句其余槽位重新路由 |
| 仅裸指标名（精确命中单个指标） | 默认给最新值 | `GMV` → 直接返回昨日 GMV，不追问 |
| 仅宽泛名词（用户/数据…） | 方向追问（最多一次） | `帮我找点数据` |

### 6.2 指标注册表

查数能力以**指标注册表**为准：每个指标登记别名、支持的分析类型、来源（指标服务 / 白名单表）、口径。新增指标只改注册表，查数 / 找数 / 上下文 / 追问自动生效。

- 指标已注册 → 查数意图直接出数。
- 指标未注册 → **降级找资产**，且回显识别到的完整槽位（"已识别你想查「退款率」的趋势，但该指标还没接入直接查数"），体现系统听懂了、只是能力未接入。

### 6.3 上下文规则

- 上下文条常显于输入框上方，展示当前话题，可手动清除；新对话自动清除。
- 短追问缺指标时（"趋势呢""按城市呢"）从上一轮补位，回复标注"已沿用上下文"。
- 补位是槽位解析的一部分，**不是**独立的匹配分支。

### 6.4 兜底原则

- 歧义每会话最多追问一次，追问后仍不明确 → 诚实"没找到" + 方向引导。
- 任何情况下**不得**默认塞某个话题的结果冒充命中。
- 映射未命中（表未收录血缘）→ 明确告知，不猜。

## 7. 功能需求

### 7.1 对话与输入（FR-AIF-01）

- 输入框支持自然语言与英文表名；Enter 发送，Shift+Enter 换行。
- 欢迎语说明三类能力（找资产 / 表配置查询 / 指标直接出数）并给引导标签。
- 引导标签、追问选项、最近找数记录点击即发送；**所有引导标签必须有真实落点**（路由到已覆盖场景）。
- **验收**：见 §8 场景矩阵一 ～ 五。

### 7.2 找资产召回与卡片（FR-AIF-02）

- 排序策略：报表 > 看板 > 表（可直接消费的优先）。
- 卡片要素：类型标签、名称、来源、描述、**推荐理由**、权限状态、按类型的用数按钮（预览报表 / 预览看板 / 查数配置 SQL）、详情。
- 整卡点击与主按钮行为一致（进入用数），避免双轨。
- **验收**：`各渠道 GMV 表现` 返回 3 张卡且排序正确；卡片按钮按类型分流。

### 7.3 查数（Chat BI 快捷路径）（FR-AIF-03）

- 支持四种分析类型：单值 / 维度分布 / 趋势 / 对比；左侧给摘要气泡，右侧给完整图表。
- **来源与口径面板默认展开**，包含：取数方式、来源表（可点击跳表工作区）、指标字段、时间条件、指标口径（业务口径 + 更新时效）。
- 未完整周期的数据须标注（如"今天：统计中，未完整"）。
- 查数结果提供"用来源表继续查 →"衔接自定义分析。
- **验收**：见 §8 场景矩阵二；口径面板内容完整、来源表可跳转。

### 7.4 表信息页（找到表之后）（FR-AIF-04）

- 展示表元信息（负责人 / 查询量 / 权限 / 更新频率）、业务说明、**表结构**（字段 / 类型 / 业务含义，默认展开）。
- 用数动作：**「去即席查询工作台」**，跳转时携带表名与字段上下文；SQL 生成与执行能力统一归即席查询模块，本页不内嵌（评审决策：降低页面复杂度，避免与即席查询重复建设）。
- **验收**：选中表展示元信息 / 说明 / 结构三段；跳转提示携带表上下文。

### 7.5 报表 / 看板嵌入预览（FR-AIF-05）

- 右侧内嵌预览（筛选条 + KPI + 图表）+ 指标口径说明；"打开原报表"跳转 BI 并携带当前筛选条件。
- **验收**：预览含口径；跳转提示携带上下文。

### 7.6 表名映射（FR-AIF-06）

- 业务库表名 → 血缘下游数仓表（ODS / DWD / DWS），每张带选用理由。
- 未收录的表名明确告知"血缘里没找到"。
- **验收**：`order` 返回 3 层下游表；未收录表名走诚实说明。

### 7.7 统一详情抽屉（FR-AIF-07）

- 结构与统一详情页对齐（真实实现直接复用统一详情组件装入 Drawer）：双层头部（`库名.英文名` + 中文名 + 来源 + 权限 + 收藏 + 复制）、信息完善度、目录路径、数据分类。
- Tab 矩阵按资产类型：表 = 字段信息 / 样例数据 / 分区信息 / 血缘关系 / 使用说明 / DDL变更 / 操作记录；报表·看板 = 定义 / 血缘 / 使用说明 / 操作记录。
- 字段带安全等级（S1–S5），S3 及以上样例脱敏（`******` + 🔒）。
- 抽屉内保留场景衔接："用这张表查数 →" 回到表工作区。
- **验收**：按 `2026-04-04-统一详情页-模块PRD.md` 的结构要求核对；脱敏规则生效。

### 7.8 权限（本期仅示意）（FR-AIF-08）

- 卡片与工作区展示权限状态（已有权限 / 申请权限 / 申请中）；点击申请仅做状态流转示意。
- 无权限报表在推荐理由中提示替代路径（先用底层表）。
