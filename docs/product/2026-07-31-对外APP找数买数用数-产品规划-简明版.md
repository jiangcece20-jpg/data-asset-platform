## 1. 一页结论

### 我们要做什么

建设统一数据消费入口。用户从“我需要什么数据”出发，完成找数、看商品、购买、交付、使用和查询；用数成果达标后，还可入驻上架卖数。

产品围绕找数、买数、交付与入驻卖数，协同以下数据来源与产品模块：

- 对外 APP：用户入口；含卖家中心。
- 数据资产平台：提供可包装、可上架的数据资产。
- 可信数据空间：既提供可包装、可上架的数据资产，也承接运营代办的空间成交；自有空间名称「万联易达可信空间」。
- 用数模块：承接已购数据的后续使用；该模块由其他团队负责，不在本规划建设范围。客户在用数做出成果后回 APP 售卖，由本期「入驻商家」流程模块承接（准入、审核、结算、卖家订单）；用数内部制作仍不在本模块建设。

### 产品最终解决什么

让用户做到这些事：

1. 找得到数据。
2. 看得懂商品。
3. 选对购买身份和交易渠道。
4. 买后能使用。
5. 在 APP 查到订单、数据和 API 账单。
6. 找不到或数据有变化时，平台能继续处理。
7. 用数成果达标后，可合规入驻上架卖数。

## 3. 为什么要做

当前数据分散在 APP、数据资产平台和可信空间。用户面临五个问题：

- 不知道去哪里找。
- 看不懂价格、质量、许可和交付方式。
- 个人身份和企业身份容易选错。
- 买到数据后不知道在哪里使用。
- 订单、数据、API 账单和售后入口分散。

平台也有三个问题：

- 搜索供给不足时不能稳定记录需求并向用户反馈。
- 上游数据变化后，不能及时判断是否影响新购和存量客户。
- 客户用数成果无法合规回流为可售供给。

因此需要一条完整链路：

`提出需求 → 找到数据 → 看懂商品 → 正确购买 → 获得权益 → 使用数据 → 查询与反馈 →（可选）入驻上架卖数`

## 4. 产品目标与关键规则

### 4.1 产品定位

产品不是单独建设一个数据商城。产品是对外 APP 中统一的数据消费入口；入驻商家是其中的流程模块。

统一三件事：

- 统一找数和商品展示（含入驻商家来源）。
- 统一用户购买前的判断体验。
- 统一订单、数据、账单与卖家订单查询入口。

不统一两件事：

- 不把可信空间交易复制成 APP 交易。
- 不重算外部系统的订单、交付和账单事实。

### 4.2 数据来源与购买方式

| 数据来源 | 在哪里展示 | 在哪里购买 | 谁能买 |
| --- | --- | --- | --- |
| APP 报告/看板 | APP | APP | 个人或企业 |
| 资产平台数据集 | APP | APP | 个人或企业 |
| 空间数据集/API | APP | APP 提交意向单，运营到空间代办成交 | 登录用户（含个人）可提交意向单；空间买方须为认证企业 |
| 入驻商家看板（本期） | APP | APP（卖家自收款） | 本期先个人 |

空间商品展示空间名称（自有空间为「万联易达可信空间」）、数据集有无样例、API 有无试用接口。APP 不展示自有/互联。主按钮为「提交意向单」，用户不跳转空间购买。方案和价格同步到 APP 展示。

### 4.3 个人购买与企业购买

| 购买身份 | 权益归属 | 使用范围 | 支付限制 |
| --- | --- | --- | --- |
| 个人 | 个人 | 仅本人使用 | 使用个人支付方式 |
| 企业 | 企业 | 可分配给企业员工 | 仅企业余额、合同或公对公转账 |

同一用户可以同时有个人和企业身份：

- 默认推荐企业购买。
- 用户可以切换为个人购买。
- 选择个人购买后，权益不能转给企业。
- 选择企业购买后，按企业管理员设置决定能否直接购买、是否需要审批。

### 4.4 报价方式

报价由商品来源和商品方案决定，与付款方式分开管理。

| 报价方式 | 适用商品 | 规则 |
| --- | --- | --- |
| APP 方案价 | APP 内成交的报告、看板、资产平台数据集，以及后续接入的 APP API | 商品可按个人/企业分别启用一次性交付和持续服务方案；不是每个商品都必须同时启用四套方案 |
| 一次性交付 | APP 内成交商品 | 数据集交付购买时点快照；报告交付当前版本；看板交付固定数据版本；API 交付固定调用量包 |
| 持续服务 | APP 内成交商品 | 数据集持续更新、报告持续获得新版本、看板持续刷新、API 持续调用；必须设置计价周期和最长可购有效期，不提供永久更新 |
| 免费或会员权益 | 部分报告/看板 | 按商品规则直接获取，不单独付款 |
| 可信空间同步报价 | 可信空间数据集/API | 仅认证企业购买；一个商品可有多个方案，方案内容和实际价格从可信空间同步，APP 不套用本地个人/企业价格模板 |
| 按量或套餐计费 | 可信空间 API | 以可信空间报价、用量和账单为准；APP 展示账单 |
| 询价 | 无标准价格或复杂需求 | 提交需求后人工报价；第一阶段只保留入口 |

当前一个商品绑定一个资源，不做商品包和多资源组合。可信空间报价以可信空间为准，APP 不改价、不重算费用。

持续服务到期后的默认规则：

| 商品类型 | 到期后的处理 |
| --- | --- |
| 数据集 | 停止更新，已交付的最近有效版本继续使用；许可或合规要求撤权时按专项规则处理 |
| 报告 | 不再获得新版本，已交付版本继续阅读 |
| 看板 | 停止刷新，保留最近有效版本查看；许可或合规要求撤权时按专项规则处理 |
| API | 停止新的接口调用，历史订单和账单继续保留 |

### 4.5 付款方式

付款由购买身份和交易渠道决定。订单、付款、发票和权益主体必须一致。

| 购买场景 | 付款方式 | 交易位置 | 权益归属 |
| --- | --- | --- | --- |
| 个人购买 APP/资产平台商品 | 个人支付方式；具体渠道由支付模块确定 | APP | 仅个人使用 |
| 企业购买 APP/资产平台商品 | 企业余额、合同支付、公对公转账 | APP | 企业权益，可分配员工 |
| 企业购买空间数据集/API | 按空间支持的方式付款（运营代办，本平台不收款） | 对方空间 | 数据集接到本平台用数；API 仍在空间使用 |

付款限制：

- 企业订单禁止使用个人银行卡、个人钱包等个人方式代付。
- 企业普通成员可以发起采购；是否审批由企业策略决定。
- 即使由成员发起，企业订单仍必须使用企业付款方式。
- 空间数据集/API 仅认证企业可作为空间买方；登录用户可先提交意向单，由运营代办；APP 不收款。
- 个人购买形成个人权益，不能转为企业权益。

### 4.6 买后使用与查询

- 报告/看板：在 APP 阅读或查看。
- 资产平台数据集：交付到用数模块使用。
- 企业购买的数据集：管理员可向员工分配权限。
- 空间数据集：运营代办到空间成交后，接到本平台用数；用户在「我的数据」使用。接入完成前不显示已买到。
- 空间 API：仍在空间使用；本平台只记录成交结果和使用说明，不代调用。
- **【新增】可信空间与万联灵析数据打通规则**：因可信空间与万联灵析订单暂未打通，**默认在可信空间和万联灵析都开通了账号的企业**，在万联灵析商业版中，可直接使用该企业在空间成交的、**支持下载的**（不需要通过沙箱使用）数据集；仅支持沙箱使用的数据集仍需在空间沙箱操作。
- APP 提供“我的订单、我的数据、API 使用账单”。
- 可信空间账单有异议时，跳回可信空间处理。
- 看板基础结构由关联看板/用数平台同步，运营维护前台展示口径和指标描述；指标定义属于购买前说明，无需解锁即可查看，图表数据仍可按商品权益控制。

本产品负责将已购数据和使用权限交付给用数模块，并展示使用入口和交付状态。用数模块内部的数据使用、分析和报表能力由对应团队负责，不在本规划建设范围。

### 4.7 当前不做

- 商品包和多资源组合。
- 数据集试用。
- 原始数据下载。
- 个人支付企业订单。
- 在 APP 处理可信空间账单异议。
- 用数模块内部的数据使用、分析和报表能力。
- 未完成包装和审核的资产直接上架。

### 5.1 五层产品架构

| 产品层 | 内容 |
| --- | --- |
| 应用层 | 用户端 APP、PC 门户、企业管理中心、运营管理后台（含卖家中心与商家审核） |
| 核心业务域层 | 找数、商品、交易、交付、订单账单、需求与变化治理、**入驻商家域** |
| 运营治理层 | 商品、目录、交易、企业、需求、售后、合规、**商家资质与上架**运营 |
| 公共能力层 | 身份（含卖家主体）、组织、权限、订单权益、支付结算（代收/自收款）、消息、搜索/AI、监控、审计 |
| 资源与协同层 | APP 内容、资产平台、可信空间、用数模块（交付与可上架对象）、企业认证、支付和财务 |

### 5.2 七个核心业务域

1. **找数问数**：统一入口、搜索、AI、筛选、无结果提交。
2. **商品与目录**：多来源商品（含入驻商家）、详情、方案、价格、质量和许可。
3. **购买与交易**：个人/企业身份、APP 订单、企业采购、空间商品意向单与运营代办、商家自收款确认。
4. **权益交付与用数**：报告阅读、数据交付到用数模块、员工授权；成果可回流上架。
5. **订单账单与售后**：买家订单、卖家订单说明、我的数据、API 账单和问题入口。
6. **需求供给与变化治理**：需求受理、商品上架、资产监控和风险处置。
7. **入驻商家（本期流程模块）**：卖家准入、资质合规、用数对象上架、结算、卖家订单（P8 / F14）。规则见完整版 §7。

## 6. 怎么建设：三阶段路线图

三个阶段只表示能力建设的先后关系，按进入条件和完成条件推进，不绑定自然月、季度或年度排期。

P0 原型已完成，是建设基础，不计入三个生产阶段。

### 路线总表

| 阶段 | 建设目标 | 主要内容 | 完成标志 |
| --- | --- | --- | --- |
| 第一阶段：最小生产闭环 | 真实跑通 | 商品目录、个人/企业购买、空间意向单与运营代办、用数模块交付、订单账单、基础监控、**入驻商家看板竖切** | 七条关键链路可用，失败可恢复，指标可查看 |
| 第二阶段：运营治理闭环 | 稳定运营 | 高级企业采购规则、支付发票、权益生命周期、售后对账、正式监控、需求供给、商家巡检与经营指标 | 流程有责任人和时限，核心指标持续改善 |
| 第三阶段：规模化协同 | 复制放大 | 多企业、复杂组织、入驻商家完整能力（报告/派生数据集与代收结算等）、标准接入、推荐和自动化 | 新企业和新供给接入成本下降，质量不下降 |

### 6.1 第一阶段：先跑通

重点建设：

- 接入真实商品目录（含入驻商家已发布商品）。
- APP 支持个人和企业购买资产平台数据集。
- 企业管理员可配置“是否允许普通成员采购、是否需要单级审批”，成员按基础策略直购或提交审批。
- 空间数据集/API 主按钮「提交意向单」；运营到空间代办成交。数据集接到本平台用数；API 仍在空间使用。
- 已购数据集交付到用数模块；企业权益可分配员工。
- APP 提供订单、数据和账单查询。
- 无结果可提交需求，商品发布后可回告。
- 监控重点资产变化；异常时停止错误新购并支持人工处理。
- **入驻商家本期竖切**：准入 L1+L2、看板上架、自收款确认到账发权、卖家订单、运营强制处置。

第一阶段完成条件：

- 个人订单不进入企业权益。
- 企业订单不使用个人支付方式。
- 空间意向单未落到认证企业时，不能进入空间成交。
- 支付成功、交付失败时可重试或人工处理；入驻商家未确认到账不得发权。
- 未准入不可上架；未审商家商品不进前台。
- 订单、权益、审批、退款、商家审核和修正记录可追溯。
- 找数、购买、交付、首次使用和入驻卖数数据能形成漏斗。

### 6.2 第二阶段：再管稳

重点建设：

- 优化搜索、详情和买后首次使用路径。
- 在基础采购开关和单级审批之上，增加金额、预算、条件审批、多级审批和续期提醒。
- 完善企业余额、合同、公对公、发票协同。
- 完善企业数据分配、收回、续期和到期处理。
- 将资产变化监控升级为正式任务、告警和分级处置。
- 完善退款、终止、补偿、通知和对账。
- 用搜索、询价、购买和使用数据指导新商品供给。
- 增强入驻商家巡检、投诉工单与经营摘要。

第二阶段完成条件：

- 找数成功率、交付成功率和首次使用效率持续改善。
- 企业采购、支付、发票和授权状态一致。
- 售后和风险事件有负责人、有时限、有结果。
- 高频需求与合格商家供给能形成商品或明确回告。

### 6.3 第三阶段：再放大

重点建设：

- 支持多企业、复杂组织、预算和多级审批。
- 接入更多供给方、可信空间和行业专区。
- 建立标准资源接入和商品包装流程。
- 增加个性化找数、适用性判断和推荐。
- 增加自动续期、到期处置、异常恢复和通知编排。
- 建立商品生命周期、企业价值和供给效率分析。

第三阶段完成条件：

- 新企业和新供给方能按标准流程接入。
- 规模增长不降低权限、交付和治理质量。
- 推荐和自动化能用真实数据证明效果。

商品包、多资源组合和项目制联合分析仍需单独立项。

## 7. 怎么判断做成了

北极星指标：**有效用数闭环率**。

有效结果包括：

- 用户得到有来源、有权限的回答。
- 用户获得并使用报告/看板。
- 用户购买数据集并首次进入用数模块使用（含空间数据集接到本平台用数）。
- 空间 API 由运营代办成交后，用户仍在空间使用。
- 没有现成商品时，需求得到有效回告。

重点辅助指标：

- 找数成功率。
- 商品详情转化率。
- 主体和交易渠道错配率。
- 用数模块交付成功率。
- 首次使用时长。
- 订单可追踪率。
- 意向单完成率。
- 需求转商品率。
- 风险发现和恢复时长。

四项必须为 0：严重权限越界、错误交易渠道放行、重复扣款/重复发放、未知外部状态显示成功。

## 8. 第一阶段启动前要确认

1. 试点企业、个人用户和商品白名单。
2. 资产平台许可、刷新、版本变化和到期规则。
3. 企业订单第一种正式支付路径和发票流程。
4. 用数模块的数据接收、授权、刷新、到期和失败恢复边界。
5. 可信空间商品方案、价格、SSO、回跳，以及订单页和 API 账单页的地址与访问权限。
6. 资产平台变化监控方式和责任人。
7. 产品、研发、测试、运营、合规和外部系统负责人。

## 9. 评审演示路线

评审演示采用一条完整主线：

`双模式找数 → 四类商品内容评估 → 个人/企业方案选择 → 企业审批与付款 → 交付异常重试 → 企业席位与我的数据 → 可信空间订单/账单外跳 → 供给不足反馈 → 商品配置 → 首次监控定级`

正式评审建议使用 20 分钟路线；时间不足时使用 12 分钟压缩路线。两条路线都必须覆盖四类商品和两条交易渠道，重点证明六件事：

1. APP 能统一发现资产平台与空间商品，展示空间名称（自有空间为「万联易达可信空间」）、数据集有无样例、API 有无试用接口，但不展示自有/互联。
2. 个人购买仅本人使用；企业购买形成企业权益，并受企业采购策略约束。
3. 企业订单只提供企业余额、合同支付和公对公转账，不允许个人代付。
4. APP 内支付、交付、权益和用数入口形成闭环；交付失败可以重试。
5. 空间商品主按钮为「提交意向单」；成交由运营到空间代办。数据集接到本平台用数；API 仍在空间使用。用户不跳转空间购买。
6. 供给不足、首次监控和企业席位均以第一阶段可评审的轻量规则形成闭环。

详细讲解步骤、评审话术和备用页面见：[《对外 APP 找数、买数与用数 · 评审演示路线》](./2026-07-31-对外APP找数买数用数-评审演示路线.md)。
