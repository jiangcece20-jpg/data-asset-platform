### 1.1 第一阶段功能边界

本节的“第一阶段”表示当前建设的能力范围，不对应固定月份或工期。

第一阶段建设：

- 关键词找数入口（首页检索、结果列表、筛选排序）。
- 与 AI 问答模块的入口对接（能力由其他团队负责）。
- 数据集、API、行业报告、自有看板四类商品。
- APP 内容和资产平台数据集的个人/企业购买。
- 空间数据集/API 的意向单与运营代办成交。
- 个人/企业单品价、普通/高级会员权益和固定可售卖周期。
- 企业成员权益分配（席位授权）；企业内认证成员（含普通成员）均可直接代表企业下单付款（调整于 2026-08-26）。
- 我的中心壳（我的订单、我的数据、卖家中心及占位一级入口），以及可信空间订单镜像回看与 API 账单外跳入口。
- 商品包装、编辑、审核、发布和变化监控。
- 供给不足时的需求提交、三状态反馈和异常人工接管。

第一阶段不建设：

- 商品包和多资源组合。
- AI 问答的回答生成、意图识别、来源引用、追问与权限披露细则（由智能找数/AI 问答团队负责）。
- 数据集正式试用（已购数据集支持在订单内下载）。
- 个人支付方式代付企业订单。
- 在 APP 内处理可信空间账单异议（订单镜像已回传，售后争议回空间处理）。
- 用数模块内部分析、报表制作和细粒度权限。
- 企业采购策略、单级审批及采购申请流程（调整于 2026-08-26；完整规划见 §12）。
- 预算、金额阈值、条件审批和多级审批。
- APP 自营 API 生产交易。
- 自动退款、自动迁移和全量变化自动处置。
- 看板付费墙运行时（解锁、扣次、糊层渲染）由其它产品负责；本模块仅提供自营收费看板的收费内容范围配置（新增于 2026-08-26）。

## 3. 角色与权限


| 角色     | 主要能力                     | 数据范围      |
| ------ | ------------------------ | --------- |
| 访客     | 浏览公开商品、回答和指标定义           | 公开信息      |
| 个人用户   | 个人购买、订单、权益和需求            | 仅本人       |
| 企业普通成员 | 代表企业直接采购、查看本人经办订单、使用已分配权益 | 当前企业内本人范围 |
| 企业管理员  | 查看企业订单与账单、分配权益           | 当前企业全量    |
| 运营人员   | 按职责管理商品、交易、交付、需求、售后和集成   | 已授权后台范围   |


关键限制：普通成员不能查看企业全量订单和账单；企业权益分配只允许管理员操作；后台审核、发布和人工修正需按角色留痕。第一阶段不做企业采购策略与审批控制，认证企业内任意成员均可直接下单（调整于 2026-08-26）。

### 3.1 身份与购买主动作

整理于 **2026-08-26**。原先散落在 §5.4.4、§5.4.6、§5.9、§10.1.4。本节为身份 × 购买按钮的权威说明；与后文冲突时以本节为准。后文旧口径划删除线保留，不物理删除。

原型顶栏三个身份对应本节四类用户：**访客**（未登录）、**个人**（陈静）、**企业管理员**（万联）、**企业普通成员**（王涛）。后两类都是「企业购买主体」；详情主按钮与购买页确认按钮均**不因管理员/普通成员而差异拦截**（调整于 2026-08-26；~~差别只在购买页能不能下单、要不要审批~~）。

#### 先分清两层按钮

| 层 | 出现位置 | 认什么 | 不认什么 |
| --- | --- | --- | --- |
| 详情主按钮 | APP 底部固定按钮；PC 右栏购买面板 | 登录、已购/交付、商品渠道、价格方案、当前购买主体（个人/企业） | 企业管理员 vs 普通成员 |
| 购买页确认按钮 | 结算/采购页 | 购买主体 + 付款方式 | 企业角色、企业采购策略（调整于 2026-08-26） |

同一时刻只保留一颗主按钮。切换身份后，价格、资格、主按钮和下一步一起刷新。

#### 详情主按钮：判断顺序

找到第一条命中即停止。

1. 服务冻结 / 已终止 → 「服务风险处置中」或「服务已终止」（禁用）。
2. 当前主体已有可用权益 → 「立即查看」。~~交付中写在本步~~（下线于 2026-08-29：交付中改入第 3 步「购买中」）。
3. **购买中**（当前主体对该商品已有未完成订单或未转买数的空间意向）→ 见下表；**不再出购买/提交试用申请**。
4. 商品暂停或下架 → 「暂停销售」/「已下架」（禁用）。
5. **空间数据集 / 空间 API** → 已登录「提交试用申请」；未登录「登录后继续」。个人和企业文案相同。
6. 商品整体免费 → 「免费查看」。
7. 数据集（含入驻商家）且可单品购买 → 「购买数据集」。
8. 配置了会员权益：
   - 当前会员已免费覆盖 → 「立即查看」。
   - 当前会员仅折扣 → 主按钮「会员价购买」；可保留次按钮原价购买。
   - 尚未开通会员且有单品价 → 详情展示「价格 / 会员价」摘要区；主按钮「立即购买」。点击后进入单品结算页，展示「直接购买 / 成为个人会员或团队会员」双路径及「会员购买立省 ¥X.X」气泡（调整于 2026-08-27；~~详情页同时展示开通会员与直接购买~~）。金额按当前身份对应单品价计算。
   - 尚未开通会员且无单品价 → 主按钮「开通个人会员，免费看本商品」或「开通个人会员，享 N 折」；企业主体把「个人会员」换成「团队会员」。点击后进入「购买 VIP」页（该模块由其它产品负责，本模块不在此页收款）。
9. 其余可买 → 「单品购买」。
10. 没有适用方案 → 「提交需求」。

入驻商家数据集不走会员价（2026-08-25）：第 8 步跳过，只出「购买数据集」。

#### 购买中：详情主按钮

新增于 **2026-08-29**；调整于 **2026-08-29（晚）**：空间试用申请**即生成订单**，订单状态为 **意向单**；与买数订单同一列表、同一订单详情。判定对象：当前购买主体对该 `productId` 的最近一笔未完成订单（含状态=意向单）。

| 相位 | 条件 | 详情底栏 | 落点 |
| --- | --- | --- | --- |
| 意向单 | 订单状态 `intent`（用户子态：已提交 / 处理中） | **查看订单** / **意向处理中** | **订单详情**（与其它订单同一详情壳） |
| 待付款 | `pending_payment` | **继续付款** | 可付则进付款页；不可付进订单详情 |
| 履约中 | `paid` / `pending_activation` / `payment_pending_confirmation` / `pending_approval` | **查看交付进度**；待开通→「待开通」；付款确认中→「付款确认中」 | 订单详情 |
| （结束购买中） | 权益已生效 / 意向单关闭 / 支付失败关闭 | 回到购买前或购买后规则 | — |

~~| 意向单 | … | 查看意向单 | 我的订单 → 意向单 Tab |~~（下线于 2026-08-29：改为统一订单列表 + 订单详情）

规则：已创建订单后离开结算/申请页再回商品详情，必须出「继续付款 / 查看订单 / 查看交付…」，**禁止**再出「立即购买 / 提交试用申请」叠单（承接 §5.9）。空间商品在订单仍为意向单期间**不再**出「提交试用申请」。

前提：商品正常在售、当前主体尚未拥有该商品权益、**且不在购买中**。已有权益一律「立即查看」；购买中见上一节。下表不再重复。

| 付款   | 个人订单使用个人在线支付；企业 APP 订单只允许企业余额、合同支付或公对公转账，禁止个人代付                                                                                                    |
| 定价   | 四类商品均可配置个人单品、企业单品和普通/高级会员权益；单品配置**原价 + 营销折扣**（默认 10 折），对外售价 = 原价 × 折扣 ÷ 10，会员权益叠在营销价上（调整于 2026-08-26）；付费商品配置一个固定可售卖周期，订单创建时锁定购买周期                                                                                     |
| 免费   | 商品整体免费与可售卖周期、个人单品、企业单品和会员权益互斥；选择免费后其他配置置灰且不参与保存                                                                                                  |
| 可信空间 | APP 只读同步商品、方案、价格、空间名称、数据集有无样例、API 有无试用接口；APP 不展示自有/互联。主按钮「提交试用申请」（调整于 2026-08-25；~~提交意向单~~）；运营代办成交。数据集接到本平台用数；API 仍在空间使用。售后与 API 账单回空间处理 |
| 用数   | 数据集交付入口按第 10.5 节「数据集交付矩阵」判定。摘要：资产平台已购已交付 → 进入用数，并按方案提供订单内下载；可信空间「可下载使用」且企业已开通找数买数 → 免费用数，并可按方案/回传提供下载；仅沙箱可用 → 不可用数、不可 APP 下载，仅前往空间/沙箱。用数内部分析不在本期范围 |
| 状态   | 订单、付款、权益、交付和外部同步分别展示；支付成功后权益或交付失败不能回退支付事实 |



| 商品类型 | 购买周期内              | 周期结束处理                |
| ---- | ------------------ | --------------------- |
| 数据集  | 获得约定更新，可进入用数或下载     | 停止更新，保留最近有效版本；合规撤权除外 |
| 行业报告 | 获得周期内发布的约定版本        | 停止新增，已获版本继续阅读        |
| 自有看板 | 按商品约定持续刷新           | 停止刷新，保留最近有效版本；合规撤权除外 |
| API  | 按空间调用量、有效期和交付规则使用   | 停止新增调用，历史订单和账单保留     |




## 5. 用户端功能说明



### 5.1 U01 找数首页

**入口**：综合 APP 首页“找数”；PC 门户首页或搜索发现。  
**使用者**：访客、个人用户、企业成员。

#### 5.4.3 APP 与 PC 的实际呈现

APP 和 PC 布局不同，演示时讲法也不同。

**APP（手机）：**

- 页面从上到下滚：返回→商品标题→风险提示（没有则不显示）→类型默认页签（数据集/API 先看基本信息，报告/看板先看内容）→报价方案→已有权益→底部固定按钮
- 底部按钮始终可见，不遮挡内容

**PC（电脑）：**

- 页面左右分栏：左边是商品内容（标题、页签、详情），右边是固定购买面板（方案、价格、按钮）
- 右边面板不压左边内容；可比较多个方案，点进去才进购买确认页，不在详情页直接扣款

**演示时 APP 怎么讲：** 先让用户判断商品类型和适不适合，再看来源和限制，最后看怎么买
**演示时 PC 怎么讲：** 先讲左边内容判断适不适合，再讲右边现在能做什么

#### 5.5.2 购买与交付规则

- 资产平台数据集在 APP 内下单和支付，可由个人或企业购买；个人权益仅本人使用，企业权益按许可分配给企业成员。
- 空间数据集主按钮为「提交意向单」；登录用户（含个人）可提交。运营到空间代办成交，空间买方须为认证企业。数据集接到本平台用数。
- **进入用数、订单内下载、前往空间/沙箱、是否进入「我的数据」一律按第 10.5 节数据集交付矩阵判定**；本节不另写例外。
- APP 商品按订单创建时锁定的购买周期交付；用户不选择周期或数据截止日期。商品后续修改可售卖周期不影响历史订单。
- 第一阶段不提供试用；有样例时未登录可看脱敏样例；无样例不假装能看。购买前样例和探查不可下载原文件。



#### 5.5.3 评审讲解顺序

1. 先展示基本信息，让用户判断数据内容、覆盖、粒度、规模、更新和来源是否匹配。
2. 再用“样例数据—字段信息—探查报告”说明数据形态、结构、口径和质量依据。
3. 说明数据来自哪里、在哪里付款、个人/企业价格及固定购买周期。
4. 最后按第 10.5 节说明购买后的用数、下载或前往空间入口，不展开用数模块内部能力。

**验收**：两类来源使用相同的数据评估逻辑，但成交渠道、购买资格和交付位置不会混淆；探查报告符合 §5.5.4。

##### 前台怎么用

1. 进入「探查报告」页签后，默认选中切换条中的第一个字段。
2. 用户切换字段时，右侧（APP 为下方）只刷新该字段的探查内容，不跳转离开详情。
3. APP：字段名横向滑动切换；PC：左侧字段列表、右侧探查内容。
4. 页底固定说明：「探查结果基于脱敏样本统计，数值经区间化处理，仅供评估参考。」
5. 不提供：自选 SQL、自由筛选全表、下钻原始行、下载探查明细。



##### 字段类型与展示指标

先按字段业务类型归入五类，再展示对应指标。所有类型**都展示**：空值率、唯一值数、更新时间；有异常时展示异常说明。


| 类型  | 典型字段          | 额外展示                                |
| --- | ------------- | ----------------------------------- |
| 数值型 | 整数、小数、浮点      | 最小、最大、平均；有则展示中位数、P25、P75；区间分布条（直方图） |
| 分类型 | 低基数文本、枚举      | TOP 值分布（名称、条数、占比）                   |

购买流程：

1. 用户选择购买主体。
2. 系统刷新可选方案、价格、支付方式和权益说明。
3. 用户确认订单信息。
4. 创建订单并付款（个人在线支付或企业付款）。
5. 付款成功后创建权益并执行交付。
6. 交付完成进入使用；交付失败进入自动重试或人工处理。

异常处理：

- 价格发生变化：阻止提交，提示刷新后重新确认。
- 付款取消或失败：订单保留待付款，可重新支付或关闭。
- 重复点击付款：按订单号幂等处理，不生成重复权益。
- 付款成功、权益失败：保留已付款状态，自动重试权益创建。
- 权益成功、交付失败：权益保持处理中，继续重试交付。
- 商品暂停销售：已付款订单继续履约；未付款订单禁止继续支付。

**关键交互**：

- 购买页采用分步结构：主体与方案、订单确认、付款、结果；顶部持续显示当前步骤，已完成步骤可返回修改，付款开始后不可返回修改订单主体。
- 切换主体、方案或期限时立即重新计算；计算中确认按钮禁用，发生价格变化时要求用户重新勾选确认。
- 表单缺失时在提交后定位首个问题并保留其他内容；提交处理中锁定按钮，重复点击进入同一申请或订单结果。
- 离开未提交购买页无需确认；已创建订单后离开，返回商品时显示「继续付款/查看交付」而非新建一单（调整于 2026-08-26）。

| 客户通知   | 按付款、权益、交付、失败、恢复和到期事件生成站内通知；运营可查看发送状态，失败可重发，用户可从通知进入对应详情              | 同一事件避免重复通知                                  |
| 对账差异   | 对账页列出 APP 与可信空间在订单、金额、状态或交付上的差异，展示两侧结果和更新时间；运营选择重新同步、确认空间结果或转人工核验       | 空间差异回归空间核对                                  |


**关键交互**：

- 工作台默认显示需要处理的订单或交付任务；筛选后顶部同步更新数量，打开详情再返回保留工作队列位置。
- 订单详情使用分轴状态卡和时间线；点击某状态进入对应交付、同步或售后记录，不用单一“处理”按钮。
- 手动重试前展示最近原因和已重试次数；提交后按钮进入处理中，同一任务不可再次触发。
- 人工接管需选择动作并填写原因；高影响动作确认对象和后果，完成后刷新任务负责人和时间线。
- 对账选择“以空间为准”前展示差异项；确认后重新读取镜像，失败保留差异待办。

**验收**：运营能定位“付了但没拿到”的订单，并在不修改支付事实的前提下恢复交付。

**关键交互**：

- 从商品、变化事件或订单进入售后时自动带入影响对象；运营先确认处置范围，再选择暂停、退款记录或补偿能力位。

**验收**：第一阶段能证明已考虑暂停、召回、退款、迁移和补偿，但自动化不作为上线条件。

### 7.11 跨模块研发评审约定

以下约定适用于全部用户端、企业中心和运营后台功能，评审时需逐模块确认是否有例外：


| 评审项   | 产品要求                                           |
| ----- | ---------------------------------------------- |
| 首次加载  | 页面进入后先展示结构占位或明确加载状态；不能把未加载完成展示成空数据             |
| 空状态   | 说明为什么为空，并提供与当前场景相关的返回、重置筛选、创建、提交需求或刷新动作        |
| 失败状态  | 展示用户能理解的失败原因、最近成功结果和可执行动作；外部状态未知统一显示“处理中”      |
| 无权限状态 | 说明当前身份、缺少的权限和可联系对象；不显示无效操作按钮，也不泄露受限内容          |
| 禁用状态  | 禁用操作同时展示禁用原因；商品暂停、企业未认证、方案不可用、权益过期分别使用明确文案     |
| 重复提交  | 下单、付款、分配、发布、交付和重试操作在处理中不可重复触发；重复进入显示原处理结果   |
| 页面返回  | 从登录、企业认证、购买、意向单或详情子页返回时，恢复原商品、主体、方案、筛选和未完成动作  |
| 状态刷新  | 页面展示状态更新时间；用户主动刷新后更新各状态轴，不用单一状态覆盖订单、付款、权益和交付   |
| 身份切换  | 切换个人或企业后重新判断价格、购买资格、订单范围、权益和账单权限，并清除上一主体受限内容   |
| 敏感信息  | 样例、接口、账单和企业信息只展示完成评估或使用所需内容；不展示密钥、敏感请求或未授权明细   |
| 操作确认  | 付款、驳回、收回权益、暂停、下架、退款等有明显影响的动作，确认前展示对象、影响和不可逆部分  |
| 操作反馈  | 成功显示结果与下一步；处理中显示进度或更新时间；失败保留已完成事实并提供重试或人工处理入口  |
| 通知承接  | 通知点击后进入对应订单、权益、交付、需求或变化事件详情，不只进入首页          |
| 时间口径  | 商品更新时间、同步时间、数据截止时间、订单时间、交付时间分别标识，避免只显示一个“更新时间” |
| 审计可见  | 权益分配、商品发布、人工修正和售后操作均保留操作者、时间、对象、结果和原因  |


研发评审以“正常流程可完成、异常流程可恢复、权限切换不越界、状态口径不混用”为通过条件。

### 9.4 详情页评审讲解顺序

### 10.1 搜索、供给阈值与排序

1. 调整于 2026-08-06：本模块找数主路径为关键词检索；AI 问答由其他团队负责。入口可保留切换或跳转，但不在本 PRD 定义回答能力。
2. 关键词检索仅返回已包装、已发布的数据集、API、行业报告和自有看板，不返回内部视图或问答正文。
3. 资产平台与可信空间的相似商品不跨来源合并；只去除同一商品记录的重复结果。
4. 有效结果数小于运营阈值时在列表底部展示需求入口；默认阈值为 3，因此 0～2 条展示、3 条及以上不展示。
5. 调整于 2026-08-08：列表排序选项统一为「默认」「价格↑」「价格↓」「最新」。有关键词结果与无关键词的发现/全部列表使用同一套规则。切换排序立即刷新并回到列表顶部，保留筛选条件；排序只改变先后，不改变谁能看见哪些商品。返回详情后再回列表时恢复所选排序。



#### 10.1.1 「默认」排序

**一句话**：给每个商品算一个总分，**分高的排前面**。

```
总分 = 文本相关分 + 运营排序权重 × 1 + 是否推荐位 × 100
```


| 项      | 怎么取值                              | 系数       | 说明                         |
| ------ | --------------------------------- | -------- | -------------------------- |
| 文本相关分  | 见下表，**最高 100**；算完后若超过 100 按 100 计 | ×1（直接加总） | 无关键词时全体为 0；封顶避免文本分过大压过运营排序 |
| 运营排序权重 | 后台配置的整数；未填按 50                    | ×1       | 运营可调                       |
| 是否推荐位  | 在推荐位＝1，不在＝0                       | ×100     | 无关键词时，推荐位通常压过普通权重差         |


同分时：上架时间更晚的在前；再相同则保持稳定次序。

用户筛选了商品类型时：先**过滤**掉不符合的类型，再对剩下的商品算分排序（类型不参与加分）。

**文本相关分怎么算**（只含名称/副标题、描述/推荐语；场景/标签不参与默认分）

```
文本相关分 = min(名称分 + 描述分, 100)
```

名称分——看「商品名称」「副标题」，取两者中更高的一档：


| 名称分 | 条件                              |
| --- | ------------------------------- |
| 80  | 与关键词完全一致                        |
| 60  | 完整包含关键词整段（连续包含）                 |
| 40  | 以关键词开头                          |
| 20  | 仅拆词命中（如关键词「货车轨迹」，名称只含「货车」或「轨迹」） |
| 0   | 名称、副标题都不命中                      |


描述分——详细描述或推荐语中出现关键词＝**20**，否则＝**0**。

名称分最高 80、描述分最高 20，合计最高 100；公式里再 `min(..., 100)` 防止以后加项超限。

多个关键词（空格分开）时：名称分取「命中最好的那个词」对应分；描述分任一关键词命中即为 20。

**无关键词**

文本相关分＝0，公式变成：

```
总分 = 运营排序权重 + 是否推荐位 × 100
```

即：先看推荐位，再看运营权重，最后上架时间。

**例子（有关键词「货车轨迹」）**


| 商品            | 名称分 | 描述分 | 文本相关分（≤100） | 权重  | 推荐位 | 总分            | 名次  |
| ------------- | --- | --- | ----------- | --- | --- | ------------- | --- |
| 全国货车轨迹热力数据集   | 60  | 20  | 80          | 86  | 1   | 80+86+100＝266 | 1   |
| 货车通行月报        | 20  | 20  | 40          | 70  | 0   | 40+70+0＝110   | 2   |

#### 10.1.2 「最新」排序

按上架时间从新到旧。无上架时间时，依次用空间最近同步时间、平台最近更新时间。时间相同则保持稳定顺序。

#### 10.1.3 「价格↑」「价格↓」排序

比较金额与卡片上的**起始价格**同一口径（见 10.1.4）。「价格↑」从低到高，「价格↓」从高到低。

先分成三类再比（「价格↑」时从前到后；「价格↓」时整类倒序）：

1. 免费类（商品免费，或当前展示为会员免费）
2. 有明确数字起始价的商品（按金额比大小）
3. 按需报价，或当前身份下暂无数字方案

同类内金额相同或同属非数字价时，上架时间新的在前，再保持稳定顺序。

#### 10.1.4 卡片价格与主体价格

列表卡只展示一个价格，须对应当前身份下用户能理解的购买起点。价格与详情主按钮分开计算；按钮文案见 **§3.1**。

**当前购买身份**


| 当前身份           | 展示价格       |
| -------------- | ---------- |
| 未登录，或登录后处于个人身份 | 已启用的个人单品价  |
| 登录后切换到企业身份     | 已启用的企业单品价  |


规则：按当前身份展示对应单品价，不把个人价和企业价混合。账号已绑定企业，但页面仍停在个人身份时，只展示个人单品价。

**APP 内购商品**

1. 商品整体免费时，卡片优先展示“免费”，不展示单品价或会员价。
2. 当前会员等级命中免费权益时，展示会员免费标签；命中折扣时，以当前主体单品价计算会员价。
3. 当前身份下未启用对应单品价时，不改用另一身份价格；个人身份展示“暂无个人价格”，企业身份展示“暂无企业价格”。
4. 商品固定可售卖周期在详情和结算页展示，不用于列表价格乘算。

**可信空间商品**

1. 价格以空间同步为准，APP 不改价。
2. 空间方案通常面向认证企业：卡片取同步且在售方案中的公开最低价，展示为「¥金额 起」（或沿用空间原始价本文案），并保留「可信空间成交」标识。
3. 个人或未登录用户仍可看到该公开最低价，便于评估；已登录用户（含个人）可提交意向单，企业由运营后续确认，不因展示最低价而开放空间侧直接购买。
4. 同步方案没有数字价时，展示「按报价」或空间给出的非数字说明。

**身份切换**

在个人与企业身份间切换后，卡片起始价和当前「价格↑ / 价格↓」结果立即按新身份重算。「默认」「最新」不含价格因素，不因身份切换而重排。

### 10.2 价格、生效与购买周期

1. 个人单品价和企业单品价均为商品固定购买周期的总价；会员折扣按当前主体单品价计算，不按天或用户选择的日期折算。

3. 生效和到期时间按北京时间精确到秒，展示为“年-月-日 时:分:秒”。有效期从生效时刻起（含）至到期时刻止（不含）。
4. 列表可只显示日期；订单详情和权益详情展示完整时间，订单中心同时展示购买周期月数。
5. V1.0 不支持用户自选购买周期、用户自选数据截止日期或按日期动态计价；续订使用续订下单时的最新价格和商品可售卖周期。

#### 10.5.4 可信空间边界（承接原规则）

1. 第一期同步空间商品、方案、价格和资格；价格刷新失败时可按最近成功信息继续进入空间，但必须提示最终以空间确认为准。
2. 空间订单以权威回传镜像进入我的订单和后台订单中心；镜像至少含空间订单号、商品、企业、金额、展示状态、交付摘要、同步时间、前往空间链接；下载入口仅矩阵允许时暴露。售后与 API 账单异议仍回空间处理。
3. APP 不伪造未经空间确认的订单状态，也不在 APP 内处理账单异议或改写空间权威事实。
4. 空间数据集免费用数、下载与我的数据展示严格按 10.5.2 矩阵判定；开通找数买数不能放宽仅沙箱授权。
5. 满足矩阵 S1 时不另收用数费，并可按 10.5.5 提供 APP 下载；未开通找数买数时即使空间已购可下载数据集，也只进「我的数据」回看与前往空间，不提供免费用数与 APP 下载（S2）。

| 权威来源   | 以可信空间回传/同步的使用授权为准；APP 只读展示                                         |

**APP 下载细则**


| 项     | 规则                                                                           |
| ----- | ---------------------------------------------------------------------------- |
| 适用    | 仅矩阵下载＝是（A1 且方案允许；或 S1 且方案/回传允许，并已开通找数买数）                                     |

| 使用对象  | 仅有成员使用资格者可下载；企业未占席/无空间资格成员不可代下                                               |
| 链接与审计 | 点击后获取短期可用地址，过期需重新获取；记录下载审计（操作者、时间、订单/权益、结果）。文件格式、次数上限与水印策略第一阶段不做产品验收硬标准      |


**订单镜像最小集**


| 项    | 规则                                   |
| ---- | ------------------------------------ |
| 必含字段 | 空间订单号、商品、企业、金额、展示状态、交付摘要、同步时间、前往空间链接 |
| 条件字段 | 下载入口仅矩阵允许时暴露                         |
| 同步失败 | 保留上次成功镜像并标识同步时间；不伪造已交付               |


1. 新需求为待处理；运营从推荐现有商品、需要定制、暂不支持中保存一个互斥结果。推荐时可关联一个已发布商品，暂不支持时二次确认；保存后用户收到站内提醒。
2. 不建设试用审批、求上架、分派、关闭、独立处理中、优先级、排队、聚合、撤回、重开和供给任务。
3. 资产监控首次成功检查保存完整快照，并把全量内容生成“待人工定级”事件；运营选择低/中/高并填写原因前不得暂停新购。
4. 后续检查以上次成功检查为基线；同时命中多项变化时取最高风险，不做分数累加。检查失败不自动生成数据风险。
5. 只有人工确认后的高风险事件可发起暂停新购，暂停仍需有权限人员确认。
