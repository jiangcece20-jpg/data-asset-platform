### 1.1 第一阶段功能边界

本节的“第一阶段”表示当前建设的能力范围，不对应固定月份或工期。

第一阶段建设：

- 关键词找数入口（首页检索、结果列表、筛选排序）。
- 与 AI 问答模块的入口对接（能力由其他团队负责）。
- 数据集、API、行业报告、自有看板四类商品。
- APP 内容和资产平台数据集的个人/企业购买。
- 可信空间数据集/API 的认证企业购买衔接。
- 一次性交付、持续服务和有效期方案。
- 企业基础采购策略、单级审批和成员授权。
- 我的中心壳（我的订单、我的数据、卖家中心及占位一级入口），以及可信空间订单镜像回看与 API 账单外跳入口。
- 商品包装、编辑、审核、发布和变化监控。
- 供给不足时的需求提交、三状态反馈和异常人工接管。

第一阶段不建设：

- 商品包和多资源组合。
- AI 问答的回答生成、意图识别、来源引用、追问与权限披露细则（由智能找数/AI 问答团队负责）。
- 数据集正式试用（已购数据集支持在订单内下载）。
- 个人支付方式代付企业订单。
- 在 APP 内处理可信空间账单异议（订单镜像已回传，售后争议回空间处理）。
- 用数模块内部分析、报表制作和细粒度权限。
- 预算、金额阈值、条件审批和多级审批。
- APP 自营 API 生产交易。
- 自动退款、自动迁移和全量变化自动处置。

## 5. 用户端功能说明



### 5.1 U01 找数首页

**入口**：综合 APP 首页“找数”；PC 门户首页或搜索发现。  
**使用者**：访客、个人用户、企业成员。  
**目标**：提供关键词找数入口，并保留与 AI 问答模块的对接入口；本 PRD 只定义关键词路径。


| 功能        | 详细说明                                                | 规则/状态                                         |
| --------- | --------------------------------------------------- | --------------------------------------------- |
| 关键词检索入口   | APP 与 PC 均提供关键词输入与提交；提交后进入找数据结果页                    | 本模块默认路径与主验收路径均为关键词检索                          |
| AI 问答入口对接 | 页面可保留“AI 问答”切换或入口，点击后进入其他团队建设的 AI 问答能力              | 调整于 2026-08-06：AI 问答能力不在本 PRD 展开与验收；原型可保留完整演示 |
| 热门场景      | APP/PC 展示运营配置的热门问题或场景；关键词模式下点击后带入检索词，用户可修改再提交       | 由运营配置；不改变搜索结果权限                               |
| 推荐商品      | 首页分类型展示推荐数据集、API、报告和看板；卡片展示名称、类型、来源、一句话摘要和价格摘要      | 只展示已发布商品；内容预览早于交易信息出现                         |
| 最近记录      | PC 展示最近搜索和商品浏览；APP 可展示最近检索记录。AI 问答会话记录由 AI 问答模块自行维护 | 按个人账号保存；两端分别恢复各自交互状态                          |
| 状态处理      | 关键词提交后在结果区展示加载状态；失败时保留用户输入并提供重试                     | 失败可重试；空内容不可提交                                 |


**关键交互**：

- 用户进入找数后默认关键词检索；若点击 AI 问答入口，跳转或切换到其他团队模块，返回时可回到关键词检索并尽量恢复原输入。
- 关键词提交只执行商品检索，不进行隐藏意图改判，不混入问答正文。
- 有效匹配商品数小于运营配置阈值时，在列表底部展示需求提交入口；默认阈值为 3。
- 提交按钮在内容为空时禁用；处理中阻止重复提交。

**验收**：关键词检索可进入找数据结果；推荐区不出现未包装资源；AI 问答入口可进入，但不按本 PRD 验收其回答能力。

### 5.2 U02 AI 问答对接说明

**边界说明**：AI 问答（含回答生成、来源引用、权限披露、追问、购买后重新生成等）由其他团队负责，本 PRD 不写功能明细。  
**本模块只约定**：


| 功能   | 详细说明                                | 规则/状态                |
| ---- | ----------------------------------- | -------------------- |
| 入口可达 | 找数首页提供进入 AI 问答的入口或模式切换              | 能力实现归智能化团队,验收归创新产品团队 |
| 商品回流 | AI 问答中推荐或引用的已包装商品，可进入本模块商品详情继续评估与购买 | 商品详情、购买、订单、交付按本 PRD  |
| 需求回流 | AI 问答无法满足时，可跳转本模块需求提交并尽量带入原问题       | 需求状态与回告按本模块 U12      |
| 原型保留 | 联调与评审原型可继续演示 AI 问答完整路径              | 原型演示不等于本 PRD 交付范围    |


**关键交互**：

- 从 AI 问答进入商品详情后，返回路径优先回到 AI 问答原上下文；从 AI 问答进入购买并完成交付后，是否提示重新生成由 AI 问答模块定义。
- 本模块不因 AI 问答结果改写关键词检索列表状态。

**验收**：存在可达的 AI 问答入口；从该入口进入的商品可完成本模块买数闭环。回答质量、来源与追问不在本验收清单。

### 5.3 U03 找数据结果

**入口**：APP 与 PC 在找数首页提交关键词后进入；若用户从 AI 问答返回关键词检索，尽量保留已输入内容。
**目标**：聚合多来源已发布商品，支持快速筛选和判断。


| 功能   | 详细说明                                                                                             | 规则/状态                                                                           |
| ---- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| 结果列表 | APP 与 PC 均直接进入关键词检索结果；顶部展示关键词与有效结果数，下方展示数据集、API、报告、看板四类商品，可继续筛选、排序和加载                            | APP、资产平台、可信空间统一卡片骨架；不混入 AI 回答或内部视图                                              |
| 卡片信息 | 每张卡片展示名称、一句话摘要、类型标签、成交渠道标签、提供方、更新频率和起始价格；起始价格先按当前购买身份过滤方案再取最低可展示价（见 §10.1）；可信空间商品额外标识"可信空间成交" | 移动端卡片为轻量骨架；列表保持轻量，不展开脱敏样例、接口示例、报告封面大图或看板趋势图；个人身份也展示全部个人和企业购买方案，但引导做企业认证 |
| 筛选   | 用户可按商品类型、业务场景、资源来源、更新频率和价格特征组合筛选；已选条件以标签显示，可逐项取消或一键重置                                            | 筛选后保持关键词                                                                        |
| 排序   | 提供「默认」「价格↑」「价格↓」「最新」；切换排序后刷新结果并保留筛选条件                                                            | 调整于 2026-08-08：文案与界面统一；有关键词与无关键词列表同一套加权公式；默认排序与起始价口径见 §10.1；排序不改变谁能看见哪些商品       |
| 状态展示 | 卡片按商品状态显示可购买、暂停新购、商品资料同步延迟或本地权益已到期等提示；不可购买时替换购买引导为查看原因                                           | 暂停商品不提供新购；商品列表不展示空间订单状态，已回传订单在“我的订单”查看                                          |
| 无结果  | 无匹配商品时展示当前检索条件、修改关键词建议和“提交数据需求”入口；进入表单时自动带入本次关键词与筛选条件                                            | 不展示候选资产和前台求上架                                                                   |
| 登录承接 | 浏览和搜索无需登录；收藏、提交需求或进入个人记录时弹出登录；登录成功后回到原结果位置并继续未完成动作                                               | 登录后恢复原结果和动作                                                                     |


**关键交互**：

- APP 关键词结果中的商品卡片保持轻量；用户进入商品详情前可判断类型、来源与内容方向，完整封面/样章/趋势预览在详情页完成。
- PC / APP 找数据结果默认使用「默认」排序；当前关键词固定显示，修改关键词并提交后重置页码并保持关键词找数路径。
- PC 筛选常驻或展开，APP 完整结果使用筛选面板；勾选条件后显示已选标签，确认后更新结果数量。
- 切换排序立即刷新列表并回到列表顶部；返回商品详情后恢复筛选、排序、分页和滚动位置。
- 切换个人 / 企业身份后，卡片起始价与「价格↑ / 价格↓」结果按新主体重算；「默认」「最新」不因身份切换改变相对顺序（除非价格排序正在生效）。
- 加载更多期间按钮防重复；请求失败保留已加载卡片并仅重试失败页，不清空整个列表。

**验收**：APP 与 PC 均由用户选择关键词检索后展示商品列表；每张商品卡在不进入详情的情况下即可理解商品内容并区分类型和来源；数据集与 API 卡片不前置字段或接口文档；供给不足时进入需求闭环；排序四选项与 §10.1 一致；卡片起始价随当前购买身份变化。

### 5.4 U04 商品详情通用框架

**入口**：搜索结果、推荐商品、收藏、订单、我的数据或 API 账单。
**目标**：按商品类型帮助用户先完成正确判断：报告和看板先看实际内容，数据集和 API 先看基本信息与适用范围，再深入查看样例、字段或接口文档。

调整于 2026-08-03：详情页不再用一条纵向顺序同时描述 APP 和 PC。两端使用相同的商品信息和状态判断，但根据屏幕空间采用不同布局；同时补充浏览发现、交易处理、已有权益和外部回流四类页面入口。

调整于 2026-08-04：详情页采用“内容优先”顺序。商品标题后默认进入最能证明价值的类型内容；报价、购买资格和方案负责承接交易，不得遮挡报告正文、看板数据、数据样例或接口示例。

调整于 2026-08-05：进一步区分类型定位。报告默认进入“在线阅读”，看板默认进入“看板预览”；数据集和 API 默认进入“基本信息”，用户再按需查看样例数据、字段信息、接口文档和在线调试。

#### 5.4.1 页面信息逻辑


| 信息区域   | 回答的问题           | 包含内容                               | 展示原则                                    |
| ------ | --------------- | ---------------------------------- | --------------------------------------- |
| 内容识别区  | 这是什么内容，能否解决当前问题 | 商品名称、类型化内容预览、公开样例或摘要、内容版本或数据时间     | 报告和看板直接展示内容；数据集和 API 先以基本信息说明用途、覆盖和服务能力 |
| 来源说明区  | 由谁提供，内容是否可信     | 提供方、资源来源、更新频率、覆盖范围、质量与合规材料         | 内容之后补充判断依据；资源来源与成交渠道分别表达                |
| 交易决策区  | 怎么买，买到什么，可以使用多久 | 报价方式、定价责任方、价格方案、购买主体、服务方式、有效期、许可范围 | 报价方式与具体价格方案分开；可信空间价格只读                  |
| 权益与服务区 | 当前能否使用，出现问题怎么办  | 已有权益、交付状态、服务风险、API 用量入口、主动作        | 状态优先于营销信息；只给一个明确主动作                     |




#### 5.4.2 页面入口


| 入口类型   | 具体入口                                  | 进入详情后的承接                                                              |
| ------ | ------------------------------------- | --------------------------------------------------------------------- |
| 浏览发现入口 | 关键词找数结果、发现页推荐、收藏列表；以及来自 AI 问答模块回流的商品卡 | 默认进入类型定位页签：数据集和 API 进入“基本信息”，报告进入“在线阅读”，看板进入“看板预览”；返回时恢复原列表或 AI 问答上下文 |
| 交易处理入口 | 我的订单、采购申请、付款结果和交付进度                   | 从统一订单卡进入对应商品详情并优先展示当前订单、审批或交付状态；主动作变为继续付款、查看审批、查看交付或进入使用              |
| 已有权益入口 | 我的订单、我的数据、企业已购权益、会员覆盖内容、API 使用账单      | 进入详情后识别已有权益，不重复展示购买为唯一动作；保留返回原订单、数据或账单页面的路径                           |
| 外部回流入口 | 可信空间购买回跳、空间订单或账单状态通知                  | 恢复原商品、原企业身份和原空间方案；优先展示购买结果或处理中状态，不以回跳本身判定成功                           |
| 消息通知入口 | 审批结果、交付结果、持续更新到期、报告新版本、商品服务风险等通知      | 进入对应商品和状态位置；通知已失效时仍说明原事件及当前最新状态                                       |


入口规则：

- 所有入口均进入同一商品详情，不为订单、权益或通知复制独立商品说明页。
- 详情页始终按商品最新销售状态、最新价格和当前用户权益重新判断；入口携带的旧状态只用于定位，不覆盖最新事实。
- 从列表、订单、账单或通知进入时记录来源；用户返回优先回到原页面和原筛选位置，而不是统一返回首页。
- 商品已暂停或下架时仍允许从订单和已有权益进入详情，用于查看历史购买、服务影响和后续处理。




#### 5.4.3 APP 与 PC 的实际呈现

APP 和 PC 布局不同，演示时讲法也不同。

**APP（手机）：**

- 页面从上到下滚：返回→商品标题→风险提示（没有则不显示）→类型默认页签（数据集/API 先看基本信息，报告/看板先看内容）→报价方案→已有权益→底部固定按钮
- 底部按钮始终可见，不遮挡内容

**PC（电脑）：**

- 页面左右分栏：左边是商品内容（标题、页签、详情），右边是固定购买面板（方案、价格、按钮）
- 右边面板不压左边内容；可比较多个方案，点进去才进购买确认页，不在详情页直接扣款

**演示时 APP 怎么讲：** 先让用户判断商品类型和适不适合，再看来源和限制，最后看怎么买
**演示时 PC 怎么讲：** 先讲左边内容判断适不适合，再讲右边现在能做什么


#### 5.4.4 底部按钮：显示什么由这 9 个条件决定

按顺序判断，显示第一个匹配的：

| 优先级 | 用户状态 | 按钮显示 |
| --- | --- | --- |
| 1 | 服务不可用 | 暂不可用 |
| 2 | 已购/交付中 | 查看权益 / 交付处理中 |
| 3 | 商品暂停/下架 | 暂停购买 |
| 4 | 数据同步失败 | 同步异常 |
| 5 | 未做企业认证/未绑定空间 | 去认证 / 去绑定 |
| 6 | 可信空间商品 | 去可信空间购买 |
| 7 | 免费/会员可买 | 免费使用 / 会员专享 |
| 8 | 正常可买 | 立即购买 |
| 9 | 搜索结果少 | 提交需求 |

同一时刻只显示一个主动作，可以附带一个不冲突的次动作。


#### 5.4.5 关键交互规则

**从哪进详情页，决定默认显示什么：**
- 从列表/发现页进来 → 默认打开内容页签（让你先看商品本身）
- 从订单/权益/通知进来 → 自动定位到对应状态，回来时恢复你最后看的那个页签

**数据同步失败时：** 不清空页面内容，保留上次成功的数据和更新时间
**价格或资格不确定时：** 按钮灰掉，不让下单
**资料没准备好时：** 显示"暂无内容"提示，不填假数据

资格提示规则：

- 个人用户浏览到的商品内容和认证企业一致，不因身份隐藏公开的价格、字段、样例、接口文档或指标定义；差异只发生在购买资格、主动作和企业专属订单权益信息。
- “去企业认证”“切换企业身份”和“查看认证进度”均为可操作入口；不得以没有解释的灰色“认证企业后购买”按钮结束流程。

- 企业名称只在已认证且当前已选择该企业时展示；个人身份下不预设企业订单归属。



### 5.5 U05 数据集详情

#### 5.5.2 购买与交付规则

- 资产平台数据集在 APP 内下单和支付，可由个人或企业购买；个人权益仅本人使用，企业权益按许可分配给企业成员。
- 可信空间数据集只允许已认证企业前往可信空间购买；APP 负责展示商品、校验资格、携带上下文跳转和恢复原浏览现场；订单以空间权威回传镜像。
- **进入用数、订单内下载、前往空间/沙箱、是否进入「我的数据」一律按第 10.5 节数据集交付矩阵判定**；本节不另写例外。
- 一次性方案交付下单确认时的数据快照，不自动更新；持续方案在有效期内持续更新，必须展示计价周期和最长可购买期限。
- 第一阶段不提供试用；购买前样例和探查不可下载原文件。



#### 5.5.3 评审讲解顺序

1. 先展示基本信息，让用户判断数据内容、覆盖、粒度、规模、更新和来源是否匹配。
2. 再用“样例数据—字段信息—探查报告”说明数据形态、结构、口径和质量依据。
3. 说明数据来自哪里、在哪里付款、有哪些快照或持续方案。
4. 最后按第 10.5 节说明购买后的用数、下载或前往空间入口，不展开用数模块内部能力。

**验收**：两类来源使用相同的数据评估逻辑，但成交渠道、购买资格和交付位置不会混淆；探查报告符合 §5.5.4。

#### 5.5.4 数据探查报告规则

调整于 2026-08-08：探查报告采用**字段级**结果，不再用整表一张「质量结论」代替字段探查。整表质量文案如需保留，只可作为基本信息或商品说明中的补充说明，不能替代本页签。

**目标**：购买前帮助用户判断「关键字段长什么样、质量是否够用」，不提供任意查询、不下发明细。

##### 谁能看、看到什么


| 情形                    | 页面表现                       |
| --------------------- | -------------------------- |
| 商品已发布，且至少有 1 个可展示探查字段 | 展示字段切换条 + 当前字段的探查内容        |
| 商品已发布，但没有任何可展示探查字段    | 展示「暂无可探查字段」                |
| 商品未发布 / 资料准备中         | 展示「资料准备中」，不展示具体探查数字        |
| 某字段已开放但结果尚未产出         | 该字段不进入切换条；后台显示「未产出」，不可勾选开放 |
| 已开放且有结果的字段被运营取消开放     | 前台立即不再出现该字段                |


可展示探查字段＝**运营已开放**，且**已有探查结果**。二者缺一不可。

样例数据页与探查报告页的内容均不可下载、不可导出为原文件。

##### 前台怎么用

1. 进入「探查报告」页签后，默认选中切换条中的第一个字段。
2. 用户切换字段时，右侧（APP 为下方）只刷新该字段的探查内容，不跳转离开详情。
3. APP：字段名横向滑动切换；PC：左侧字段列表、右侧探查内容。
4. 页底固定说明：「探查结果基于脱敏样本统计，数值经区间化处理，仅供评估参考。」
5. 不提供：自选 SQL、自由筛选全表、下钻原始行、下载探查明细。



##### 字段类型与展示指标

先按字段业务类型归入五类，再展示对应指标。所有类型**都展示**：空值率、唯一值数、更新时间；有异常时展示异常说明。


| 类型  | 典型字段          | 额外展示                                |
| --- | ------------- | ----------------------------------- |
| 数值型 | 整数、小数、浮点      | 最小、最大、平均；有则展示中位数、P25、P75；区间分布条（直方图） |
| 分类型 | 低基数文本、枚举      | TOP 值分布（名称、条数、占比）                   |
| 标识型 | 高基数文本、业务主键类编码 | 唯一性；可选脱敏样例格式（如「ENT-XXXX」），不展示真实完整标识 |
| 时间型 | 日期、时间戳        | 最早日期、最晚日期、时间跨度；按周期分布（如按季/按月）        |
| 布尔型 | 是/否           | 是与否的条数及占比条                          |


同一字段只归入一类。文本字段由运营/数据侧在产出探查时定「分类」或「标识」，前台按结果类型展示，用户不可改类型。

##### 开放规则（运营后台）

在商品/资源编辑的「数据探查配置」中维护：

1. 列表展示：字段名、业务含义、类型、敏感提示、是否已产出探查结果。
2. **仅「已产出探查结果」的字段可勾选开放**；未产出的不可勾选。
3. **默认不勾选**：主键字段、敏感等级为 L2 或 L3 的字段。
4. **第一阶段禁止开放**：主键字段、敏感等级 L3。即使用户想勾选，保存时拒绝并提示原因。
5. **L2 字段**：默认不勾选；运营可手动开放，保存时二次确认「将对外展示该字段的统计分布」，并留操作痕迹。
6. 保存后立即作用于已发布商品的前台探查页签；未发布商品仍显示「资料准备中」。
7. 取消开放不删除已产出的探查结果，只是前台不再展示；再次勾选可恢复。



##### 数据来源与更新


| 来源      | 探查结果从哪来                | 说明                                         |
| ------- | ---------------------- | ------------------------------------------ |
| 资产平台数据集 | 资产侧或商品包装时产出的字段探查       | APP 只展示已同步结果，不在详情页现算                       |
| 可信空间数据集 | 空间同步的对外探查/质量摘要，落到字段级结果 | APP 不改权威统计；同步失败时不展示过期字段结果冒充最新，可提示「探查资料待更新」 |


探查更新时间取该字段结果上的更新时间；列表或页签不要求实时刷新，用户再次进入详情时取当前已同步结果。

##### 与「字段信息」「样例数据」的边界


| 页签   | 回答什么                   | 不回答什么     |
| ---- | ---------------------- | --------- |
| 字段信息 | 有哪些字段、类型、含义、是否主键/可空/敏感 | 分布、最值、占比  |
| 样例数据 | 固定脱敏样例行长什么样            | 全量统计、区间分布 |
| 探查报告 | 已开放字段的统计形态与质量信号        | 原始明细、自由查询 |




##### 验收要点

- 已发布且有开放字段时，探查页可切换字段并看到与类型相符的指标。
- 无开放字段时文案为「暂无可探查字段」；未发布为「资料准备中」。

| 付款     | 个人订单展示个人在线支付入口；企业订单只展示已开放的企业余额、合同支付或公对公转账；付款取消、失败或处理中时保留订单并提供对应操作        | 企业订单禁止个人支付                 |
| 结果页    | 提交付款后分别展示订单状态、付款状态、权益状态和交付状态；每个状态附更新时间和下一步，支持查看订单或返回商品                   | 付款成功不等于交付成功                |
| 使用承接   | 交付完成后结果页和订单详情按第 10.5 节矩阵显示使用入口；交付未完成时显示进度或处理说明                           | 按矩阵展示主动作；不因付款成功默认同时开放用数与下载 |


购买流程：

1. 用户选择购买主体。
2. 系统刷新可选方案、价格、支付方式和权益说明。
3. 企业普通成员触发企业策略校验。
4. 需要审批时先提交采购申请；审批通过后由申请人继续付款。
5. 不需要审批或审批已通过时创建订单并付款。
6. 付款成功后创建权益并执行交付。
7. 交付完成进入使用；交付失败进入自动重试或人工处理。

异常处理：

- 价格发生变化：阻止提交，提示刷新后重新确认。
- 付款取消或失败：订单保留待付款，可重新支付或关闭。
- 重复点击付款：按订单号幂等处理，不生成重复权益。
- 付款成功、权益失败：保留已付款状态，自动重试权益创建。
- 权益成功、交付失败：权益保持处理中，继续重试交付。
- 商品暂停销售：已付款订单继续履约；未付款订单禁止继续支付。

**关键交互**：

- 购买页采用分步结构：主体与方案、订单确认、付款、结果；顶部持续显示当前步骤，已完成步骤可返回修改，付款开始后不可返回修改订单主体。
- 切换主体、方案或期限时立即重新计算；计算中确认按钮禁用，发生价格变化时要求用户重新勾选确认。
- 表单缺失时在提交后定位首个问题并保留其他内容；提交处理中锁定按钮，重复点击进入同一申请或订单结果。
- 离开未提交购买页无需确认；已创建申请或订单后离开，返回商品时显示“继续审批/继续付款/查看交付”而非新建一单。
- 付款返回后以查询到的状态展示结果；未知状态显示处理中和刷新，不用页面跳转结果直接判定成功。

**验收**：个人和企业订单主体、支付和权益不串用；结果页能区分付款、权益和交付状态。

### 5.10 U10 可信空间购买衔接

**适用商品**：可信空间数据集、可信空间 API。
**入口**：详情页“前往可信空间购买”。
**目标**：在 APP 完成评估和企业资格校验，在可信空间完成正式交易；返回后以空间权威回传订单镜像供回看，售后与 API 账单仍回空间处理。


| 功能      | 详细说明                                                               | 规则/状态                                                  |
| ------- | ------------------------------------------------------------------ | ------------------------------------------------------ |
| 企业身份校验  | 用户点击“前往可信空间购买”后，系统校验登录状态、当前是否为企业身份及企业认证状态；未满足时展示缺失条件和登录、切换企业或去认证入口 | 个人身份、未认证企业不能购买                                         |
| 企业切换    | 用户属于多个企业时，在跳转确认前展示企业选择；选择后刷新认证状态、成员权限和可购买方案，校验失败时停留当前页并说明原因        | 切换后重新校验认证和权限                                           |
| 方案确认    | 确认页展示从空间同步的方案名称、计费方式、包含权益、价格、有效期、更新时间和服务说明；用户只能选择方案，不能在 APP 修改内容   | 只读，不在 APP 改价                                           |
| 跳转确认    | 跳转前用明确提示说明合同、企业付款、正式交付、凭证和账单均在可信空间完成；用户确认商品、企业和方案后进入空间对应页面         | 用户确认后携带商品和企业上下文跳转                                      |
| 返回恢复    | 用户从空间返回 APP 时恢复原商品、原企业和原方案，并提供“继续前往可信空间购买”或进入“我的订单”回看              | 回到 APP 不代表成交成功                                         |
| 返回处理    | 从空间返回后，以空间权威回传订单镜像；APP 展示交付摘要，并用数/下载/前往空间按第 10.5 节矩阵展示，不以回跳本身判定成功  | 状态以空间回传为准；即使回传带 downloadUrl，未满足矩阵（如 S2/S3）也不在 APP 展示下载 |
| 订单与使用入口 | 我的订单展示空间回传订单；用数、下载、前往空间按第 10.5 节矩阵展示                               | 成交与售后仍以空间为准；不免费用数不等于改写空间授权                             |
| 账单异议    | 可信空间 API 账单入口提供“前往可信空间处理异议”；APP 不展示完整账单明细、处理状态或本地异议表单              | APP 不受理、不生成本地异议单                                       |


关键规则：

- 未登录：登录后恢复原商品。
- 无企业上下文：引导加入或切换企业。
- 企业未认证：引导完成企业认证，再返回原商品。
- 空间价格最新刷新失败：仍可按最近成功商品信息进入空间，并提示最终价格与资格以空间确认为准。
- 跳转后未回 APP：用户可从商品或个人中心入口前往可信空间；空间回传到达后出现在我的订单。
- 空间订单结果：以空间权威回传为准；APP 展示镜像供回看，不对账改写权威事实。

**关键交互**：

- 点击空间购买先打开资格与跳转确认；缺少登录、企业上下文或认证时，确认页只保留对应补齐动作。
- 多企业用户在确认页选择企业；切换后方案区显示加载状态，校验完成前不能继续跳转。
- 跳转外部空间前记录原商品、企业和方案；用户取消跳转时停留详情，不生成已完成订单。
- 回跳或重新打开 APP 时恢复原商品、企业和方案；有空间回传时在我的订单展示镜像。
- 空间不可访问时展示稍后重试和复制商品信息，不降级为 APP 内购买。

**验收**：个人用户不能发起空间购买；认证企业可完成“APP 评估—空间成交—订单镜像回看—账单异议回空间”的闭环。

| 需求表单 | 表单按业务语言收集使用场景、希望获得的数据、覆盖范围、粒度、更新频率、期望时间、预算区间和联系方式；分组展示必填与选填内容 | 不要求用户填写技术字段   |
| 主体选择 | 登录用户选择以个人或当前企业提交；企业需求展示企业名称和当前成员身份，切换主体时重新确认联系方式和需求可见范围       | 企业需求记录当前企业    |
| 即时推荐 | 用户填写关键信息后展示可能匹配的已发布商品；可先查看商品再返回继续提交，也可标记“不符合”并补充原因            | 推荐不代表需求已完成    |
| 需求详情 | 提交成功后生成需求详情，展示需求摘要、当前状态、负责人或响应说明、商品推荐、补充记录和回告时间线              | 只看本人或当前企业权限范围 |
| 结果回告 | 运营回告时按“已有商品可用、仍在评估、可形成供给、暂不可供给”展示结论、依据、推荐商品和下一步；用户可反馈是否解决     | 回告需说明下一步      |
| 处理状态 | 用户查看已提交、处理中、已回复三种状态                                           | 第一期不提供撤回或重开   |
| 反馈提醒 | 运营回复后用户收到站内提醒，并查看文本反馈和可选商品链接                                  | 不建设复杂处理时间线    |


处理状态：已提交、处理中、已回复。
处理结论：暂无结论、已有商品可用、可形成供给、暂不可供给、用户确认解决。处理进度和处理结论分别展示，不再把“已有商品可用”写成流程状态。

**关键交互**：

- 从搜索或问答进入时先展示自动带入内容；用户修改后，原始来源仍作为只读背景保留在需求详情。
- 表单分组展示必填与选填；提交时定位首个缺失项，已填写内容不丢失，提交中阻止重复需求。
- 即时推荐卡片在表单旁或提交前出现；进入商品详情再返回时恢复表单内容，标记“不符合”后可继续提交。
- 第一期不显示优先级、队列位置、撤回、重开或供给任务；反馈发送失败时保留运营输入，成功后只更新为已回复。
- 运营要求补充时，用户从通知进入对应需求和待补内容位置，提交后回到最新处理状态。

**验收**：无结果场景不暴露候选资产；用户能看到需求处理状态、推荐理由和下一步。

## 6. 企业中心功能说明

调整于 2026-08-03：补齐企业中心及各子模块入口，并与“我的订单 / 我的数据”统一入口对齐。企业中心负责企业身份、采购策略、采购审批和权益分配；企业订单复用统一「我的订单」（含空间镜像），API 账单仅外跳可信空间，不重复建设另一套订单或账单列表。
调整于 2026-08-08（V2.6）：「我的」升级为统一壳后，企业中心仍从用户信息卡/独立企业管理入口进入；不占用「我的」一级入口名额，也不替代卖家中心。

**总入口**：

- 移动端：底部导航“我的”进入个人中心，点击用户信息卡右侧“企业中心”。
- 业务反向入口：用户在商品购买页选择企业主体后，可从采购策略提示进入企业中心；管理员从审批通知进入待审批采购；管理员从企业数据权益卡进入成员分配。
- PC 端：「我的」左栏为个人中心壳（订单/数据/卖家等）；企业策略、审批和权益管理沿用独立的企业管理入口。PC 企业管理页面不在本次原型建设范围。
**进入条件**：登录用户均可看到企业入口；未认证用户进入企业认证说明，认证中用户查看进度，认证通过且属于当前企业的成员进入企业中心。普通成员与管理员进入同一企业上下文，但按角色显示不同操作。

**默认落点**：进入后先展示当前企业、认证状态、本人角色和待办摘要；管理员优先看到待审批采购、采购策略和权益待处理事项，普通成员优先看到本人采购进度、已分配权益和当前企业策略说明。

### 6.1 E01 企业上下文

**入口**：企业中心首页的企业信息卡；也可从商品购买页的企业主体选择、企业认证结果页和身份切换菜单进入。
**使用者**：已登录用户；企业认证及企业切换对所有用户开放，企业内信息仅当前企业有效成员可查看。


| 功能   | 详细说明                                                         | 规则/状态           |
| ---- | ------------------------------------------------------------ | --------------- |
| 当前身份 | 全局导航持续展示当前为个人身份或具体企业身份；进入购买、订单、数据和账单页面时同步显示，避免用户误用主体         | 全局导航可见          |
| 企业切换 | 身份菜单列出用户可用企业；切换前提示当前页面内容将刷新，确认后重新展示目标企业的采购策略、订单、权益和账单        | 页面重新加载当前企业权限和数据 |
| 认证状态 | 企业信息区展示未认证、审核中、已认证、认证驳回或认证失效及最近更新时间；非已认证状态提供查看进度、查看原因或继续认证入口 | 可信空间购买要求已认证     |
| 成员角色 | 展示用户在当前企业的普通成员或管理员角色，并据此显示采购、审批、策略和权益操作；角色失效后正在访问页面同步收回操作    | 角色改变后立即刷新权限     |


**关键交互**：

- 身份菜单默认高亮当前主体；企业较多时支持按名称查找，个人身份固定可选。
- 切换企业前展示目标企业名称；确认后页面进入加载态并整体刷新，不局部保留原企业数据。
- 未认证或认证失效状态点击后进入认证说明；认证完成返回原商品或企业页面并重新校验。
- 角色在访问期间变化时，中断越权操作并提示权限已更新，用户确认后回到仍有权限页面。

**验收**：身份切换后订单、价格、购买按钮和数据权限同步刷新。

### 6.2 E02 企业采购策略

**入口**：企业中心首页“采购策略”；管理员也可从企业采购审批页或成员购买受限提示进入查看当前生效策略。
**使用者**：企业管理员可编辑并保存；普通成员仅在购买页和企业中心查看与本人相关的只读结果说明。


| 功能       | 详细说明                                                         | 规则/状态      |
| -------- | ------------------------------------------------------------ | ---------- |
| 普通成员采购开关 | 管理员在采购策略页开启或关闭“允许普通成员代表企业采购”；保存前展示影响说明，保存后普通成员新发起的购买立即按新策略判断 | 关闭后仅管理员可采购 |
| 审批开关     | 当允许普通成员采购时，管理员选择是否先审批；开启后成员提交采购申请，关闭后成员可直接创建企业订单             | 仅单级审批      |
| 策略说明     | 策略页把两个开关组合翻译成成员可理解结果，并显示生效时间；成员在购买页也能看到相同规则和下一步              | 修改后对新申请生效  |
| 操作记录     | 管理员可查看每次策略调整的操作人、时间、调整前值、调整后值和备注；记录只读，支持按时间查看                | 管理员可查看     |


普通成员策略结果：


| 允许普通成员采购 | 需要审批 | 普通成员结果               |
| -------- | ---- | -------------------- |
| 否        | 否    | 不可代表企业采购；引导联系管理员     |
| 否        | 是    | 仍不可采购；审批开关不生效        |
| 是        | 否    | 可直接创建企业订单并继续企业付款     |
| 是        | 是    | 先提交采购申请；管理员通过后继续企业付款 |


企业管理员不受“普通成员采购”开关限制，第一阶段管理员采购不触发自审批。

不纳入第一阶段：预算、金额阈值、商品类型条件、部门策略、多级审批、自动审批。

**关键交互**：

- 页面默认展示当前生效策略和面向成员的结果说明；修改开关后只进入未保存状态，不立即生效。
- 关闭“允许普通成员采购”时，“需要审批”变为不可编辑并说明不生效；重新开启时恢复管理员本次未保存选择。
- 点击保存前展示新旧策略和影响对象；保存中禁止重复操作，成功后更新时间和操作记录同时更新。
- 离开存在未保存修改的页面时提示继续编辑或放弃修改；放弃后恢复当前生效策略。

**验收**：四种策略组合均有确定结果，不出现“允许购买但无人可继续处理”的状态。

### 6.3 E03 企业采购审批

**入口**：企业中心首页“采购审批”及待办数量；管理员可从审批通知直达具体申请，普通成员可从“我的订单”中的待审批订单或申请结果通知进入本人申请详情。
**使用者**：企业管理员处理当前企业申请；普通成员只查看、撤回本人提交的申请，不进入管理员待办列表。


| 功能   | 详细说明                                                           | 规则/状态               |
| ---- | -------------------------------------------------------------- | ------------------- |
| 提交申请 | 成员从购买页提交时，系统带入商品、方案、期限、金额和申请人；成员补充用途、计划使用成员和说明后确认，成功后生成申请记录    | 不占用权益、不进入付款         |
| 待办列表 | 管理员审批中心展示当前企业待办数量和申请列表；每条显示申请人、商品、金额、提交时间和等待时长，可筛选待审批、已处理和本人处理 | 按当前企业隔离             |
| 审批详情 | 详情展示申请商品、方案、价格、期限、用途、使用范围、申请人与操作时间线；商品或价格变化时突出差异并要求重新确认        | 价格变化需重新确认           |
| 通过   | 管理员确认通过后填写可选意见；申请状态改为已通过并通知申请人继续企业付款，审批页展示处理人和处理时间             | 通过不代表已购买            |
| 驳回   | 管理员驳回时必须填写原因；申请立即结束并通知申请人，申请人可从详情复制原信息后重新发起                    | 申请人可重新发起            |
| 申请撤回 | 待审批申请由申请人在详情页确认撤回；撤回后从管理员待办移除并保留时间线，已通过申请只允许关闭后续未付订单           | 已通过后不能撤回申请，只能关闭未付订单 |
| 策略变化 | 申请提交后记录当时采购策略；策略后来调整时，原申请继续按提交时流程处理，详情提示所用策略版本                 | 新申请使用新策略            |


**关键交互**：

- 审批中心默认打开待审批页签并显示数量；打开申请详情再返回时恢复筛选和列表位置。
- 通过和驳回按钮固定在详情操作区；驳回必须输入原因，通过可填意见，提交前展示申请对象和金额。
- 审批提交中两个动作同时禁用；若已被其他管理员处理，刷新显示最终结果并阻止二次审批。
- 价格或商品状态变化时，审批动作先展示差异；需要重新申请时不允许直接通过旧申请。

**验收**：审批状态与订单、付款状态分开；审批通过后仍需完成企业付款。

### 6.4 E04 企业权益分配

**入口**：企业中心首页“企业权益”；管理员可从企业已购数据卡、权益到期提醒或交付完成通知进入具体权益详情和成员分配。普通成员从“我的数据”查看已分配给自己的企业数据，但不进入分配操作。
**使用者**：企业管理员管理当前企业全部权益和成员授权；普通成员只使用已分配权益。


| 功能     | 详细说明                                                      | 规则/状态         |
| ------ | --------------------------------------------------------- | ------------- |
| 企业权益列表 | 管理员查看企业全部已购商品，列表展示商品类型、服务方式、许可人数或范围、已分配人数、有效期、交付和当前权益状态   | 管理员全量可见       |
| 成员分配   | 管理员从权益详情选择在职企业成员，查看可用名额后确认授权；成功后成员收到通知，并在我的数据中看到该企业权益     | 不超过许可人数/范围    |
| 批量分配   | 管理员可按姓名或组织筛选并多选成员，一次提交授权；结果分别显示成功、已授权、超过名额或成员不可用          | 第一阶段支持基础批量操作  |
| 权限收回   | 管理员选择一个或多个已授权成员，确认影响后收回权限；成员后续访问受限内容时显示权限已收回及联系管理员提示      | 不删除历史操作记录     |
| 成员离职   | 成员离开企业后从可分配名单移除，其企业权益自动标识待收回或按企业规则立即收回；管理员可查看处理结果         | 个人权益不受影响      |
| 分配记录   | 权益详情按时间展示授权、批量授权、收回、离职处理和到期操作，包括操作者、成员、结果和失败原因            | 管理员可审计        |
| 到期联动   | 企业权益到期时所有成员授权同步变为到期；成员入口按数据集、报告、看板和 API 的到期规则展示可保留内容或停止能力 | 按商品到期规则保留已获内容 |


**关键交互**：

- 权益详情默认显示许可总量、已分配和可用名额；点击分配打开成员选择，已授权和不可用成员不可重复选择并说明原因。
- 搜索或筛选成员不清空已选项；提交前展示新增人数与剩余名额，超限时阻止提交并定位超出部分。
- 批量分配完成后分别展示成功和失败成员；关闭结果后刷新已分配数量，失败成员可再次选择。
- 收回权限需二次确认受影响成员和内容；提交中禁止重复，成员正在使用时下次访问立即按新权限判断。

**验收**：普通成员只有被分配后才能使用企业购买内容；收回后不能继续访问受限数据。

### 6.5 E05 企业订单与账单

**入口**：移动端和 PC 均从“我的 > 我的订单”进入；企业中心首页的“查看企业订单”仅作为带企业主体筛选条件的快捷入口。订单区「查看可信空间 API 账单」外跳可信空间，不进入 APP 内账单明细页。
**使用者**：企业管理员查看当前企业全量订单与企业汇总账单；普通成员只查看本人经办订单和本人获授权凭证的账单明细。


| 功能   | 详细说明                                                                         | 规则/状态                                  |
| ---- | ---------------------------------------------------------------------------- | -------------------------------------- |
| 企业订单 | “我的订单”统一展示有权查看的 APP 企业订单与可信空间回传订单镜像；从企业中心进入时自动带入当前企业主体筛选。PC 为管理员补充经办人和下单时间筛选 | 管理员看当前企业全量（含空间镜像）；普通成员仅看本人经办；不另建空间订单列表 |
| 经办订单 | 普通成员只看到本人发起、本人付款经办或系统明确分配给本人的企业订单；列表和详情隐藏其他成员及企业汇总信息                         | 不可查看其他成员订单                             |
| 企业账单 | 管理员从我的订单进入「可信空间 API 账单」外跳入口；正式账期、用量、费用与异议均在可信空间查看与处理                         | APP 不拼接完整空间账单镜像；不建设本地账单明细二级页           |
| 授权账单 | 普通成员如需查看本人获授权凭证相关费用，同样外跳可信空间；APP 不展示企业总额、其他成员应用或未授权凭证                        | 隐藏企业汇总和其他成员                            |
| 导出   | 有权限管理员可导出本企业 APP 订单范围；空间账单导出以空间侧能力为准                                         | 记录导出审计；空间格式以空间为准                       |
| 空间跳转 | 空间订单卡与账单入口提供“前往可信空间”，跳转时保留企业、订单或账期上下文；返回后可刷新空间订单镜像                           | APP 不修改空间记录；下载/用数仍按第 10.5 节矩阵          |


**关键交互**：

- 企业中心不复制建设企业订单列表；“查看企业订单”跳转到我的订单并自动筛选当前企业（含空间镜像），返回企业中心时恢复原企业中心位置。
- API 账单不作为企业中心或 PC 门户一级页签，也不建设 APP 内完整账单明细页；从订单区外跳可信空间查看与处理。
- 移动端以快速查单为主，只展示主体、商品类型、成交渠道和订单状态筛选；PC 承担企业管理，管理员可继续按经办人和下单时间筛选并导出 APP 订单。普通成员不显示其他经办人选项。
- 筛选、排序切换即时更新列表；打开详情再返回保留原条件，切换企业后全部重置为目标企业默认状态。
- 导出点击后先确认范围；生成期间可离开页面，返回后查看任务状态，失败只重试该导出任务。

**验收**：管理员和普通成员的数据范围严格不同；普通成员不能通过筛选或导出获得企业全量。

| 开始处理 | 运营点击“开始处理”，状态由已提交变为处理中  | 不要求分派负责人和承诺时间       |
| 用户回复 | 运营填写文本反馈，可选关联一个已发布商品并发送 | 发送后状态变为已回复，用户收到站内提醒 |
| 状态   | 仅使用已提交、处理中、已回复三个用户可见状态  | 不做撤回、重开、供给任务和复杂流转   |


**关键交互**：

- 需求列表按提交时间倒序，卡片直接显示原问题、提交时间和三状态。
- 运营点击“开始处理”后状态变为处理中；填写文本反馈，可选一个已发布商品后发送。
- 发送失败保留编辑内容；成功后状态变为已回复并触发站内提醒。

**验收**：需求从提交、处理中到回复可追踪；页面不出现一期未建设的优先级、聚合、撤回、重开或供给任务。

### 7.8 O08 售后与逆向治理


| 功能      | 详细说明                                                       | 规则/状态       |
| ------- | ---------------------------------------------------------- | ----------- |
| 商品暂停    | 运营或合规人员从风险事件进入商品处置，填写暂停原因、影响说明和预计恢复条件后暂停新购；前台详情保留并立即更新风险提示 | 支持          |
| 权益暂停/恢复 | 经授权人员按企业、用户或整批权益选择暂停或恢复，提交前查看受影响范围；执行后用户端显示原因、时间和处理入口      | 支持人工处理      |
| 客户影响清单  | 系统按商品和风险事件汇总受影响订单、企业、个人用户、成员授权、交付任务和权益状态，支持运营标记处置负责人及结果    | 支持          |
| 人工退款    | 经核验需退款时创建人工退款记录，关联原订单、原因、金额和既有财务流程状态；运营持续更新进度并向用户展示结果      | 记录状态；不做自动退款 |
| 迁移/补偿   | 处置页预留替代商品、延长服务期限或其他人工补偿的记录位置，展示方案、适用客户、确认状态和执行结果           | 仅留能力位和记录    |
| 空间售后    | 可信空间商品出现售后或账单问题时，后台展示空间订单和跳转入口；运营可记录跟进状态，但正式处理仍在空间完成       | APP 不代办账单异议 |


**关键交互**：

- 从商品、变化事件或订单进入售后时自动带入影响对象；运营先确认处置范围，再选择暂停、退款记录或补偿能力位。
- 暂停商品、暂停权益和恢复权益分别确认，页面明确新购影响与存量影响，不能一个动作同时隐式处理两者。
- 客户影响清单支持勾选和分派负责人；批量操作完成后分别展示成功与失败对象。
- 人工退款、迁移和补偿只记录流程与状态；未完成时不能展示给用户为已退款或已补偿。
- 空间售后点击后外部跳转；返回保留原客户和订单上下文，可补记空间处理进度。

**验收**：第一阶段能证明已考虑暂停、召回、退款、迁移和补偿，但自动化不作为上线条件。

### 7.9 O09 集成与变化治理


| 功能        | 详细说明                                                          | 规则/状态                      |
| --------- | ------------------------------------------------------------- | -------------------------- |
| 空间商品与订单回传 | 集成工作台处理可信空间商品、方案、价格和购买资格同步，并接收空间订单回传镜像；API 账单明细与异议仍以空间为准      | 展示最近成功时间和失败摘要              |
| 资产监控任务    | 运营选择首期白名单资源并配置周期检查；任务比较资源可用性、结构、规模、更新时间和合规状态，结果显示正常、发生变化或检查失败 | 第一阶段白名单+周期检查               |
| 变化事件      | 首次成功检查保存全量快照并生成“待人工定级”事件；后续检查以上次成功快照为基线，展示前后变化、初判风险和关联商品      | 原型使用 Mock 数据；首次事件定级前不得暂停新购 |
| 自动重试      | 超时或临时失败任务进入自动重试，列表展示下次时间、已重试次数和上次原因；达到上限后转人工待处理并通知负责人         | 有次数和间隔限制                   |
| 人工修正      | 集成运营可补充资源与商品映射、确认监控误报、重新拉取或重新执行；提交时填写原因，结果保留前后状态和操作者          | 完整审计                       |
| 销售影响      | 普通同步失败只在后台告警并在前台标识信息可能延迟；确认高风险变化后可从事件一键发起暂停新购，经授权确认后生效        | 不因一次失败自动下架                 |
| 存量影响      | 事件详情列出需通知、暂停权益、人工退款或迁移评估的存量客户；运营逐项确认处置方式、负责人和结果后更新事件进度        | 人工确认后执行                    |


**关键交互**：

- 集成工作台默认显示失败、延迟和高风险任务；正常任务可通过筛选查看，状态卡点击后带入对应任务列表。
- 变化事件使用前后对比展示；运营确认风险等级、影响商品和负责人后，才能进入销售或存量处置。
- 手动刷新或重试提交后显示任务进度，连续点击不创建重复任务；失败时保留上次成功时间和结果。
- 标记误报或人工修正必须填写原因并二次确认；完成后事件状态变化但原始变化记录不删除。
- 高风险暂停新购从事件发起，仍需进入发布治理确认；监控页面不能直接无确认下架商品。

**验收**：后台能看到资产变化 Mock 任务和处置入口；一般同步失败不会自动下架商品。

以下约定适用于全部用户端、企业中心和运营后台功能，评审时需逐模块确认是否有例外：


| 评审项   | 产品要求                                           |
| ----- | ---------------------------------------------- |

| 无权限状态 | 说明当前身份、缺少的权限和可联系对象；不显示无效操作按钮，也不泄露受限内容          |

| 操作反馈  | 成功显示结果与下一步；处理中显示进度或更新时间；失败保留已完成事实并提供重试或人工处理入口  |
| 通知承接  | 通知点击后进入对应申请、订单、权益、交付、需求或变化事件详情，不只进入首页          |
| 时间口径  | 商品更新时间、同步时间、数据截止时间、订单时间、交付时间分别标识，避免只显示一个“更新时间” |
| 审计可见  | 企业策略、审批、权益分配、商品发布、人工修正和售后操作均保留操作者、时间、对象、结果和原因  |

#### 8.1.1a 会员等级与商品权益规则


| 规则   | 说明                                                                       |
| ---- | ------------------------------------------------------------------------ |
| 等级划分 | 个人会员分普通会员、高级会员两档；开通与续费在会员购买页选择档位                                         |
| 覆盖关系 | 高级会员可享受商品上配置给普通会员与高级会员的权益；普通会员仅享受普通会员档权益                                 |
| 商品配置 | 报告、看板、API 可分别配置各等级为不纳入 / 免费 / 折扣；数据集第一阶段不配置会员免费或折扣                       |

| 权益判断 | 仅当用户会员等级命中商品该等级的「免费」配置时，主动作视为会员已覆盖；仅折扣时仍需走购买（可享会员价）                      |
| 配置权威 | 以「分等级的会员权益配置」（等级 + 免费或折扣 + 可选折数）为准；旧版单一「是否会员包含」等展示口径由该配置派生，二者冲突时以分等级配置为准 |

## 10. 第一阶段详细业务规则

本章为研发和测试的唯一业务口径；前文若存在历史描述，以本章为准。技术状态编码、金额精度、幂等和接口映射进入 SDD。

### 10.1 搜索、供给阈值与排序

1. 调整于 2026-08-06：本模块找数主路径为关键词检索；AI 问答由其他团队负责。入口可保留切换或跳转，但不在本 PRD 定义回答能力。
2. 关键词检索仅返回已包装、已发布的数据集、API、行业报告和自有看板，不返回内部视图或问答正文。
3. 资产平台与可信空间的相似商品不跨来源合并；只去除同一商品记录的重复结果。
4. 有效结果数小于运营阈值时在列表底部展示需求入口；默认阈值为 3，因此 0～2 条展示、3 条及以上不展示。
5. 调整于 2026-08-08：列表排序选项统一为「默认」「价格↑」「价格↓」「最新」。有关键词结果与无关键词的发现/全部列表使用同一套规则。切换排序立即刷新并回到列表顶部，保留筛选条件；排序只改变先后，不改变谁能看见哪些商品。返回详情后再回列表时恢复所选排序。



#### 10.1.1 「默认」排序

**一句话**：给每个商品算一个总分，**分高的排前面**。

```
总分 = 文本相关分 + 运营排序权重 × 1 + 是否推荐位 × 100
```


| 项      | 怎么取值                              | 系数       | 说明                         |
| ------ | --------------------------------- | -------- | -------------------------- |
| 文本相关分  | 见下表，**最高 100**；算完后若超过 100 按 100 计 | ×1（直接加总） | 无关键词时全体为 0；封顶避免文本分过大压过运营排序 |
| 运营排序权重 | 后台配置的整数；未填按 50                    | ×1       | 运营可调                       |
| 是否推荐位  | 在推荐位＝1，不在＝0                       | ×100     | 无关键词时，推荐位通常压过普通权重差         |


同分时：上架时间更晚的在前；再相同则保持稳定次序。

用户筛选了商品类型时：先**过滤**掉不符合的类型，再对剩下的商品算分排序（类型不参与加分）。

**文本相关分怎么算**（只含名称/副标题、描述/推荐语；场景/标签不参与默认分）

```
文本相关分 = min(名称分 + 描述分, 100)
```

名称分——看「商品名称」「副标题」，取两者中更高的一档：


| 名称分 | 条件                              |
| --- | ------------------------------- |
| 80  | 与关键词完全一致                        |
| 60  | 完整包含关键词整段（连续包含）                 |
| 40  | 以关键词开头                          |
| 20  | 仅拆词命中（如关键词「货车轨迹」，名称只含「货车」或「轨迹」） |
| 0   | 名称、副标题都不命中                      |


描述分——详细描述或推荐语中出现关键词＝**20**，否则＝**0**。

名称分最高 80、描述分最高 20，合计最高 100；公式里再 `min(..., 100)` 防止以后加项超限。

多个关键词（空格分开）时：名称分取「命中最好的那个词」对应分；描述分任一关键词命中即为 20。

**无关键词**

文本相关分＝0，公式变成：

```
总分 = 运营排序权重 + 是否推荐位 × 100
```

即：先看推荐位，再看运营权重，最后上架时间。

**例子（有关键词「货车轨迹」）**


| 商品            | 名称分 | 描述分 | 文本相关分（≤100） | 权重  | 推荐位 | 总分            | 名次  |
| ------------- | --- | --- | ----------- | --- | --- | ------------- | --- |
| 全国货车轨迹热力数据集   | 60  | 20  | 80          | 86  | 1   | 80+86+100＝266 | 1   |
| 货车通行月报        | 20  | 20  | 40          | 70  | 0   | 40+70+0＝110   | 2   |
| 企业物流活跃度（名称不中） | 0   | 0   | 0           | 80  | 1   | 0+80+100＝180  | 3   |


说明：第 3 个名称不中但有推荐位，总分 180，仍高于「名称弱命中、无推荐位」的月报 110——这是推荐位系数与文本封顶共同作用的结果。若希望「凡有文本命中必须压过纯推荐位」，需再调系数（不在本默认值内自动保证）。

**系数与封顶**

- 文本相关分**封顶 100**，不再另乘放大系数。
- 推荐位 ×100、运营权重 ×1 为第一阶段默认；若要推荐位更强/更弱，只改推荐位系数。



#### 10.1.2 「最新」排序

按上架时间从新到旧。无上架时间时，依次用空间最近同步时间、平台最近更新时间。时间相同则保持稳定顺序。

#### 10.1.3 「价格↑」「价格↓」排序

比较金额与卡片上的**起始价格**同一口径（见 10.1.4）。「价格↑」从低到高，「价格↓」从高到低。

先分成三类再比（「价格↑」时从前到后；「价格↓」时整类倒序）：

1. 免费类（商品免费，或当前展示为会员免费）
2. 有明确数字起始价的商品（按金额比大小）
3. 按需报价，或当前身份下暂无数字方案

同类内金额相同或同属非数字价时，上架时间新的在前，再保持稳定顺序。

#### 10.1.4 卡片起始价与多方案最低价

列表卡只展示一个起始价，须对应当前身份下用户能理解的购买起点。

**当前购买身份**


| 当前身份           | 纳入比价的方案       |
| -------------- | ------------- |
| 未登录，或登录后处于个人身份 | 仅个人主体、且仍在售的方案 |
| 登录后切换到企业身份     | 仅企业主体、且仍在售的方案 |


规则：**先按当前身份筛方案，再在筛后结果里取最低价**；不得把个人方案和企业方案混在一起算最低。账号已绑定企业，但页面仍停在个人身份时，只算个人方案。

**APP 内购商品（一商品多方案）**

1. 只比较当前身份下仍在售的方案。
2. 一次性方案：用该方案标价。
3. 持续方案：用**单期标价**（与详情里方案行一致），不用「最短可购期限的应付总额」。
4. 有数字价时取最低；多于一个数字方案时展示为「¥金额 起」；只有一个数字方案时可只展示「¥金额」。
5. 当前身份下没有可售方案：不改用另一身份的价格；个人身份展示「暂无个人方案」，企业身份展示「暂无企业方案」。
6. 商品本身为免费时，卡片优先展示「免费」；会员免费按会员规则展示标签。免费类不与付费方案抢「最低数字价」；参与价格排序时归入免费类。

**可信空间商品**

1. 价格以空间同步为准，APP 不改价。
2. 空间方案通常面向认证企业：卡片取同步且在售方案中的公开最低价，展示为「¥金额 起」（或沿用空间原始价本文案），并保留「可信空间成交」标识。
3. 个人或未登录用户仍可看到该公开最低价，便于评估；能否下单仍看购买资格，不因展示最低价而开放个人购买。
4. 同步方案没有数字价时，展示「按报价」或空间给出的非数字说明。

**身份切换**

在个人与企业身份间切换后，卡片起始价和当前「价格↑ / 价格↓」结果立即按新身份重算。「默认」「最新」不含价格因素，不因身份切换而重排。

### 10.2 价格、生效与续订

1. 一次性方案使用方案总价；持续方案应付金额＝单周期价格×完整周期数＋增加项－优惠项，不按天折算。
2. 持续服务仅在付款成功、权益创建成功且首次必要交付完成后开始计期；交付中或失败不消耗期限。
3. 生效和到期时间按北京时间精确到秒，展示为「年-月-日 时:分:秒」。有效期从生效时刻起（含）至到期时刻止（不含）。
4. 列表可只显示日期；订单详情、权益详情、付款与续订确认必须显示到秒。
5. 未到期续订从原到期时间顺延；已到期续订从重新恢复可用时起算；使用续订下单时的最新方案和价格，不新建重复“我的数据”入口。



### 10.3 企业审批、锁价和付款截止

1. 申请提交时固化商品、方案、期限、席位数、许可范围和应付金额快照；后续企业策略变化不改变本申请审批路径。
2. 管理员审批通过后，在配置的审批付款有效期内锁定申请快照；超期变为失效，需按当前方案和价格重新提交。
3. 订单创建时锁定方案、期限、席位、许可和金额。未付款订单超过该付款方式配置的有效期自动关闭。
4. 经过审批的订单，最终付款截止时间取“审批付款截止时间”和“订单付款截止时间”的较早值；到截止秒立即禁止付款。
5. 商品暂停新购或下架可以提前终止未付款资格；企业订单只能使用企业余额、合同支付或公对公转账。



### 10.4 商品级企业席位

1. 第一阶段企业方案必须配置席位数；席位按每个已购商品权益分别计算，不跨商品或订单共用。
2. 经办人和管理员均不自动获得席位。管理员显式分配后，成员在当前企业身份下自动获得该商品的查询和使用权限。
3. 达到剩余席位上限后直接禁用其他未选成员，不允许页面形成超额选择；先取消已选成员后才可继续选择。
4. 已授权、已失效或不属于当前企业的成员不可选择。提交时个别成员失效允许部分成功，失败成员不占席位并逐项提示。
5. 收回席位、成员离职或企业成员身份失效后立即失去企业查询权限，个人权益不受影响。



### 10.5 数据集交付矩阵

本节为数据集「进入用数 / 订单内下载 / 前往空间 / 我的数据」的唯一判定口径。API、报告、看板不适用本矩阵。

#### 10.5.1 判定输入定义


| 输入项      | 取值                 | 说明                                                                            |
| -------- | ------------------ | ----------------------------------------------------------------------------- |
| 成交渠道     | 资产平台（APP 成交）/ 可信空间 | 以商品成交渠道为准，不以用户从哪跳转为准                                                          |
| 空间使用授权   | 可下载使用 / 仅沙箱可用      | 仅可信空间商品需要；以空间权威授权为准。第一阶段用数判定只认这两种                                             |
| 企业开通找数买数 | 已开通 / 未开通          | 企业能力状态：是否已开通本模块服务。开通后才可为空间已购「可下载使用」数据提供免费用数与 APP 下载；未开通时仍可进「我的数据」回看，但不开放用数与下载 |
| 成员使用资格   | 有资格 / 无资格          | 个人＝本人已购；资产平台企业＝已占该商品席位；空间企业＝属于空间授权使用范围的成员（企业全员或空间侧已授权成员）。管理员不因角色自动获得资格        |
| 交付完成     | 已交付 / 未交付          | 资产平台：用数交付成功；可信空间：空间回传为已交付。未交付时不开放用数与下载                                        |
| 方案允许下载   | 是 / 否              | 商品方案或空间回传标明允许下载时为是；样例与探查永远否                                                   |




#### 10.5.2 交付结果矩阵

前提：下列各行均要求「成员有使用资格」且（除仅查看订单进度外）「已交付」。未交付时：订单可回看进度；用数、下载均不可用。


| 场景  | 成交渠道 | 空间使用授权 | 企业开通找数买数 | 进入用数         | 订单/我的数据下载              | 前往空间/沙箱           | 进入「我的数据」            |
| --- | ---- | ------ | -------- | ------------ | ---------------------- | ----------------- | ------------------- |
| A1  | 资产平台 | —      | —        | 是            | 方案允许则是，否则否             | 否                 | 是                   |
| A2  | 资产平台 | —      | —        | 否（成员无席位/非本人） | 否                      | 否                 | 否                   |
| S1  | 可信空间 | 可下载使用  | 已开通      | 是（免费用数，不另收费） | 按 10.5.5：方案/回传允许则是，否则否 | 是                 | 是                   |
| S2  | 可信空间 | 可下载使用  | 未开通      | 否            | 否                      | 是                 | 是（仅回看与前往空间，无用数、无下载） |
| S3  | 可信空间 | 仅沙箱可用  | 已开通或未开通  | 否            | 否                      | 是（沙箱/空间）          | 否                   |
| S4  | 可信空间 | 可下载使用  | 已开通或未开通  | 否（成员无空间使用资格） | 否                      | 可展示企业入口，本人不可用数/下载 | 否                   |


说明：

- **免费用数**仅出现在 S1：不向企业另行收取用数模块使用费；空间数据集采购、续订、席位与售后仍以可信空间为准。
- **不依赖跳转路径**：无法可靠识别是否经找数买数跳转购买，因此不把「是否经 APP 跳转」作为矩阵输入。
- **下载与用数均依赖开通找数买数（空间侧）**：S2 未开通时仍可进入「我的数据」回看来源与前往空间，但不提供 APP 内下载与用数；下载与免费用数仅在 S1 且满足 10.5.5 下载细则时开放。
- **仅沙箱不可放宽**：即使企业已开通找数买数，S3 仍不可用数、不可在 APP 下载。
- **合规撤权 / 空间收回授权 / 席位收回**：对应该成员立即落入「无资格」行，入口同步消失；支付事实不回退。
- **细则**：开通状态、授权同步、下载版本与冲突处理见 **10.5.5**。

| ----------------- | -------------- | -------------------------------- | ----------- |

| 进入我的数据＝是且用数＝否（S2） | 无用数、无下载，可有前往空间 | 卡片保留，标明「空间已购 · 开通找数买数后可用」；不提供下载  | 不展示用数/下载主动作 |

#### 10.5.4 可信空间边界（承接原规则）

1. 第一期同步空间商品、方案、价格和资格；价格刷新失败时可按最近成功信息继续进入空间，但必须提示最终以空间确认为准。
2. 空间订单以权威回传镜像进入我的订单和后台订单中心；镜像至少含空间订单号、商品、企业、金额、展示状态、交付摘要、同步时间、前往空间链接；下载入口仅矩阵允许时暴露。售后与 API 账单异议仍回空间处理。
3. APP 不伪造未经空间确认的订单状态，也不在 APP 内处理账单异议或改写空间权威事实。
4. 空间数据集免费用数、下载与我的数据展示严格按 10.5.2 矩阵判定；开通找数买数不能放宽仅沙箱授权。
5. 满足矩阵 S1 时不另收用数费，并可按 10.5.5 提供 APP 下载；未开通找数买数时即使空间已购可下载数据集，也只进「我的数据」回看与前往空间，不提供免费用数与 APP 下载（S2）。



#### 10.5.5 开通找数买数与 APP 下载细则

**【新增】可信空间与万联灵析数据打通规则**：因可信空间与万联灵析订单暂未打通，**默认在可信空间和万联灵析都开通了账号的企业**，在万联灵析商业版中，可直接在用数模块使用该企业在可信空间成交的、**支持下载的**（不需要通过沙箱使用）数据集；仅支持沙箱使用的数据集仍需前往可信空间沙箱操作。

**企业开通找数买数**


| 项       | 规则                                                       |
| ------- | -------------------------------------------------------- |
| 含义      | 企业已开通本模块（找数买数）服务能力的企业级开关；用于判定空间已购数据能否在 APP 免费用数与 APP 下载  |
| 配置责任    | 由平台运营或开通流程维护；企业管理员在前台只读查看开通状态（第一阶段不要求企业自助开关）             |
| 生效      | 开通状态变更后，相关空间数据集入口按矩阵立即重算；已打开的页面在刷新或再次进入时更新               |
| 前台提示    | 未开通且存在空间可下载使用数据时，在「我的数据」S2 卡片提示「开通找数买数后可用」；不暗示当前可下载或免费用数 |
| 与空间采购关系 | 开通与否不影响空间内购买、付款、空间侧下载/沙箱使用；只影响 APP 侧用数与下载入口              |


**空间使用授权同步**


| 项      | 规则                                                                 |
| ------ | ------------------------------------------------------------------ |
| 权威来源   | 以可信空间回传/同步的使用授权为准；APP 只读展示                                         |
| 第一阶段取值 | 仅「可下载使用」「仅沙箱可用」参与矩阵判定                                              |
| 变更处理   | 授权降级为仅沙箱或收回后，对应成员立即失去用数/下载资格；已进入「我的数据」的 S1 卡片按新结果变为不可用或移出（仅沙箱移出列表） |
| 成员范围   | 企业全员可用或空间侧已授权成员名单；APP 不另建独立席位池收取用数费。管理员不因角色自动获得资格                  |


**APP 下载细则**


| 项     | 规则                                                                           |
| ----- | ---------------------------------------------------------------------------- |
| 适用    | 仅矩阵下载＝是（A1 且方案允许；或 S1 且方案/回传允许，并已开通找数买数）                                     |
| 冲突处理  | 空间回传带 downloadUrl，但矩阵不允许（S2/S3/S4/未交付）→ APP 与对用户可见后台不展示、不代理下载；空间内是否仍可下载以空间为准 |
| 方案开关  | 资产平台：方案「允许下载」默认开启，运营可关闭；关闭后 A1 仅用数不下载。空间：以空间方案/回传是否允许下载为准，并叠加开通找数买数          |
| 下载内容  | 一次性＝下单确认快照；持续更新＝当前有效版本（不在第一阶段提供历史多版本列表）                                      |
| 使用对象  | 仅有成员使用资格者可下载；企业未占席/无空间资格成员不可代下                                               |
| 链接与审计 | 点击后获取短期可用地址，过期需重新获取；记录下载审计（操作者、时间、订单/权益、结果）。文件格式、次数上限与水印策略第一阶段不做产品验收硬标准      |


**订单镜像最小集**


| 项    | 规则                                   |
| ---- | ------------------------------------ |
| 必含字段 | 空间订单号、商品、企业、金额、展示状态、交付摘要、同步时间、前往空间链接 |
| 条件字段 | 下载入口仅矩阵允许时暴露                         |
| 同步失败 | 保留上次成功镜像并标识同步时间；不伪造已交付               |


1. 需求只使用已提交、处理中、已回复三种状态；运营回复以文本为主，可选关联一个已发布商品，发送后用户收到站内提醒。
2. 不建设优先级、排队、聚合、撤回、重开和供给任务。
3. 资产监控首次成功检查保存完整快照，并把全量内容生成“待人工定级”事件；运营选择低/中/高并填写原因前不得暂停新购。
4. 后续检查以上次成功检查为基线；同时命中多项变化时取最高风险，不做分数累加。检查失败不自动生成数据风险。
5. 只有人工确认后的高风险事件可发起暂停新购，暂停仍需有权限人员确认。



## 11. 第一阶段功能验收清单



### 11.1 用户端

- [ ] APP 与 PC 可通过关键词检索进入找数据结果；AI 问答入口可达，但其能力不按本 PRD 验收。
- [ ] 四类商品卡片使用轻量骨架，展示名称、类型、来源、一句话内容摘要和起始价格；不展开脱敏样例、接口示例、报告封面或看板图表。
- [ ] 搜索结果只展示已包装、已发布商品。
- [ ] 无结果进入需求提交，不显示候选资产。
- [ ] APP 四类详情页按单列结构展示商品摘要、默认内容页签、报价与方案、权益提示和底部固定动作；报价区位于内容之后。
- [ ] PC 四类详情页采用左侧商品评估、右侧固定购买面板；切换左侧页签时右侧方案和动作保持可见。
- [ ] APP 与 PC 允许调整字段排布和信息密度，但商品类型、成交渠道、报价、方案、页签、权益和主动作的业务含义一致。
- [ ] 四类商品均可从浏览发现、交易处理和已有权益入口进入同一详情页；可信空间商品同时支持外部回流入口。
- [ ] 从搜索、订单、账单、权益或通知进入详情后，返回时可恢复原页面、筛选条件和业务上下文。
- [ ] 已暂停或下架商品仍可从历史订单和已有权益进入详情，并明确展示服务影响和后续动作。
- [ ] 数据集详情包含基本信息、字段信息、样例数据和字段级探查报告，并区分资产平台与可信空间交付。
- [ ] 探查报告仅展示「已开放且已产出结果」的字段；五类指标与 §5.5.4 一致；无字段/未发布空态文案正确。
- [ ] 后台探查配置：未产出不可勾选；主键与 L3 禁止开放；L2 默认关闭且手动开放需确认；保存后前台即时生效。
- [ ] API 详情包含基本信息、接口文档、固定脱敏调试、错误码与 SLA，调试不消耗正式额度。
- [ ] 报告详情默认进入在线阅读并展示封面、版本、公开摘要和样章，同时包含目录和报告介绍，能区分当前版本购买与持续获得新版本。
- [ ] 看板详情默认进入看板预览并展示公开指标值、数据时间和趋势图，同时提供指标定义、基本信息、更新与导出页签。
- [ ] 看板指标定义购买前完整展示名称、描述、计算公式和支持维度；公开预览值标识实时、延迟、样例或脱敏口径，其余实际数值和明细按权益控制。
- [ ] 有企业身份时默认企业购买，并可切换个人。
- [ ] 个人购买只形成个人权益。
- [ ] 企业购买只允许企业付款方式。
- [ ] 一次性和持续方案按商品配置展示。
- [ ] 持续方案显示计价周期和最大有效期，不出现永久更新。
- [ ] 购买结果区分付款、权益和交付状态。
- [ ] 认证企业可跳转可信空间购买数据集/API。
- [ ] 个人和未认证企业不能发起可信空间购买。
- [ ] 个人用户查看可信空间商品时，页面明确展示“可浏览、不可下单”的购买资格说明，并提供去企业认证或切换企业入口。
- [ ] 企业认证中显示审核状态且不可下单；认证通过并完成空间连接后显示当前购买企业和“前往可信空间购买”。
- [ ] 可信空间资格不满足时不得只显示无解释的禁用购买按钮。
- [ ] 移动端与 PC 的“我的”均提供统一一级入口（含我的订单、我的数据、卖家中心及占位入口）；原型默认进入「我的订单 → 买数」。
- [ ] 我的订单二级含 VIP / 买数 / 看数；买数列表展示有权查看的个人/企业、APP/可信空间数据集订单，并完整展示主体、渠道、方案、付款和进度信息。
- [ ] 我的数据二级含我购买的 / 我生产的；我购买的数据展示数据集（按第 10.5 节矩阵）与个人报告；个人报告提供「上架」进入卖家新建上架单。
- [ ] 卖家中心二级含入驻申请、新建上架、卖家订单、我的上架单；移动与 PC 均可进入，不依赖独立枢纽大卡片页。
- [ ] 已完成的数据集订单和「我的数据」按第 10.5 节矩阵展示「进入用数」「下载数据」「前往空间」；不因订单存在而默认全开。
- [ ] 矩阵 S1：企业已开通找数买数且空间授权为可下载使用时，可免费用数，并可按方案/回传下载；S2 未开通则可进「我的数据」但无用数、无 APP 下载，仅可前往空间；S3 仅沙箱无用数、无 APP 下载、不进我的数据。
- [ ] 我的数据展示数据集的更新服务到期日；持续更新权益可续订，一次性快照不显示续订。
- [ ] API 账单仅提供前往可信空间查看的外跳入口；APP 不拼接完整空间账单镜像。
- [ ] 空间账单异议从 APP 跳回可信空间。



### 11.2 企业中心

- [ ] 移动端可从“我的”用户信息卡进入企业中心；未认证、认证中和已认证用户分别进入对应状态页。
- [ ] 企业上下文、采购策略、采购审批、企业权益和企业订单账单均有明确的主入口、反向入口和角色限制。
- [ ] 管理员进入企业中心优先看到待办与管理入口，普通成员优先看到本人采购进度、已分配权益和只读策略说明。

- [ ] 企业中心“查看企业订单”复用我的订单并带入企业筛选（含空间镜像）；API 账单仅外跳可信空间，不新增本地账单明细一级/二级页。
